# P12 — IM 跨端草稿、表情同步与结构化输入

> 状态：**代码已实现，待部署与跨端实测**（2026-08-08）。
>
> 前置阶段：[`p7-im-rich-messages.md`](./p7-im-rich-messages.md)、
> [`p8-im-calendar-integration.md`](./p8-im-calendar-integration.md)。

## 1. 目标与边界

P12 统一 Web 与 Android 的消息输入体验，并补齐多设备连续编辑能力：

- 会话草稿在同一账号的 Web、Android 间同步；
- 最近使用表情跨端同步；
- 支持组织管理员维护企业自定义表情；
- 用同一套命令契约驱动“＋”面板、会话顶部入口和 `/` 快捷指令。

输入结构保持克制：

- 输入栏：文字、表情、发送、更多；
- “＋”面板：图片、拍摄、文件、云文档、日程；
- 会话顶部：语音通话、视频通话与会议；
- `/` 指令：日程、文档、会议的键盘快捷入口。

本期不恢复语音消息，不引入红包、位置、名片、富文本输入、命令参数、机器人
命令或企业自定义命令。附件不属于草稿。

## 2. 关键决策

| # | 决策 | 说明 |
|---|---|---|
| D1 | 草稿以 `user + cid` 唯一标识 | 账号和会话双重隔离，退出登录时清除当前账号本地缓存 |
| D2 | 本地即时保存，停止输入 800 ms 后同步 | 切换会话或 App 进入后台前立即补同步；离线时保留本地副本 |
| D3 | 服务端按接收顺序最后写入覆盖 | `updated_at` 用于客户端刷新与本地/云端恢复判断，不做字段级合并 |
| D4 | 消息确认成功才清草稿 | 发送失败保留正文和回复上下文，避免弱网丢输入 |
| D5 | 最近表情采用最多 24 项 MRU | 重复项移到首位；点击后本地立即更新，云端异步同步 |
| D6 | 企业表情继续使用 `content_type="image"` | 新客户端识别 `emoji/` 前缀；旧客户端仍可按普通图片显示 |
| D7 | 企业表情停用而不删除对象 | 从选择器和最近列表移除，但历史消息继续可见 |
| D8 | 命令是结构化动作，不是文本消息 | 选择命令后移除输入中的命令文本，执行既有业务流程 |

## 3. 跨端草稿

后端新增 `ImDraft`：

```text
user + cid       唯一键
text             最多 4000 个 Unicode 字符
reply            可空；保存 mid、发送者与摘要快照
updated_at       最后一次服务端写入时间
```

接口：

```http
GET    /api/v1.0/im/drafts/
PUT    /api/v1.0/im/drafts/{cid}/
DELETE /api/v1.0/im/drafts/{cid}/
```

客户端行为：

1. 每次输入先写账号隔离的本地副本；
2. 停止输入 800 ms 后覆盖云端草稿；
3. 切换会话、Web 重新聚焦、App 前后台切换时刷新或补同步；
4. 会话列表优先显示 `[草稿] 内容摘要`；
5. 消息得到发送确认后删除本地和云端草稿；失败则保留；
6. 回复草稿保存消息 ID、发送者和摘要，不依赖原消息仍在当前分页内；
7. 同步接口不可用时降级为纯本地草稿，恢复网络后重试。

## 4. 最近表情

后端为每个用户保存一份 IM 偏好：

```http
GET   /api/v1.0/im/preferences/
PATCH /api/v1.0/im/preferences/
```

最近表情元素有两种形态：

```json
{"kind":"unicode","value":"😀"}
{"kind":"custom","id":"…","key":"emoji/…","name":"…"}
```

服务端和客户端均执行去重与 24 项上限。Web、Android 表情面板统一为“最近 / 系统
表情 / 企业表情”。企业表情被停用后，服务端读取偏好时过滤该项；历史消息不受
影响。

## 5. 结构化快捷指令

Web 与 Android 维护字段和语义一致的命令注册表：

```text
id
本地化名称与搜索别名
图标
可用会话类型
执行动作
可视入口位置
```

首批命令：

| 命令 | 别名 | 动作 | 可视入口 |
|---|---|---|---|
| `schedule` | `/日程`、`/schedule` | 携带当前 `cid` 和成员进入日程创建/忙闲流程 | “＋”面板、斜杠菜单 |
| `document` | `/文档`、`/doc` | 打开只读云文档选择器 | “＋”面板、斜杠菜单 |
| `voice-call` | `/语音通话`、`/voice` | 私聊直接发起语音通话 | 会话顶部、斜杠菜单 |
| `voice-meeting` | `/语音会议`、`/voice` | 群聊打开语音会议成员选择器 | 会话顶部、斜杠菜单 |
| `meeting` | `/会议`、`/meeting` | 群聊打开视频会议成员选择器；私聊进入视频通话流程 | 会话顶部、斜杠菜单 |

仅当输入以 `/` 开头且命令片段尚未包含空格时显示菜单。Web 支持上下键、Enter、
Esc 和鼠标；Android 支持键盘和触摸。选择命令后不发送 `/命令` 文本。当前语言
提供本地化别名，同时始终接受英文别名。

## 6. 企业自定义表情

后端新增组织级 `OrganizationEmoji`，保存名称、对象键、真实格式、字节数、宽高、
GIF 动画信息、排序、启停状态、创建人和时间。

约束：

- PNG、JPG、WebP、GIF；
- 最大 2 MiB、最大 512×512；
- 每个组织最多 100 个启用表情；
- 名称最长 32 字符，组织内忽略大小写唯一；
- 对象键固定为 `emoji/<org_id>/<uuid>.<ext>`。

接口：

```http
GET  /api/v1.0/im/custom-emojis/

GET/POST/PATCH/DELETE /api/v1.0/admin/im-emojis/
POST                  /api/v1.0/admin/im-emojis/upload-url/
```

只有组织所有者和管理员可在 Web 管理端上传、重命名、排序、启用和停用；普通成员
及 Android 只消费启用项。上传使用预签名 URL，但创建数据库记录前，后端重新读取
对象并验证真实格式、大小、尺寸和 GIF 动画信息，不能信任扩展名或客户端声明。

发送时仍使用图片消息：

```json
{
  "content_type": "image",
  "body": "emoji/<org_id>/<uuid>.webp"
}
```

新客户端按表情尺寸渲染并使用 `[表情]` 作为会话、引用和转发预览；旧客户端按
普通图片渲染。媒体解析允许 `emoji/` 前缀，跨组织会话的接收者也能查看消息中的
企业表情。企业表情只作为独立消息发送，不插入文字，也不用于消息反应。

## 7. 兼容与安全红线

1. 停用企业表情只影响可选列表，不删除对象和历史记录；
2. 创建表情记录前必须由后端检查对象内容，不能只校验上传申请；
3. `emoji/` 仍走私有聊天图片桶和签名解析，不公开对象；
4. 草稿和偏好必须按登录用户隔离，登出时不能遗留给下一账号；
5. 待发附件、上传中的对象和命令菜单状态不得进入草稿；
6. P0 已消除的图片、通话和会议重复入口不得恢复；
7. 不新增企业表情消息类型，确保旧客户端兼容。
