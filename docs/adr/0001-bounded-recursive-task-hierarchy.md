# ADR-0001：有界递归子任务层级

> 状态：Accepted  
> 实现状态：Completed（2026-08-27）
> 日期：2026-08-26  
> 决策范围：任务模型、层级约束、权限、查询、删除与移动  
> 关联计划：[任务模块功能完善实施计划](../plan/task-module-improvement-plan.md#6-阶段-c有界递归子任务检查项)

## 背景

迁移 `0112_task_parent` 曾为 `Task` 增加自引用 `parent`，随后由 `0124_remove_task_parent` 删除。旧字段只有级联删除关系，没有定义深度、循环引用、跨组织挂载、权限继承、搜索父链和子树移动等产品与安全语义，因此不能直接恢复旧迁移。

一级子任务容易实现，但会过早把产品能力固化在模型和数据库约束中。阶段 C 需要更接近飞书、钉钉、Linear 和 Notion 的递归拆解体验，同时用 ClickUp、Asana 和 monday.com 一类产品常见的深度与规模配额控制工程复杂度。

## 决策

### 1. 使用邻接表表达递归层级

- 为 `Task` 新增可空的自引用外键 `parent`，API 使用 `parent_id`；`parent_id=NULL` 表示根任务。
- 任意非根任务都可以继续拥有子任务。数据库只维护引用完整性和必要索引，不增加“父任务必须是根任务”或固定最大深度的约束。
- 建议为 `(organization_id, parent_id, position)` 建立索引。深度、祖先链、子树大小和子树高度由服务端通过递归查询计算，首期不持久化冗余路径或 `depth` 字段。
- 使用新的前向迁移增加字段和索引，不修改或重放 `0112`、`0124`。

### 2. 产品深度和规模采用服务端配额

- `TASK_MAX_SUBTASK_DEPTH=5`：根任务深度为 0，首期允许深度 1—5 的子任务。
- `TASK_MAX_DIRECT_CHILDREN=100`：每个父任务最多 100 个直接子任务。
- `TASK_MAX_TREE_NODES=500`：包含根任务在内，单棵任务树最多 500 个节点。
- 深度上限不写入数据库约束。未来提高 `TASK_MAX_SUBTASK_DEPTH` 只需调整服务端配置并完成对应容量验证，不需要迁移现有数据。
- 服务启动时拒绝负数深度、非正数数量等无效配置；API 返回稳定的配额错误码和当前上限。

### 3. 所有层级写入通过统一服务完成

创建子任务、改变 `parent_id`、提升为根任务和移动子树必须复用同一层级服务，并在单个数据库事务中完成。服务应锁定来源树与目标树涉及的节点，并按稳定顺序加锁，以避免并发写入绕过约束。

写入时必须同时验证：

1. 目标父任务不是当前任务本身，也不在当前任务的后代集合中。
2. 当前任务、整棵待移动子树与目标父任务属于同一 `organization_id`；组织为空与非空也不得混挂。
3. `目标父深度 + 1 + 待移动子树高度` 不超过配置的最大深度。
4. 目标父任务的直接子任务数量和目标树的总节点数没有超过配额。
5. 调用者有权移动待移动子树中的每个节点，也有权在目标父任务下创建内容。

任何一项失败都回滚整个层级写入。禁止通过普通模型更新、批量更新或管理脚本绕过该服务。

### 4. 权限不沿父子关系自动扩大

- 每个任务继续按创建人、负责人、关注人、任务清单角色和会话分享计算自身权限；仅仅成为父任务或子任务，不会自动获得另一节点的读取或写入权限。
- 返回子任务前，服务端必须确认调用者可以查看该节点及其从根到当前节点的完整父链。若任一祖先不可见，该子任务不得出现在详情、列表、搜索、筛选、统计、通知或会话分享结果中。
- 创建、移动、分派或分享操作如果会形成“可见子任务但不可见父链”的状态，服务端必须拒绝，并返回可修复的权限错误；前端能力字段只能用于提示，不能替代服务端校验。
- 会话分享只作用于明确分享的任务，不递归分享祖先或后代。子任务不得借父任务分享越权暴露，父任务也不得借子任务分享泄露。

### 5. 子任务状态独立，父任务只展示进度

- 每个节点保留独立的 `status`、负责人、关注人、优先级、日期、评论、附件、提醒和活动历史。
- 完成或重开子任务不自动改变任何祖先状态；完成或重开父任务也不批量改变后代状态。
- 父任务可展示服务端计算的完成进度。首期进度按其全部可见后代统计为 `completed_descendants/total_descendants`，不包含父任务自身；API 必须明确返回统计口径。
- 批量操作逐节点鉴权和记录结果，不因选中父任务而隐式包含整棵子树。
- 会议行动项与其直接关联的任务节点同步，不向祖先或后代传播状态。

### 6. 搜索、筛选和统计保留层级上下文

- 搜索或筛选命中子任务时，结果返回从根任务到命中节点的完整 `ancestor_path`，至少包含每个节点的 `id`、`title` 和 `depth`。
- 父链必须批量或递归查询，禁止按结果逐节点查询造成 N+1；父链中的每个节点都经过可见性校验。
- 默认保存视图同时匹配根任务和子任务。调用方可显式选择仅根任务，但不能返回缺失父链的子任务搜索结果。
- 统计接口显式声明 `roots_only` 或 `include_descendants`。节点计数去重，完成进度与全局任务统计不得混用隐含口径。

### 7. 删除和移动按整棵子树提示与执行

- 删除任意父任务会删除其整棵子树。执行前，服务端必须提供受影响的节点总数、最大深度和必要摘要，前端必须明确提示“将删除 N 个任务及其子任务”并二次确认。
- 删除服务先枚举完整子树，对每个节点执行现有的权限、行动项解绑、附件清理、活动与通知快照逻辑，再在一个事务中删除；不能只删除父节点并依赖数据库级联跳过业务清理。
- 移动父任务会原样移动整棵子树。确认提示必须展示受影响节点数、原父链、目标父链和移动后的最大深度。
- 当前 `Task` 没有归档或恢复语义，阶段 C 不新增任务级归档/恢复。任务清单归档只改变清单可用性，不拆散或重写任务树；未来若增加任务恢复，必须另立 ADR 定义整树恢复和冲突处理。

## 结果与权衡

该方案允许产品在首期提供五级拆解，同时避免把一级限制写死在数据库中。100 个直接子任务、500 个树节点和可配置深度为递归查询、权限校验、确认提示及前端渲染提供了可测试的上界。

代价是创建、移动、删除、搜索和统计必须使用递归查询与事务锁，权限测试也会明显多于一级模型。邻接表在首期规模下更简单且没有路径冗余一致性问题；如果以后需要远超 500 节点的树或高频跨树移动，应基于实际指标重新评估物化路径或闭包表。

## 不采用的方案

- **数据库和 API 只允许一级子任务**：实现简单，但模型过早固化产品限制，未来扩层需要迁移并重写契约。
- **不设上限的递归层级**：体验灵活，但无法为递归查询、权限、渲染和删除影响提供可靠容量边界。
- **首期使用物化路径或闭包表**：读取更快，但移动需要维护额外一致性；在 500 节点上限下收益不足。
- **父子自动同步完成状态**：会覆盖节点负责人的独立决策，且容易与会议行动项双向同步产生循环更新。
- **父子关系自动继承或传播分享权限**：容易通过挂载或分享泄露原本不可见的任务。

## 实现门槛

ADR 评审通过后才能进入模型和 API 实现。实现至少需要：

- 新迁移、递归查询与统一层级写服务。
- 稳定错误码：循环、跨组织、深度超限、直接子任务超限、整树超限和父链不可见。
- 深度、宽度、整树规模、并发移动、权限矩阵、搜索父链、独立状态及子树删除/移动的后端测试。
- 五级创建、完整父链、完成进度和整树影响确认的真实 E2E。

## 实现验证

阶段 C 已满足上述门槛：层级写入使用组织范围的稳定事务锁，直接子任务排序使用完整同级快照的原子 reorder 接口；权限和通知均复核完整父链。PostgreSQL 后端层级与任务回归测试共 `84 passed`，相关前端单元测试 `45 passed`，真实 OIDC + Chromium E2E `3 passed`，包含五层创建、独立状态、完整父链搜索、子树移动和整树删除确认。
