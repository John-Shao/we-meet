# ADR 0017：单写主 + 多可用区；区域恢复写入依赖同步灾备安全账本

> 状态：Proposed（目标架构提案，待架构评审签收）
>
> 日期：2026-10-25
>
> 决策编号：A10
>
> 决策范围：目标架构；不证明当前仓库已实现，也不替代真实用户/生产验证。
>
> 关联：[Work 系统架构](../plan/work-system-architecture-2026-10-25.md)

## 背景

多区域双写会造成跨日志原子性缺口；安全事实丢失比短暂不可用更严重。

## 决策

业务库单写主、多 AZ 高可用；承诺区域写恢复的部署必须把派发、预算、撤权、删除 tombstone 等安全事实同步复制到独立灾备故障域，否则禁止自动跨域恢复写入。

## 备选与取舍

跨故障域提交增加延迟，分区时执行不可用；需要显式声明每个部署形态的提交持久性边界，且不能降级为异步安全提交。

## 证据与关闭条件

架构 §18.2–§18.3；F15/F26；S5。状态保持 Proposed，待架构评审、对应验证闸门和风险登记签收后转为 Accepted；不得仅因文档存在而宣称生产就绪。
