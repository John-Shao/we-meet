# ADR 0007：Work 执行模型只承诺本地与远程，云电脑标记为规划中

> 状态：Accepted
>
> 实现状态：Partially implemented（本地 / 远程协调已存在，`waiting_device` 与超时未实现）
>
> 日期：2026-10-24
>
> 后续变更：2026-10-25 已删除日常办公的 `communication` 执行器与材料处理；下文涉及材料、来源重授权和该执行器的表述仅保留为当时背景，不再代表当前实现。
>
> 决策范围：执行位置、离线语义、跨端派发、数据边界与可用性叙事
>
> 关联：[Work 方案第 11 节](../plan/work-module-product-architecture-agent-plan-2026-09-21.md)、[Work Agent 架构](../features/work-agent-architecture.md)、[ADR-0005](0005-work-two-layer-access.md)

## 背景

设计稿第 11 节给出了一张跨端执行表，其中两行承诺了当前没有资源兑现的能力：

| 情况 | 设计稿原文 |
|---|---|
| 云端任务，电脑关机 | 云端继续；手机可看进度与成果 |
| 从本地切云端 | 确认材料迁移后重新规划；不承诺迁移任意运行进程 |

实现侧的现状是：

- `work.WorkRun.execution_target` 取 `cloud` / `local`（`work/models.py:139`）。
- 远程派发由 `remote_api.RemoteTaskView` 把任务落到目标 workspace，执行仍发生在用户设备上（`work/remote_api.py`）。
- 设备领取与回报在 `local_runs.claim()` / `report()`；租约过期后置为 `disconnected`，不自动重发（`work/local_runs.py:323`）。
- 服务端 Agent（`agent_runs.claim()`）是内部灰度路径，生产 `WORK_AGENT_ENABLED` 默认关闭。
- 设备离线时，远程任务目前停在 `queued`，用户看到的是“排队中”，无法区分“设备离线”。

用户于 2026-10-24 明确：当前只规划**本地执行**与**远程执行**（例如用手机或家用电脑提交到办公电脑执行）；**没有资源实现云电脑**，应标记为“规划中”。

## 术语

本 ADR 区分三件常被混为一谈的事：

1. **服务端固定流程调用**：历史上 `communication` 执行器在服务端调用模型生成草稿；该能力已于 2026-10-25 删除。
2. **服务端 Agent 执行**：`execution_target=cloud` 的 office_agent / Pi 路径。当前是内部灰度和只读复核，不是用户可依赖的执行承诺。
3. **云电脑**：持久的云端工作环境，预装用户软件、挂载用户文件、在用户设备关机后继续运行。**当前不建设，标记为规划中。**

## 决策

### 1. 产品只承诺两种执行位置

- **本地执行**：在当前设备上运行，文件和工具留在本机；模型调用按授权策略进行。
- **远程执行**：从设备 A 提交，在设备 B（如办公电脑）上运行；B 必须在线、已授权该 workspace，并以 B 的本地权限执行。

不承诺第三种“云端替你继续跑”的执行位置。

### 2. 云电脑标记为规划中，不进入 P0/P1

- 产品文档、导航和销售材料统一标注“规划中”，不给日期、不给 SLA、不作为差异化卖点。
- 设计稿第 11 节的“电脑关机云端继续”删除，改为“任务等待目标设备上线”。
- 服务端 Agent 路径保持内部灰度，不得在设备离线时被静默选中作为替代。

### 3. 状态语义

在现有状态上新增一个用户可见状态：

| 状态 | 含义 | 是否终态 |
|---|---|---|
| `queued` | 已受理，目标在线或即将领取（短时） | 否 |
| `waiting_device` | 已受理，目标设备离线或尚未领取；任务未开始 | 否 |
| `running` | 设备已领取并开始执行 | 否 |
| `disconnected` | 已领取后设备失联，租约过期；可能已产生部分副作用 | 是 |
| `succeeded / failed / canceled` | 既有终态 | 是 |

- 远程任务在准入时若目标设备离线，落 `waiting_device` 并写事件；设备上线后转回 `queued`，再按正常领取流程执行。
- `waiting_device` 超过 `WORK_WAITING_DEVICE_TTL`（建议 7 天）转 `failed + device_offline_timeout`。
- `disconnected` 是终态，不自动重发、不自动切换设备；用户显式重提才创建新 run。

### 4. 执行位置在准入时冻结，禁止静默回退

- `execution_target`、`device`、`workspace`、目标和模型在 `local_runs.admit()` 时冻结（`work/local_runs.py:63`）。
- 目标设备离线、掉线、撤销授权、workspace 停用，都不触发服务端接管。
- 切换执行位置必须由用户显式操作，创建一个新的 run（新 `request_key`），并重新走组织/成员授权与目录授权。
- 不得把远程任务改派到另一台设备；用户必须重新选择目标。

### 5. 用户可见交互

设备离线时提供三个明确动作：

1. **等待**：保持 `waiting_device`，展示目标设备名称、最后心跳、离线时长。
2. **取消**：终止任务；从未派发的预占可以释放。
3. **改用当前设备执行**：创建一个新的本地 run，需要重新确认目录授权。

补充规则：

- 进度文案用“等待设备上线”，不用“处理中”；不显示虚假百分比。
- 设备上线通知可选、限频，默认不做持续打扰。
- 成果只有在设备上传、服务端校验 manifest 后才可见；离线期间不提供“预览”或“下载”假入口。

### 6. 数据边界

- 准入时冻结的 payload 是设备能看到的全部输入；设备不能自行扩大输入范围。
- 服务端在领取、回报、成果同步三个时点重新鉴权（沿用 ADR-0005 的组织/成员校验）。
- 成果写入 owner + organization 限定的存储；设备不能写入其他 owner 或组织的路径。
- 设备身份、ticket、序号与哈希继续用于防重放（现有 `local_runs` 契约）。

### 7. 预算与计量

- 从未派发的 `waiting_device` 取消：释放预占，因为没有发生模型调用。
- 已派发或结果未知：沿用“预占不自动退还”，用量可能已经发生在设备侧。
- 设备上报的用量标记 `usage_origin=device_reported`，不作为供应商账单。
- 远程执行同样受组织级日预算约束（ADR-0005）。

### 8. 可用性叙事

- 对外表述：任务运行在用户自己的设备上，文件和工具不离开本机；设备离线时任务会等待，不会悄悄搬到云端。
- 这是与“云端 Agent”不同的取舍，不是缺陷；不承诺 7×24 可用性。
- 支持文档必须写明：办公电脑休眠、断网、关机都会让远程任务停在 `waiting_device` 或 `disconnected`。

## 后果

**正面**

- 产品承诺与实现一致，不再出现“关机后云端继续”的无法兑现文案。
- 数据边界更清晰：没有隐式的跨设备或上云迁移。
- 失败语义明确：等待、掉线、超时各有独立状态和处理动作。

**代价**

- 可用性低于云端方案；用户必须保持目标设备在线。
- `waiting_device` 增加一个长驻状态和超时清理任务，前端、通知、统计都要适配。
- 远程执行的支持成本上升，需要设备状态与最后心跳的可观测性。
- 若未来要做云电脑，需要新的执行环境、持久化、隔离与计费体系，另立 ADR。

**风险**

- 用户容易把“远程执行”理解成“云端执行”，文案必须持续澄清。
- 设备休眠策略因操作系统而异，心跳与租约参数需要按真实环境校准。
- 设备侧部分执行后失联时，副作用无法自动回滚，只能标记未知并让用户核对。

## 不采用的方案

- **设备离线时自动切服务端执行**：违背“文件不离开本机”的承诺，且会让失败归因不可控。
- **掉线后自动重发**：设备可能已经产生部分副作用，重发会重复执行。
- **现在建设云电脑**：没有资源，且会同时引入持久化、隔离、计费和合规问题。
- **把服务端 Agent 当成默认执行位置**：当前只是灰度与复核路径，不具备产品级承诺。
- **用“排队中”掩盖设备离线**：用户无法判断该等待还是该换设备。

## 实施顺序

1. 增加 `waiting_device` 状态、事件与读模型映射；前端显示设备名称、最后心跳和三个动作。
2. 准入时检测目标设备在线状态；离线落 `waiting_device`，上线转 `queued`。
3. 增加 `WORK_WAITING_DEVICE_TTL` 与 beat 清理任务；超时转 `failed + device_offline_timeout`。
4. 取消 `waiting_device` 时释放未派发预占；补计量测试。
5. 删除设计稿与产品文案中的“云端继续”承诺，统一改为“等待设备上线”。
6. 补跨端 E2E：离线提交、上线领取、掉线终态、超时、切换设备新建 run。

## 验收

- 目标设备离线时提交远程任务：状态为 `waiting_device`，不产生模型调用，不落 `running`。
- 设备上线后任务转 `queued` 并被原设备领取；其他设备不能领取。
- 设备中途掉线：租约过期后 `disconnected`，不自动重发，不切服务端。
- `waiting_device` 超时：`failed + device_offline_timeout`，原因可见。
- 取消 `waiting_device`：预占释放；取消已派发任务：预占保留。
- 组织或成员在等待期间被停用：任务终止为 `org_disabled` / `member_disabled`，不执行。
- 页面不存在“云端继续”或虚假进度文案。
