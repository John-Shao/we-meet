# ADR 0004：会议模块的职责边界（会议实录 = 妙记等价物）

- 状态：**已采纳**（2026-09-19）
- 相关：`docs/research/miaojie-gap-analysis-2026-09-18.md` §5.1

## 背景

「会议」下有三个入口，用户看到的却是**同一批记录**：

| 入口 | 路由 | 现有职责 |
|---|---|---|
| AI 录音 | `/meeting/recording`、`/meeting/recording/capture` | 采集 + 导入 |
| 会议实录 | `/meeting/notes`、`/meeting/records/:id` | 记录与原文 |
| 智能纪要 | `/meeting/minutes` | AI 产物 |

问题不在数据层——`MeetingRecord` **已经**是「身份 + 媒体 + 原文 + 产物容器」，
且独立于会议存在（`source_type` = `meeting` / `audio_recording` / `upload`），
正是飞书妙记的形态。问题在信息架构：三个入口并列，导致

1. AI 录音页与会议实录页**重复展示同一批记录**；
2. 同一条记录在两处**两套版式**（竖排两行 vs 横排一行）；
3. 「智能纪要存在哪里」认知分裂——它其实是实录注入 `has_summary=true`
   （`MeetingLibrary.tsx:711`）。

## 决策

**`会议实录` 是录音/上传记录的权威列表（≡ 妙记）。**

1. **会议实录 = 妙记等价物**：记录身份 + 媒体 + 原文 + AI 产物容器。
   整理/检索/分享/导出都以它为准。
2. **智能纪要 = 会议实录的一个视图**，不是独立资料集。它读的是同一份记录，
   只是筛出「已生成纪要」的那些。**不新建数据、不新建所有权**。
3. **AI 录音 = 动作入口**：保留「录制 / 导入」两个动作 + 最近记录快捷列表 +
   「更多」指向实录的对应筛选。**不做长列表的第二份权威**。

### 本次落地的具体改动

- 录音页标题由「历史录音」改为「最近录音」（zh）/「Recent recordings」（en）
  /「Enregistrements récents」（fr）/「Recente opnamen」（nl）/「Letzte Aufnahmen」（de），
  Android 同步改 `recording_history`。
  **理由**：该页只给最近 20 条，标题不该承诺"全量历史"——全量在会议实录。
- 保留 20 条上限（**不做缩短**）：20 条是既有的、可用性验证过的窗口。
  收敛的是**语义**（这是"最近"，不是"全部"），不是条数。

## 明确不做

- **不改数据模型**：`MeetingRecord` 已是正确形态，没有迁移。
- **不删路由 / 不合并页面**：保留三个入口的便利性，只收敛语义与权威归属。
- **不动「更多」的目标**：仍为 `/meeting/notes?source_type=recordings`。

## 后果

**正面**
- 「同一批记录两处两套版式」的重复感消失：录音页自己是"动作 + 最近"，
  实录页是"全部 + 管理"。
- 后续 M2「逐字稿修订」有了明确挂载层：**实录内的原文**（不是纪要、不是录音页）。

**代价 / 仍需注意**
- 「智能纪要」仍是独立导航项，认知分裂只是**缓解**而非消除。
  彻底合并（删导航项、改为实录内筛选）成本更高（Web + Android + i18n + 文档），
  本次**不做**，留待有足够收益时再评估。
- 录音页 20 条与实录页仍会有重叠内容，这是"最近"语义的必然结果，可接受。
