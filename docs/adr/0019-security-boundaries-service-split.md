# ADR 0019：按安全边界拆部署，按真实瓶颈拆服务

> 状态：Proposed（目标架构提案，待架构评审签收）
>
> 日期：2026-10-25
>
> 决策编号：A12
>
> 决策范围：目标架构；不证明当前仓库已实现，也不替代真实用户/生产验证。
>
> 关联：[Work 系统架构](../plan/work-system-architecture-2026-10-25.md)

## 背景

R0 的流量和团队规模不足以承担过早分布式化的运维和授权复杂度；按安全边界拆能先隔离凭据、执行和内容。

## 决策

先按 API/worker/egress/runner/device gateway 等信任域拆部署；Kafka、向量库、独立搜索和微服务只在容量/驻留/安全证据出现后引入。

## 备选与取舍

后拆服务需要可观测阈值和迁移计划；模块化单体不能成为不拆的永久借口；所有拆分必须保持领域命令和账本。

## 证据与关闭条件

架构 §2.3、§20.2；S6 容量。状态保持 Proposed，待架构评审、对应验证闸门和风险登记签收后转为 Accepted；不得仅因文档存在而宣称生产就绪。
