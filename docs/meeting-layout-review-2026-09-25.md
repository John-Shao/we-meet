# 会议子模块布局与交互检查

范围：AI 录音、会议实录、智能纪要的 Web 与 Android 页面。

## 发现与调整

| 页面 | 问题 | 调整 |
| --- | --- | --- |
| Web 实录、纪要列表 | 展开的筛选区在 390px 下占约 547px 高，压缩列表；条件混合即时生效与提交生效 | 使用共享筛选弹窗，正文高度保持不变；范围、来源、日期统一在“应用筛选”时生效；Escape、关闭和点击遮罩放弃草稿 |
| Web 列表 | 搜索或筛选无结果时，只提示暂无数据，缺少恢复操作 | 显示“没有匹配的记录”与“清除筛选”；清除搜索、来源、日期及范围并重置分页 |
| Web 列表 | 来源来自链接时自动展开筛选，返回列表也会恢复展开状态 | 保留查询条件和列表位置；筛选弹窗仅由用户打开；头部显示当前条件及清除入口 |
| Web 录音子页 | 开始录音页在手机宽度下仍保留桌面侧栏 | 所有会议子页共用窄屏隐藏侧栏规则；一级页保留栏目入口，详情页保留列表返回入口 |
| App 实录、纪要列表 | 筛选入口分散在更多菜单与来源行；两页范围切换样式不同 | 统一可见的筛选入口、可横滑的范围标签和列表／网格切换 |
| App 筛选 | 范围、来源未确认便生效；横滑选项难以发现；长表单中的确认操作不稳定 | 范围、来源和日期使用统一草稿；返回或关闭不提交；选项自动换行，正文可滚动，底部保留清除和应用操作 |
| App 搜索 | 搜索无结果时只有刷新，无法直接清除查询；提交后焦点仍留在输入框 | 空结果提供清除筛选；提交或关闭搜索时清理输入焦点与键盘 |
| App AI 录音 | 来源、时间和上传状态共用一行，长状态被截断；关闭历史能力时底色不连续 | 辅助信息最多三行；历史不可用时也保持白色内容区铺满 |

## 验证方式

- Web：`scripts/check-meeting-layout-ui.mjs` 使用真实 Chromium 与固定 GET 数据，覆盖 320、390、768、1440px，长标题、独立滚动、筛选取消／提交／无效日期、搜索恢复、录音子页、深色主题及 200% 文字。
- Web：列表、录音概览、录音页、实录工作区及返回列表状态共 64 项相关测试；另运行 TypeScript、ESLint、语言包及设计 token 检查。
- Android：本地 Pixel 8 模拟器，25 项相关检查通过；另外将设备调整到实际 320dp 宽度、系统字体 1.5 倍，3 项专项检查通过。检查结束已恢复原始分辨率与字体设置。Debug 构建及 `checkDesignTokens` 通过。
- 截图为测试数据，不依赖生产账号；本次主要验证布局和交互，没有执行真实录音、上传、分享或删除。

Android 对应修改位于同级 `we-meet-android` 仓库。此记录不表示已经提交、推送或部署。
