# 双向翻译 WebSocket 发布候选

本候选以生产后端镜像对应的 `f950ba8cc2ef13ddc0ed8feb21768f1a81e2f34f` 为基线，只合入双向翻译修复。保留既有声纹、会议远程控制及采集翻译功能，不携带原开发工作区中未提交的办公平台和屏幕共享改动。

## 数据与配置

生产只读检查确认已应用 `0226_remote_control_signing_rotation`。本候选增加 `0227_bilingual_session`，依赖该迁移，创建双向翻译独立会话表。原隔离测试中的 `0203_bilingual_session` 依赖另一条开发迁移链，不能原样部署到生产；其内容已移植至 `0227`，未改动生产既有迁移。

默认关闭 `ASSISTANT_TRANSLATION_ENABLED`；每用户并发 1 次、每日 100 次、最长 900 秒、有效活动空闲 300 秒。旧直连接口在部署后返回 426，须协调新版内部 APK 的交付与启用时机。会议/AI 通话的 AOQ 与 WebRTC 不在退役范围。

## 候选验证

- 生产基线上的四个双向翻译后端测试文件：94 项通过，94.92 秒；迁移模型检查无漂移。命令为 `src/backend/.venv/Scripts/python.exe scripts/test_bilingual_backend.py`，仅使用本机临时数据库。
- 网关相关 12 个 unittest 模块：137 项通过，6.425 秒；范围与 Android 仓库 `docs/bilingual-websocket-design.md` 一致。
- 29 种音频语言契约一致；Android app 五语言检查 0 错误、158 条既有提示。
- 发布分支的 Release guard 增加 `test_bilingual_sessions.py`，必须取得该候选提交的完整 CI 成功记录。
- APK、真实链路、部署与开关回滚结果在完成后追加。既往 Debug/真机声学证据不冒充本候选 Release 验证。

## 发布顺序

1. 固定两个仓库的候选提交；Android 使用用户确认的既有内部签名，交付非 debuggable 的内部 Release 包。
2. 完成候选包覆盖安装、真实登录页面和翻译冒烟，检查实际签名、版本和正式域名。
3. 构建不可变标签的后端、agents 镜像，通过 Release guard。生产仓库存在其他未提交改动，使用独立发布检出，保留当前 Helm values 和未选中组件镜像。
4. 运行发布预检，核对迁移、Ingress、内部鉴权及配置；使用 `release-meet.sh backend translation-gateway` 仅部署后端与翻译网关，保留其他 agents 镜像，并关闭双向翻译开关。
5. 在受控范围完成 V2 链路验证后开启。检查结束边界、回放、业务会话关闭及旧接口 426。
6. 验证关闭开关能拒绝新会话，并通过续约终止已开会话；恢复预期状态。保留新表，不回退到旧直连分配接口。

本轮耳机和并发容量仍按用户决定不验。用量已记录，实际账单金额后续核对。发布观察关注错误枚举、ACK 超时、收尾不完整、会话释放和输入输出字节数，不记录凭据、原文、译文或音频。
