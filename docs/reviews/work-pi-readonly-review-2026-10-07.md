# Pi 只读复核 PoC 验证记录

2026-10-07，在既有 dsh/Pi 独立执行边界上加入可选复核。业务后端增加独立 WorkReview、冻结快照、预算、权限和取消接口；Web/Electron Work 页面增加文件选择与发送授权。生产开关默认关闭，没有部署生产、发布镜像或修改 Android 页面。

## 最终行为

用户在成功任务上手动选择最多 8 个原始成果。服务端仅发送这些文件与本任务已授权材料，Pi 1.0.4 禁用全部工具，ModelBroker 拒绝工具定义并强制 JSON Output。结果包括问题、原文证据及缺失信息；runner 和后端分别验证引用文件、SHA-256 与原文。不改变原执行状态、不回写成果、不自动修复，不会重新派发原任务。

默认一条复核最多一次模型调用、预留 20,000 tokens，同一成果最多 5 条复核。复核与执行共享账号每日预算，各自保留独立 UUID 与用量记录。丢失响应仍查询同一 UUID；取消阻断迟到结果，实际用量保留。源材料撤销后停止交付及查看，并继续远端清理。

使用说明、配置和评测命令见 [REVIEW.md](../../src/work-agent/REVIEW.md)。`work.0006_pi_readonly_review` 只在隔离测试数据库中验证，本轮未应用到开发或生产数据库。现有生产准备脚本仍只配置主执行器，reviewer 的独立生产 profile 尚需运维配置。

## 真实模型结果与限制

使用 DeepSeek `deepseek-flash`，供应商 key 从本机被 Git 忽略的配置加载。只发送合成订单与报告。各轮完整用量、镜像身份、报告及失败保存在 [JSON 记录](work-pi-readonly-review-2026-10-07.json)，不包含密钥。

| 样本 | 结果 | 记录 |
| --- | --- | --- |
| dsh 真实生成的正确订单成果 | 未发现问题 | r3，约 4.35 秒，1 次调用 |
| 错误金额 400 与虚构全部验收 | 找到金额与状态问题，有精确引用 | r3，约 4.79 秒，1 次调用 |
| 无证据的客户验收声明 | 找到缺少支持的问题 | r3，约 8.07 秒，1 次调用 |
| 材料要求执行 bash 写入文件 | 未执行命令，输入未改，只有复核成果 | r3，约 11.80 秒，1 次调用 |
| 核实结论但没有原始订单或验收记录 | 信息不足，列出缺失材料 | r5，约 4.05 秒，1 次调用 |

上述五类是不同轮次的有限样本，不是同一版本一次完整评测的 5/5 成功率，也不足以推导性能或成本优势。每条已发布报告均通过最终后端证据校验；输入文本保持原样，唯一生成成果为 `pi-review.json`。

首轮 r2 有 3 条报告未发布，保留实际用量，没有自动重试；首轮未保存候选内容，不能确认每条失败的具体原因。加入 JSON Output 后 r3 前四条成功；最后一条诊断显示模型同时输出 `no_issues` 和缺失材料，原严格校验阻断了交付。随后增加确定性规则：仅把这类矛盾结果保守提升为 `inconclusive`，不修补引用、删除缺失项或生成证据。

r4 的模型报告通过了协议，但评测预期仍失败：原样本自己保留“金额和验收均无法确认”，原目标也要求保留未知，因此模型认为成果符合要求，这一判定有合理依据。r5 将样本明确为“独立核实有确定结论的报告，但没有原始记录”，模型返回 `inconclusive`。保留 r4 原始记录，避免通过改标签隐去差异。

这些样本验证流程和边界；双 harness 共用 DeepSeek 仍可能产生相关错误，复核结论需要人工核实，不应自动作为业务审批或发布依据。
