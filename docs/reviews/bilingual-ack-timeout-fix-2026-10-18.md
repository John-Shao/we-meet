# 双语互译 BT11：ACK 与界面线程耦合修复

用户在荣耀 300 / Android 16 重测长句“我明天上午 9 点去火车站，然后乘坐高铁去上海参加会议”，仍出现译音不完整，诊断码为 **BT11 / ACK_TIMEOUT**。

## 已确认的失败机制

旧版将 ACK 处理和输入发送排在界面线程。真实 WebSocket 已收到 ACK，但界面线程忙碌时，确认额度与输入发送不能推进，恢复后可能误报五秒 ACK 超时，关闭会话并截断译音。

本轮使用 OPPO / Android 12、实际 OkHttp TLS WebSocket、手机内本地测试服务器和真实 AudioTrack 做对照。界面线程阻塞 6.2 秒，旧 work.6 的网络回调已收到 2 个 ACK，服务端输入帧仍从 2 停在 2，最终明确复现 ACK_TIMEOUT。此前初始化证书、测试 URL 与熄屏造成的测试环境失败单独保留，不与有效对照混算。

这证明了一类与本次错误码一致的客户端故障；尚未取得荣耀手机原故障的线程日志，不能声称自然语音的全部中断原因均已确认。

## 修复与边界

- ACK 在网络接收回调中确认；输入窗口、发送与 ACK 看门狗在后台线程推进。结果与页面更新仍按序安装。
- 服务端结束消息到达后停止继续采集/发送，保留排空尾音；服务端错误紧接断线时保留原始失败类别。
- 后台发送在等待前后复查登录授权与取消，避免授权失效后继续发送排队 PCM。
- 保留五秒 ACK 限制、50 帧发送窗口、50 帧采集缓冲和 64KB 网络队列预算；没有放宽超时或以扩大缓存掩盖问题。

## 验证与交付

候选版通过相同真实 TLS WebSocket 对照：界面忙碌时输入和 ACK 持续推进，12 秒零值 PCM（288000 个样本）全部写入并排空，结果与可回放记录保留。真正缺失 ACK 的控制组仍在原有五秒预算内失败。控制器回归 42 项通过（另两项长时专项为显式 opt-in，本轮未启用）、1019 项 JVM 回归、40 项脚本测试，以及产品提交的两项 CI 均通过；详见配套 JSON 与本地不可变证据归档。

整类控制器运行达到主机脚本预设的八分钟总时限，当时已完成的用例没有断言失败。首批日志保留，尚未完成的 10 项单独补跑后，合计覆盖全部 44 项（42 项通过、2 项按显式 opt-in 条件跳过）；不把首批记为一次完整通过。

传输对照使用合成输入与零值 PCM；控制器回归另覆盖真实麦克风的后台和熄屏持续收音，但没有用户口述或人工听感确认。AudioTrack 排空不等于人工听感、完整语义或荣耀设备验收。旧版仅使用即时 ACK 替身的长音频回归不足以覆盖此机制，新增真实传输对照补足该缺口。
