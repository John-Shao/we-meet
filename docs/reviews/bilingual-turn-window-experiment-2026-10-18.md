## 普通短句结果

单位为毫秒：同一探针时钟下，估计说话结束到网关首次下发译音。不是手机实际出声时间。550/1000 与 400/700 采用相反顺序的两轮对照；300/500 只有一轮，550/700 在后续时段测两轮，不能排除时段波动。

| 本地 VAD / 供应商静音窗口 | 中文中位数（样本数） | 英文中位数（样本数） |
| --- | --- | --- |
| 550 / 1000 | 1167.8（n=2） | 732.0（n=2） |
| 400 / 700 | 1029.4（n=2） | 570.1（n=2） |

400/700 相比基线：中文约减少 138.3 ms，英文约减少 161.9 ms。样本有限，不外推为旅游场景的平均收益。

## 停顿与交替语言

在两个原有合成短句的 VAD 语音区间中点插入 500 ms 全零 PCM，不删除原样本。这是压力测试，可能切在音素中间，不代表自然停顿、真实口音或旅游地名。离线 12 项检查中，550 ms 本地窗口保留一段，400/300 ms 均切成两段。

“预期输出形状”只检查预设条数、语言标签、音频字节和结束边界，不等于语义完整性或声学验收。400/700 停顿样本的中英文各输出两条、均带 audio_end、方向正确、无协议错误；不能据此宣称漏译或断言两段语义正确。550/700 也出现两条译音，虽然本地仍只有一段，说明供应商也能独立断句。多段样本不计算单句延迟，避免将第一条译音与最后一个语音结束错误配对。

本轮发现旧诊断单句标记只检查 VAD 段数，无法排除“本地一段、供应商两条”的情况。原始 JSON 保留旧标记与时间，分析记录另存 original_summary 并剔除两项供应商分段样本的单句延迟。诊断脚本已改为记录每条下发译音的首包并检查条数，增加回归；不影响上表普通短句中位数。

中英文交替是在同一业务会话连续输入中文、5 秒零 PCM、英文；未按实际译音播放完成控制第二句，因此只是自动方向路由检查，不替代半双工产品流程或回声测试。

## 结论与下一步

暂不采用 400/700、300/500 或 550/700 作为产品默认值：本轮观察到了缩短等待与句中停顿分段之间的取舍；只缩短供应商窗口仍有分段，普通英文等待波动也较大。仍需更多自然短句、短回答、长句停顿及实际听感确认后才能选型。当前继续保留 550/1000。

后续优先在人可配合时完成真实手机网络与播放计时、自然中英文停顿及语义/听感对照；本轮未覆盖短回答、旅游地名、口音、持续环境噪声或播报中插话。旧的四次建连失败仍保留为独立遗留问题，本轮结果不证明其根因已修复。CPU 调整、扩大灰度/常开、有线/蓝牙及账单金额继续按原决定延期。

- 本轮 23 个真实供应商场景，无自动重试；使用固定合成 PCM、fixture admission、loopback 下游。不会创建业务 API 用量行，诊断计数单独归档，账单金额未取得。
