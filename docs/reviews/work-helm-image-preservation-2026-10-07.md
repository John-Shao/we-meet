# Work 镜像与部分模块发布保护验收（2026-10-07）

生产业务对齐已完成，回执见 [业务发布回执](work-k3s-business-alignment-release-2026-10-07.md)。本批仅修改发布源码和离线验证，不执行生产 Helm 升级，不调用模型，不启用四个新功能开关。

修复的问题：业务镜像已按 digest 部署，旧脚本要求从 tag 反推提交；其他模块的 Helm 发布也会重新渲染后端配置，并执行后端数据库钩子，可能覆盖现场的关闭开关。本批允许组件使用完整镜像引用；未选中后端时保留全部七个后端工作负载的完整 spec，并在渲染前关闭数据库迁移和管理员创建钩子。可选 AI worker 未部署时从公开 values/chart 默认配置解析仓库，发布不会自动启用它。

后端 digest 的 CI 来源仅取已提交的镜像回执，必须唯一对应一个有效源码提交；原有源码 CI 和 AI pool 兼容检查保留。后处理器检查镜像来源和快照一致，并在渲染时重新检查资源 UID/spec；不符合即停止。该检查是发布前的漂移保护，不构成 Kubernetes 多资源原子事务，操作期间仍应避免并发发布。

在本地 WSL 上验证 54 项通过：镜像引用与发布链路 16 项、已有 CI 门禁 9 项、会议 AI chart/脚本 26 项、HTTP AI pool 3 项。使用真实 Helm 的离线链路覆盖前端发布保留 7 个后端 spec、数据库 hooks 不生成、可选 worker 仓库回退及关闭状态，以及 UID/spec/镜像变化时停止。Helm lint、Bash 语法检查、新增 Python 文件 Ruff 和 git diff 检查通过。所有集群接口使用只读替身，无生产凭据读取或模型调用。

生产 Helm revision 457 的已存模板尚未通过新脚本重新发布，本批不会消除现场与 Helm 历史之间的差异。后续真实发布前需要基于已提交源码、CI 成功和现场快照检查 dry run；不能据此直接执行旧 Helm rollback。下一阶段为测试账号准入与合成材料的桌面/Android 联调，四个新开关继续关闭，测试账号待指定。
