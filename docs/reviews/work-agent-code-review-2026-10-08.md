# Work Agent 代码走查整改（2026-10-08）

在生产联调和架构整改后，走查业务复核快照、Gateway 凭据与计量、K3s Pod 生命周期、桌面协调与签名运行环境、Web/Android 报告访问以及发布/回退入口。原任务与复核分离、授权材料冻结、未知执行不重放、未知计量不清零、账号撤销隐藏缓存和供应商密钥隔离的既有检查继续保留。

| 问题 | 触发与后果 | 修复与验证 |
| --- | --- | --- |
| 直接重提任务没有核对已持久化工作空间 | 云端接收响应丢失后，同 UUID/目标/标签但换 workspace ID，可在新目录执行原任务 | 在任何原生能力查询或云端请求前核对 workspace ID；重启后的跨目录重提拒绝且无新请求，原目录可恢复 |
| 运行环境健康探测失败占用了正式版本目录 | 下一次导入同一合法签名版本永久返回冲突 | 复制到本次独有暂存目录，验签/哈希、探测、再次校验后才原子发布；失败仅清理本次已核实目录，同版本可重试 |
| 升级/回退的激活指针可能并发覆盖；探测后未重新验包 | 同时切换或探测修改了包内文件时，可能激活不一致目录 | 同实例切换互斥，探测后重新核对完整清单；并发操作与探测篡改回归通过 |
| Gateway 升级镜像校验未区分服务与 worker 镜像族 | 两个合法 digest 镜像对调仍能进入 patch 计算 | 按 Gateway/Pi 分别验证镜像族，错配在 patch 前拒绝；版本化快照保留所有历史升级 |
| 发布保护未兼容旧 Helm `env: null` | 新保护器导致旧版无 Agent 的合法部分发布失败 | 兼容空 env；WSL 16 项真实 Helm/发布测试全部通过，新回归保留此场景 |

桌面 `npm test` 33 项中 32 项通过，实际包运行环境测试按独立开关启用；新 NSIS 候选在构建后单独执行真实解包、包内代码/renderer/运行环境清单及原生适配器探测。签名升级回归使用临时 Ed25519 测试公钥，不将测试公钥作为正式信任配置。

成果引用约束仍检查文件名、哈希和所属文件原文，不能由模型请求覆盖 Gateway 的冻结快照。真实 Pi 容器中使用合成 SSE 响应验证“needs_changes + 缺失信息”保守转成 inconclusive，供应商调用为 0；现有生产报告只读复验后，桌面和 Android 显示信息不足，同时保留原始模型意见与源成果。该机制不会证明模型每条判断正确，也不会自动修改文件或重跑任务。
