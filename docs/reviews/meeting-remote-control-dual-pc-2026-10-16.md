实际构建生产前端镜像时，发现 Dockerfile 未包含引用的七个共享远控模块。补齐 COPY 后，隔离容器又实际报出 `authorization.ts` / `signing-trust.ts` 无法解析 `jose`：模块位于 frontend 的同级目录，原本依赖本机 desktop 的 node_modules。现通过前端 TypeScript paths 和 Vite/Vitest dedupe 显式使用前端已锁定的 `jose@6.2.2`。没有增加浏览器对 Node 或原生执行模块的依赖。

修正后的实际 `frontend-production` 和 `backend-production` 本地 Docker 构建均退出 0；前端远控六文件 35 项测试通过。后端最终镜像中确认包含远控接口、密钥命令及四个迁移文件。镜像尚未据此登记为线上部署或双机验收通过。

功能分支已推送，新增对该分支的 Release guard push 检查，并将实际生产前端 Docker 构建纳入门禁。首次托管运行 `38769700263` 的 Windows 作业通过普通桌面测试，但原生构建失败：vcvars 返回 `Path`，原构建脚本在普通字典中仍读取继承的 `PATH`。现统一 Windows 环境变量名大小写；两项回归测试、本机原生构建、47 项释放故障、58 个子进程崩溃窗口、572 种组合/1,830 次策略判断通过，实际输入调用为 0。后续托管复跑结果另行登记，不把这些本地结果算作托管门禁通过。

用户已指定默认组织中的两个演示账号，A 由维护者操作、B 由用户操作；不在可分发文档中保存登录凭据。B 安装和登录已由用户确认。
