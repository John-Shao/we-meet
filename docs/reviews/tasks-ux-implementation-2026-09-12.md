# 任务模块 UX 优化收尾记录

日期：2026-09-12。承接 [任务与任务清单权限设计审查](tasks-permissions-review-2026-09-12.md) 和工作区中断前的未提交实现。本轮范围是 Web 任务模块的权限、清单协作与生命周期体验，不是重新实施任务模块总规划。

## 最终规则

| 动作 | 允许范围 |
| --- | --- |
| 编辑任务内容、状态 | 任务创建者、负责人、清单所有者或编辑者；直接任务角色与清单角色叠加 |
| 删除任务 | 任务创建者或清单所有者；清单编辑者不再仅凭编辑角色删除他人的任务 |
| 移出清单 | 需要源清单编辑权；默认清单任务按任务编辑权判断；移入目标还需有效的目标写权限 |
| 管理清单成员、转让所有权、删除清单 | 清单所有者 |
| 转让后的原所有者 | 降为编辑者，可以退出；退出后不会因为仍是历史创建者重新获得所有权 |
| 管理员接管 | 仅限本组织已无有效所有者的清单；接管前只展示清单标识和名称，接管操作与审计记录原子提交 |
| 归档 | 默认隐藏，已有任务仍按权限查看、编辑；禁止新增任务和子任务；查看者可以直接打开和退出 |
| 删除清单 | 默认保留任务并移出清单；可选删除清单中所有无负责人任务，须先获取并确认当前影响范围 |

删除任务时，仅保留未包含在删除集合中的子任务，并解除其与被删除父任务的关系。移出、退出或删除清单可能使仅依赖清单授权的成员失去访问，但不撤销任务创建者、负责人、关注人的独立授权。

## 完成内容

- 复用任务移动、删除与清单角色政策，新增 API `can_move`，对内容编辑、移动、删除和成员管理分别判定。
- 详情与表格只提供可写目标清单，并保留当前清单名称；编辑时说明源清单成员失去访问、目标清单成员获得访问的影响。
- 归档清单复用正常导航行，可选中、查看、恢复和退出；直接访问归档清单不再依赖列表接口的归档筛选参数。保留恢复操作的提交中禁用状态，并显示归档说明。
- 共享对话框提供所有权转让；降权、移除和退出说明残留独立权限，异步失败保留界面供重试。
- 删除清单展示无负责人任务数量和前 100 项预览；长列表独立滚动，明确完整删除总数，使用危险色按钮。确认令牌失效或影响范围加载失败时禁止提交附加删除；默认保留任务的操作仍可用。
- 所有权转让、管理员接管写入组织审计日志；离职盘点纳入任务清单，包括有协作者但无显式所有者记录的历史清单。恢复清单查询通过 SQL 判断有效所有者，避免逐清单查询。
- 补齐中、英、德、法、荷五种语言的规则说明；修复旧重复任务测试随当前日期推移失效的问题。

## API 与迁移

- `GET task-lists/{id}/deletion-impact/` 返回 `count`、`token`、`tasks`（最多 100 项）。
- `DELETE task-lists/{id}/?delete_unassigned=true` 的 JSON 请求体须带 `confirmation_token`；集合或任务更新时间变化后返回 `409 task_list_impact_changed`，前端要求重新确认。
- `POST task-lists/{id}/transfer/` 接收本组织有效成员的 `user_id`；不能转让给自己、组织外成员、停用用户或设备账号。
- `GET task-lists/recoverable/` 与 `POST task-lists/{id}/takeover/` 提供受组织管理员权限保护的接管入口。
- 迁移 `0147_task_list_ownership_audit` 添加所有权转让与接管的审计动作类型；迁移一致性检查未发现缺失变更。

发布时先部署后端及迁移，再部署前端。旧客户端的附加删除请求因缺少确认令牌会收到 409；这是保护删除范围的有意行为。未返回 `can_move` 的旧后端会使新版前端禁用清单移动入口。

## 验证与限制

- 前端任务模块 173 项用例已验证通过：全量运行中 172 项通过，新增用例补齐必需回调后，其所在的 36 项列表测试重跑全通过；新增覆盖删除预览过期、冲突恢复、只读源清单和归档查看者退出。
- PostgreSQL 上任务与离职测试共 165 项已验证通过：全量运行 163 项通过，修正测试角色名称和过期日期后，权限与重复任务两个文件的 20 项重跑全通过；其中新增权限场景 12 项。
- TypeScript、任务模块 ESLint、相关后端 Ruff、JSON、颜色对比检查和 `git diff --check` 通过。
- Chromium 使用隔离的模拟 API 数据检查删除、共享、接管三个真实组件，在 `1024×768` 下无运行错误，对话框不超出视口；人工检查截图后调整了长预览与接管行布局。临时浏览器测试入口已移除。
- 全局基础样式检查仍报告日历的 `CalendarManagementDialogs.tsx` 及管理台 `Bots.tsx`、`Members.tsx`、`MeetingRooms.tsx` 的既有反馈组件问题。`offboarding.py` 全文件 Ruff 有三处既有告警，新增权限模块与修改的任务 API 检查通过。
- 本轮未运行真实 Keycloak 登录的浏览器端到端场景；浏览器检查使用模拟数据，多角色权限与真实数据库操作由后端测试验证。开发数据库未执行迁移，尚未部署。
