# 语音开始后并行握手：隔离对照（2026-10-18）

完成语种识别“一次语音、一次握手”的隔离原型验证。原型只在诊断进程中使用，没有接入产品网关默认路径、部署或安装 APK；本地 VAD 550 ms、供应商窗口 1000 ms、语种探针 800 ms、最终原文方向校验保持不变。基线与原型都使用已有识别清理修复 `90af10475`，避免把旧的约 500 ms 同步关连接等待混入本轮收益。

## 机制与生命周期

- 基线在音频前缀达到原有条件、真正调用 detect 时建连；原型在 VAD 确认 start_of_speech 时异步建立同样的识别连接，收音继续。音频内容、探针长度、分类提示及最终方向校验没有改变。
- 握手不提交音频、不请求推理；达到原来的探针条件后使用该连接识别。固定方向和未知语种退避期间跳过准备；正常识别后不续开下一条连接。
- 建连受既有识别超时约束（默认 4 秒）；若准备完成后没有 detect，2 秒闲置期限后退役，关闭沿用 0.5 秒上限。下一条准备先等待之前的有界回收；取消会话会取消准备与闲置计时。
- 这是诊断子类，不调用现有会自动续预热的 prepare()。语音已被 VAD 接纳后立刻取消时，原型可能比基线多建立一条尚未推理的连接；本轮正常语音和静音计数不能外推为所有取消/噪声场景费用相同。

## 短回答结果

合成“是的／Yes”每种方式、每种语言各三轮；顺序为基线→原型、原型→基线、基线→原型。下表为估计说完到网关首包，单位毫秒，尚不包括手机网络、音频播放及实际出声。

## 验证、状态与下一步

- Windows 157 项相关回归、Linux 28 项诊断回归、Ruff 通过。新生命周期回归包括：握手不阻塞消费/不发推理、重复开始不重复建连、取消准备与取消识别的回收、准备失败不静默冷重试、无请求时的闲置回收、上一条关闭后才开下一条、静音/固定/退避不准备、无效音频仍有回收、未知结果不猜测，以及 VAD 钩子只响应开始事件。
- 补测发现并修正原型取消边界：detect 仍在等待上一条关闭时被取消，可能还未等待到共享准备任务，因而后台准备任务没有随之取消。新增先红后绿回归，取消时显式取消/等待准备任务并关闭可能已建立的连接；上一条回收仍受 shield 保护。22 项正常路径模型对照使用补丁前原型；157/28 项回归使用补丁后候选源码，未额外重跑供应商用例。两个版本源码和哈希分别归档，不能混写为同一版本的真实模型验收。
- Linux 使用原修复镜像，网络关闭，只读挂载当前诊断/测试；本轮没有构建或发布产品镜像。实际模型探针为 fixture admission、loopback，不产生业务用量行；诊断用量与连接数另存，金额未取得。
- 最后生产只读复核：Helm 495 / deployed，开关 `false`，全部工作负载就绪 `true`，Pending 0，有效活动会话 0。audit.date 是旧静态标签，实际采集日期见 JSON observed_at。

该原型保留为候选优化。产品接入还需把一次语音的准备信号接到真实路由生命周期，并补产品级取消/退避回归与手机网络/出声验收；本轮没有把诊断 VAD 钩子当作产品实现。真人口述与物理播放仍待配合。
