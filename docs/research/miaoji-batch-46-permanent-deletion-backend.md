# 第四十六批：手动永久删除后端

## 范围与行为

只接受所有者对回收站中独立录音/上传件的明确删除请求，不按日期自动清空回收站。`POST meeting-records/{id}/purge/` 只接收当前 `expected_revision`；在线会议、非所有者、处理中、已恢复或版本变化均拒绝。重复原请求返回同一删除凭据，`GET` 状态继续校验当前账号和组织成员资格。

受理后增加生命周期版本并禁止恢复。后台每 30 秒扫描明确请求，单轮最多 20 个任务、100 个对象步骤及约 15 秒工作预算（单次存储调用有独立超时）；逐对象删除且确认不存在后，才清理记录及其原文、修订、ASR、快照、AI/人工纪要和关联导出记录。存储异常保留任务，5 分钟后重试；用户重试也沿用原意图。关闭开关暂停工作但不解除恢复和上传重放保护。

外部 Docs 文档、已转换任务、已经发送的消息以及用户下载的副本不在删除范围。这里的完成指应用主库与当前私有媒体源站，不是备份、第三方处理商或已交付副本的全链路擦除证明。

## 数据与并发边界

- 新迁移 `0186_record_purge`：保留最小所有者/组织身份、记录 UUID、原意图版本、状态、上传幂等键及私有对象清理标识。没有标题、正文或供应商报错进入公开凭据。
- 记录锁与上传对象 advisory lock 排序恢复、重复请求、对象采用和清理；已存在的跨记录媒体别名拒绝清理。删除后上传键和对象指纹继续阻止旧凭证重建记录，即便功能开关关闭。
- 上传件至少等待当前直传签名 TTL；完成后每小时重新核查上传对象，清理迟到的在途 PUT。原生音频完成后不重复扫描。不能确认实际删除的存储、启用或暂停过版本控制的 S3 桶均不会报告成功。
- 原有临时音频清理容忍记录先被永久删除；任务包显式注册新 worker。

## 验证与发布

真实 PostgreSQL 上，永久删除、逻辑回收、普通上传、直传、分片上传及临时音频清理共 **125 项通过**，包括迁移一致性检查。非空场景包含发布的 ASR、媒体分片、AI 纪要、两个人工版本、导出关联和任务：内部内容清理，任务保留，无外部 HTTP 调用。新服务、任务、迁移和测试 Ruff 通过，`git diff --check` 通过；上传服务原有三处参数数量规则告警未作无关改动。

生产 `MEETING_RECORD_PURGE_ENABLED=False`。本批未部署、未永久删除任何生产样本。下一批补 Web/App 确认、状态与重试入口；随后先发布迁移及全部后端上传采用者/worker，再单独安排启用和专用样本验收。自动保留期仍延后。
