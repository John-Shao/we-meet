# 记录级识别 API 与建议决定事务

日期：2026-10-10。本阶段接通上传记录的公开识别提交／读取／取消，以及人工确认／拒绝建议。Web／Android 的识别交互、其他来源、长 ASR 前导入预检和生产部署继续开发；API 接通不代表真人效果通过。

## 路径与请求

实际路径为 `/api/v1.0/meeting-records/{record_id}/speaker-identification/`，沿用项目的 meeting-records 路由：

| 方法 | 数据 | 行为 |
|---|---|---|
| POST | request_key、整数 expected_revision、明确 organization_id（个人作用域为 null）、1～50 个 user_ids；可选 1～50 个 speaker_ids | 202 返回独立批次和每个目标的任务；不启动或重跑计费 ASR |
| GET | 可选 request_key 查询参数 | 无 key 读本人可见的最新批次；有 key 读准确批次，不存在或不可见均为 404 |
| DELETE | request_key、整数 expected_revision | 取消本批未完成工作及待确认建议，失效租约；匹配关闭时仍可取消，不改最终姓名或 ASR |

POST 的所有字段严格校验，拒绝任意 URL、客户端姓名／评分、重复 ID、超出上限的列表和非整数 revision。组织作用域不从候选或当前页面猜测。默认选择当前已发布来源中尚未人工标记的说话人；明确选择已标记目标返回冲突，未知或其他记录的目标不可使用。

新增 `0208_speaker_identity_requests`：独立 `SpeakerIdentityRequest` 保存记录／请求者／作用域、请求 key、输入摘要、明确目标与候选 ID 和原展示版本；任务关联其批次。记录／request_key 唯一；同 key 的来源、候选、门限或目标选择变化返回冲突。每个任务还绑定目标展示状态。整个批次原子提交，预算不足不会保留半个批次或部分任务。

共享来源及完整候选证明每批读取一次，再按目标创建任务；保留既有每用户 100 个未过期活跃任务预算，新增 POST 6 次／分钟限流。公共批次最多 50 个任务，有界读取，历史批次按已知 request_key 获取；不会自动扩大候选池。

## 读取与隐私

提交、读取、取消和建议决定均要求当前活跃真人账号、当前编辑权限及明确媒体授权。只读分享者、无媒体授权的编辑者不能访问建议。个人库的批次只有原请求者可读／决定；共享组织库还要求当前有效组织成员。某人获得记录的媒体编辑授权不会获得原请求者的个人库或其他组织库。

读取返回任务状态、独立建议版本、固定结果／原因、片段数、有效语音和经过验证的来源时间区间。只有仍有效的待确认建议显示候选账号 ID 和公开姓名，不返回向量、音频、凭证、请求候选列表、指纹、租约、评分或排名。已确认和拒绝的建议不再通过此接口显示生物识别候选姓名；最终人工姓名仍通过既有转写／导出投影读取。

待确认批次只解密一次共享候选池，逐目标复核来源、期限、目标展示状态与状态机。来源／授权／候选变化会提交失效并清空候选关联；密钥或校准文件暂不可用时隐藏候选及确认能力，保留建议以待恢复，不把坏模板当作缺少竞争候选。关闭匹配时 GET 返回不可用；取消仍可执行。响应采用 private、no-store，并复用可选 X-Voiceprint-Owner 防止账号切换。

## 确认与拒绝

沿用 `/api/v1.0/meeting-records/{record_id}/speakers/{speaker_id}/identity-decision/`：

```json
{"action":"confirm_suggestion","suggestion_id":"建议 UUID","expected_revision":1}
```

拒绝使用 `action=reject_suggestion`，字段相同；两种操作都不能附带 user_id、label、contact_ref 或 score。既有通讯录选择、自定义标签和清除继续通过同一入口。

整批仍有排队／执行／可重试任务时，读响应 processing=true、can_confirm=false，直接确认或拒绝返回 409 `voiceprint_identity_request_processing`，保持待确认建议。这样不会因先推进一个目标的展示版本而取消同批其他仍在生产的查询；用户随时可取消整批，普通人工标记继续可用。

批次结束后，确认在用户／组织／授权／档案／记录／任务／建议／目标锁内重新检查当前编辑者的库边界、原请求者的权限、来源及完整候选证明、门限、目标展示状态和期限。只接受当前有效的 suggested；任何人工归属优先。成功后绑定成员、清除标签和联系人引用，记录真实操作人／时间，增加展示 revision，写关联建议版本的不可变审计，不新增登记样本或模板。

多个完成建议使用原来源 generation 与稳定候选上下文逐个确认：仅展示 revision 可变化，来源、原始区间、生命周期、候选授权及目标的人工归属仍不可变化。重复的已完成操作在当前 revision 下不增加审计；旧 revision 冲突。确认并发只会产生一次成功写入，其他请求返回冲突。

拒绝清除待确认候选、评分和差值，保留最终姓名并写拒绝审计／新展示版本，不训练模型或加入声纹库。拒绝／取消不需要恢复失效的 encoder 密钥或校准配置；已被撤销失效的建议不可重新决定。确认发现永久失效时，失效事务先提交再返回 409，避免异常回滚把候选关联留在待确认状态。

## 验证与剩余范围

最终 40 项 API 专项通过，包括批次幂等／原子预算、字段校验、个人／组织／媒体边界、旧建议与人工编辑保护、并发确认、多人依次确认、来源／生命周期／授权／期限变化、密钥及策略文件恢复、取消、审计和导出一致。收尾先复现两个失败：关闭匹配的 POST 仍读取校准配置，以及过期的 queued 任务未在 GET 中转为 expired；修复后 40 项复验通过。来源删除新增批次／任务／建议／审计级联回归，独立声纹库保留。

906 项相关后端整组回归通过，无跳过，耗时 368.71 秒；包括实际 Qwen 的内部提交及公开 API 提交 → 私有下载／原生解码／真实 encoder／模拟短 ASR → 持久结果 → API 读取两个入口。收尾新增的三个用例在 40 项专项中复验通过；另补验两名不同登记成员在同一批次内匹配不同来源说话人并依次确认，共验证 910 个不同后端用例、41 个不同 API 用例。多身份用例使用合成特征，不能当作真人准确率。日志在仓库外 `work/speaker-identification-api-regression-2026-10-10.log` 与 `work/speaker-identification-api-final-2026-10-10.log`。

`0208` 隔离库迁移和漂移检查通过。修改的 7 个独立 Python 文件 Ruff／格式通过；模型、既有记录 API 和 URL 文件与基线相比没有新增 lint 诊断。实际模型链路使用仓库外固定 Qwen encoder、原生 FFmpeg 和合成音频，质量 ASR 使用本地契约；没有调用收费 ASR、真人录音或生产部署。

跨端交互、长 ASR 前预检、AI 录音派生分人、可信通话采样、调度／恢复／清理及获授权真人评测仍待完成。生产门限没有校准，默认开关保持关闭，模型路线继续 Qwen 优先。
