# 导入预检的单声道媒体准备

日期：2026-10-10。分支：`feature/speaker-identity-voiceprint`。本阶段实现方案 8.1 所需的本地流式单声道派生基础，供收费 ASR 前的导入预检使用；尚未接入上传状态机、选择界面或云端 ASR。

## 实现边界

`voiceprint_import_media.prepare` 在现有受限 FFprobe 中核对唯一音轨、声道、时长及媒体／音轨起始时间。单声道复用原文件；2～8 声道使用新的固定用途 `voiceprint_import_worker` 流式输出 24 kHz、16 位单声道 WAV，不把长录音 PCM 带回 Django 内存。

完整转换不裁剪静音、不推断说话人、不修改原文件。保留原时钟，派生输入 `time_offset_ms=0`；再次探测派生输出，核对声道／采样率，时长差最多 1 ms。时间映射不明、多音轨、超过两小时及无效媒体仍拒绝。沿用当前私有来源 512 MiB 工程上限；这不是普通转写上传上限，也不代表已经支持所有两小时编码／码率组合。

调用方必须持有当前上传／来源授权及私有目录租约，后续仍须把 ASR 与查询绑定到同一不可变对象回执；此工具的 `MediaInfo`、文件路径和成功返回本身不是声纹授权或对象完整性凭证。

## 进程与文件生命周期

- Native FFmpeg 只接收固定参数和本地路径，协议／容器白名单、单线程、内存限制沿用既有解析策略。实际 native 环境只包含语言与必要 Windows 变量，没有应用密钥或对象存储凭据。
- 新导入用途 CPU／操作时限最多 180 秒。短片段 decoder 的 25 秒和 storage 的 90 秒上限不变。Windows Job 包含全部子孙进程；Linux 子进程增加内核父进程死亡信号、CPU／内存／文件大小限制，实际 Linux 部署仍需验证。
- 父进程以独占方式预留固定 `diarization.wav`，子进程复核文件身份后流式写入。发布前再次核对原来源快照和派生文件身份；被替换的文件既不采用，也不当作本任务的文件删除。
- 正常退出、调用方异常或权限撤销都会清理本任务的派生文件。现有来源租约也会独立删除 `diarization.wav`；源文件暂被 Windows 句柄占用时，仍先删除可释放的派生文件，不被同目录另一个文件阻挡。崩溃恢复沿用受限私有目录清理器。

## 验证

使用此前校验的本地 FFmpeg／FFprobe 9.0.2 和合成音频，未采集真人声音、调用模型／收费 ASR、写入云端对象或部署生产。

实际 16／24 kHz 立体声及 48 kHz 六声道转换通过；派生时长、规范 WAV 大小和原时间段的中部 PCM 校验通过。短片段 seek 与完整重采样存在滤波起始瞬态，因此不把所有边界 PCM 必须逐字节相同误当作时间映射条件。

两小时实际边界用例通过：8 kHz 立体声来源按固定 64 KiB 块生成；输出大小为 345,600,044 字节，时长 7,200,000 ms；完成后派生与测试来源均清理。不是仅检查伪造的时长元数据，也没有构造整段 PCM 数组。

媒体／来源下载／查询生产／租约五组组合回归 `100 passed, 1 skipped`。跳过项是既有实际 Qwen 编码器用例，本次没有配置外部模型运行环境；不能把跳过算作通过。新增文件身份替换拒绝后，单声道准备与租约专项 `29 passed`，其中准备器 14 项、租约 15 项，不累计重跑次数。Ruff 检查与格式检查通过。

## 继续接入的要求

后续上传任务应在 provider submission 前完成此预检，保存原始及派生输入的不可变回执和时间映射，并在提交前重新核对身份候选、授权与校准政策。预检不满足时须给用户普通 ASR／人工标记的明确继续选择，不能自动启动收费任务，也不能因为身份识别失败重跑已经完成的 ASR。

显式分人＋作用域／候选选择、三个上传入口的一致请求契约、预检状态与决定 API、派生对象上传／短期清理、转写和查询共同使用派生对象世代，以及转写后的独立身份请求仍待接入。本阶段不能据此宣称导入预检完整上线或全目标完成。Qwen 优先路线与完整验收范围不变。
