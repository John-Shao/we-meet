# Qwen 查询质检与有界媒体解码走查

日期：2026-10-10。范围：内部短片段查询生产基础，不是完整实名识别交付。

## 查询与登记分别验证

新增 `qwen-short-asr-query-v1`：会议查询没有随机朗读挑战，但仍须由 Qwen 短音频 ASR 提供最终句、词时间戳、明确说话人编号及至少 3 秒有效语音。登记继续使用 `qwen-short-asr-enrollment-v1`，必须验证当前挑战摘要与朗读内容。严格的字段集合和策略版本阻止两类证明互用。

查询只向 ASR 发送音频，不发送预期转写、联系人姓名或登记答案；输出只包含固定质检摘要，不保存 ASR 文本。沿用独立可取消子进程、有限响应、硬期限和实时授权检查。有效语音按词区间并集统计，标点不增加时长，多人、语音不足或缺失证据不能得到合格查询特征。

`voiceprint_query.extract_clip` 接收可信内部源区间及绑定来源／任务的授权回调。先验证源区间、期限和质检配置，再提取信号合格的固定 Qwen 特征，最后进行查询质检。特征组装前重新验证模型空间、音频摘要、信号质量契约、质检策略、有效时长和当前权限。向量仅在内存中返回，不写登记样本、模板或说话人归属，也不自动积累声纹。

## 本地媒体边界

`voiceprint_media` 只读取调用方专用临时目录中的本地普通文件，最多 512 MiB、2 小时、一个音频流。每次只解码 3～10 秒，统一输出 24 kHz 单声道 PCM16 WAV；源文件状态在探测和解码前后复核。延迟音轨映射未证明、多音频轨、无音频、无效时长或变更源文件均拒绝。不足 3 秒的结果不能补零；合法短结果按实际长度缩短结束时间，保持时间与音频一致。

通用解码器可规范化立体声，但这不代表导入分人预检允许多声道。后续生产者仍必须按原方案执行单声道分人支持范围和多人质量检查，不能用转换结果替代源媒体条件核验。

固定子进程模块只接受精确的探测／解码参数，不接受 URL、任意滤镜、命令或额外字段。原生工具仅启用 `file,pipe` 协议和固定容器白名单，拒绝 HLS／concat 播放列表。原生进程不继承应用凭证或 ASR 密钥，错误仅返回固定错误码，不输出原生诊断正文。

探测硬期限 10 秒、解码 20 秒，授权失效或超时回收进程。Windows 在执行前原子挂入 Job Object，限制每进程 512 MiB、整个进程树 768 MiB 和总 CPU 时间 25 秒，父进程退出或关闭 Job 会杀死后代。Linux 先设置父死亡信号与地址空间／CPU 上限，再以 `execve` 保持同一 PID 运行原生工具。本轮实际验证平台为 Windows／Python 3.13；Linux 部署验证继续待完成。`-max_alloc` 是单次分配限制，不能替代 OS 资源边界，见 [FFmpeg 官方文档](https://ffmpeg.org/ffmpeg.html)。

生产者必须独立核验记录可处理权限、媒体保留期限、源 generation／校验和，使用私有存储的固定对象键有界下载至专用临时目录，并保证清理。此模块的路径和 stat 校验不能替代上述授权或内容完整性检查；当前尚未接通对象下载或导入识别 API。

## 走查修复

| 问题 | 处理 |
|---|---|
| 登记随机朗读策略直接用于普通会议查询，或查询证明反向用于登记 | 分开策略与严格输出契约，登记仍验证挑战 |
| 错误模型、音频摘要或质检策略被组装成查询 | 组装前复核编码器及 ASR 结果，绑定同一音频和源区间 |
| 提取完成后来源授权已撤销，仍释放向量或开始收费质检 | 两次结果边界再次检查授权及期限，信号不合格不调用 ASR |
| 共用 ASR 请求逻辑后，结果解释阶段缺少到期复核 | 保留实际请求期限，解释及音频摘要绑定后再次验证；先复现两条失败，再修复登记与查询回归 |
| 原生解码无进程树生命周期或总量资源限制 | Windows 原子 Job、Linux 同 PID 父死亡保护、独立硬期限和输出上限 |
| Job 初始化异常／关闭管道异常泄露底层异常 | 固定错误码及关闭异常处理，失败仍回收资源 |
| 异常探测时长、半个 PCM 样本或短音频被补成完整片段 | 严格时长和整样本检查，不补零，按实际时长返回 |
| 未检查源变化或把多音轨／延迟音轨当作可信源时间 | 前后状态复核，未支持的时间映射明确拒绝 |

## 验证资源与限制

使用合成双频 WAV、16／24／48 kHz 和立体声输入，实际验证 WAV、FLAC、MP3、M4A、WebM 的探测与选段。频率切换验证选段位置，检查规范 WAV 长度和帧数；覆盖权限撤销、硬期限、慢授权回调期间独立计时器、输出上限、播放列表拒绝及进程回收。

Windows 验证使用 [FFmpeg 官方下载页](https://ffmpeg.org/download.html)列出的 Gyan 构建来源；仅在仓库外准备工具，不提交二进制或全局安装：

- `ffmpeg.exe`：`3256173f3f8bffd7df12227c68adf68025edb1832273a9530688a7bb1ed8edec`。
- `ffprobe.exe`：`f0d36ecbbdd3bcfac3efa078c96c7271c2e68b3810595552ac3b7f17e9a65c52`。

实际固定 Qwen encoder 的登记与查询传输已验证，查询没有新增样本或模板。ASR 使用本地模拟响应，不调用真实收费接口；合成声波并不证明语音或说话人身份效果。当前没有获授权真人样本，生产门限仍未校准，匹配默认关闭，继续 Qwen 优先，不触发 CAM++ 替换。

最终声纹相关 578 项后端回归全部通过，无跳过，包括 44 项查询、32 项媒体回归及实际固定 Qwen 的登记／查询链路。到期解释问题先由两条回归复现，修复后整组复验通过。修改的 11 个 Python 文件 Ruff 与格式检查通过；本阶段没有数据库迁移、Web／Android 变更或生产部署。
