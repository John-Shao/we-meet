# 第四十七批：Web/App 永久删除入口与发布预检

## 已实现

Web 和 Android 回收站只在服务端明确返回 `purge_available=true` 时展示新的永久删除入口。旧后端缺字段、开关关闭均不展示。已有删除请求仍能查看状态，不能恢复。

确认框展示记录标题和删除范围，必须勾选不可撤销提示后再确认。媒体、原文和纪要历史属于清理范围；外部文档、已转换任务和已交付副本保留。请求受理后转入状态页，展示排队/处理中、失败重试或完成；等待时间不承诺完成时间。关闭页面不会取消已受理的后台工作。

POST 不自动重放。网络响应不明时保留原版本供用户明确重试；服务端已受理后即使生命周期版本增加，失败重试仍使用凭据中的原始意图版本。400/401/403/404/409 阻止原界面再次提交，要求关闭刷新。状态读取失去权限时隐藏标题、状态及操作，不沿用旧结果。Android 读写响应同时校验当前账号，状态轮询只在前台运行，完成后停止轮询。

## 发布顺序

1. 构建本批提交的 backend/frontend 镜像，使用现有 `release-meet.sh --tag <本批前9位SHA> backend frontend` 发布；迁移 hook 需应用 `0186_record_purge`。summary/agents 没有本轮代码变更。
2. 确认 backend、celery-backend、celery-beat 全部成功更新，生产回收站返回 `purge_available=false`，现有上传、资料库和恢复路径正常。所有上传采用者必须已经具备第 46 批的重放保护，不能在混合旧实例时打开永久删除。
3. 另外核对私有媒体桶版本配置、删除/存在性查询权限及 worker 运行情况，再进入独立启用批次。启用后用新建且明确可销毁的专用样本验收；保留第 30/41/43/45 批的回归样本。

当前生产仍为此前用户确认的 Helm 380；本批状态是已实现并通过所列本地回归、等待发布和启用。永久删除不可通过关闭开关撤销：关闭只暂停新受理和后台清理，已受理记录继续不可恢复，上传重放保护继续生效。不能回滚到不含该保护的旧后端。

自动 30/90 天清理、管理员保留期、备份/第三方副本治理仍未实现。大文件恢复和长原文跨页按用户要求继续延后。
