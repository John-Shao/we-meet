## 实现与预算

- 正文命中分数先于标题命中，日期只在相关性相同后排序；关键词按抽取优先级加权。没有引入同义词表、查询模型、embedding 或向量库。
- 原生/上传有效原文、线上原文、最新人工纪要和最新 AI 纪要分别保留最多 64 个候选。数据库按记录计算 `ROW_NUMBER` 并先限制每记录最多 2 条，再截取全局候选池，防止单条近期长记录占满候选。
- 四个来源统一排序、同记录相同文本去重、每记录最终最多 2 条。先给每条记录一个证据位置，再补第二段；最终最多 **8 条、每条正文 800 字符**。标题、日期和提示模板另占空间。原策略各原文分支最多 4 条、各纪要分支最多 3 条，总共最多 14 条。
- 原文在 SQL 内截取最高优先级命中词附近的窗口，通常保留命中前 150 字符；只取窗口到 Python。纪要按可见正文重新评分并截窗，JSON 键/引用元数据命中本身不能作为证据。纪要仍取有限行完整 JSON，不声称候选总字节数有硬上限。
- 继续使用当前有效校对/转写代次、最新人工纪要替代 AI 和实时能力权限；响应/流式输出前的引用权限复核保持。窗口引用保留段落起始时钟，不伪造命中词时间戳。
- 英文常见问句词不再挤占三个关键词位置；大小写重复合并。显式引号短语仍保留，`IT` 等业务缩写保留。抽词是 GlobalAsk 多来源共享入口，既有搜索问答 API 一并回归。

## 限制与下一步

有限候选池仍会在大量同相关度记录中优先近期记录；它不能保证任意旧证据必达。每记录先取两条再去重，前两条重复时也不保证补到第三条。800 字符窗口不保证覆盖同一段中相距很远的多个事实；两段配额可能遗漏需更多片段的问题。词面加权不是语义相关性评分。

SQL 窗口排序与多次 `icontains` 的大库性能尚未实测，候选返回数有界不等于扫描成本有界。生产验收需记录数据库耗时与问答延迟；若不满足要求，应按测量优化索引/候选检索，而不是盲目扩大池。31题是已公开合成诊断集，不是盲测或线上准确率。

下一批先独立比较同义/跨语言扩展的收益与噪声，并增加不参与调参的题；再执行真实回答及引用复核。第 55 批专用记录永久删除最终复核保持独立待办。

本批只改 **backend**，无迁移、配置开关、frontend、Android、summary 或 agents 变更。提交与后端镜像准备后交由用户发布，生产验收仍待完成；达到整体质量门槛前不宣称全面推广通过。
