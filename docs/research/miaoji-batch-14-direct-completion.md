# 第十四批：直传完成登记与重试

生产验收暴露签名入口问题后，对签名后的完成链路继续检查，发现原文件名丢失和完成重试重复 PUT。以下修复经本地回归，尚未部署到生产。

- 完成登记保留客户端声明的原文件名和标题，剥离 Windows/Unix 路径，并要求文件扩展名与已验证的存储对象一致；原先会把随机存储键当成文件名。
- Web 在 PUT 成功后记住已传完状态。登记响应丢失或登记暂时失败时只重试登记，不重复上传文件，也不依赖已经过期的 PUT 签名。选择新文件仍清空凭证。
- 数据库登记失败时保留已上传对象供重试；在持有所有者行锁时重新检查活跃转写任务，防止两个先前签发的上传同时创建任务。
- 顺手修正直传测试文件既有的导入顺序和函数内导入告警。第十三批文档提前记述了该文件 Ruff 通过；实际在本批修正后通过。

## 验证与范围

- PostgreSQL：直传 17 项、普通上传/原文件读取/分片 53 项测试通过。
- Web 上传组件：14 项通过，包含登记失败重试只 PUT 一次；TypeScript 与变更文件 ESLint 通过。
- Ruff：API/测试文件通过；服务文件继续排除既有 3 处 PLR0913，其余通过。
- 不需要迁移；完成接口原本就要求 `name`，客户端请求结构不变。已登记历史记录不会自动改名。
- Web 的免重传状态限当前组件生命周期；刷新后的普通直传恢复、遗留孤立对象清理不在本批范围内。Android 本批未修改，不能将 Web 重试结果记为 Android 验收。
