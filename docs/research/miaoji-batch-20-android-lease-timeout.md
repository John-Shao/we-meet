# 第二十批：原生媒体准备超时与签名恢复

2026-09-20。Android `a06355a6`，Pixel 8 / Android 16。该批修复和可重复回归不替代生产签名自然到期验收，后者单独记录。

## 发现与修复

在真实 `MediaPlayer`、本地 HTTP 服务与有效 WAV 数据的仪器测试中，让旧链接返回 403：30 秒内观察到同一旧路径 11 次请求，但原生播放器仍报告 preparing，未调用错误回调。先前仅依靠 `failure()` 的恢复逻辑会一直显示加载，无法保证及时换用已刷新的签名。假引擎回归没有覆盖这个原生行为。

`UploadMediaPlayer` 增加基于 `SystemClock.elapsedRealtime()` 的 30 秒准备上限：

- 超时或失败时已有不同的新链接，释放旧引擎，以原位置与倍速自动重试一次。
- 同一轮失败准备最多自动重试一次；即使不断收到新链接，也不会无限加载。仍失败则显示可重试错误，由用户再次发起。
- 一旦准备成功，恢复正常播放状态并清除本轮重试计数。
- 已正常播放或暂停的引擎不会因后台签名刷新而重启；下一次播放/定位使用最新链接。

这个超时限制针对无法完成的网络准备，不是缩短生产对象存储签名 TTL。慢网络超过 30 秒仍未完成准备时也会走相同恢复/重试路径。

## 验证

13 项播放器仪器测试全部通过，0 失败、0 跳过：已有 9 项，加 4 项真实 HTTP/原生解码测试。新增覆盖暂停后刷新链接并恢复原位置及 1.5 倍速、精确定位、旧链接 403 后手动重试、已有新链接时自动恢复、持续失效链接的重试上限。暂停/恢复及定位在同一用例中验证。

HTTP 故障测试用 1.5 秒的可注入准备期限加快回归，生产默认仍为 30 秒。有效媒体通过 HTTP 200 或 206 返回并实际解码；不要求原生播放器每次初始打开都发 Range。生产对象存储 Range 的验证独立进行。

测试依赖 MockWebServer 只加入 `androidTestImplementation`。新增 `ProductionMediaRenewalAcceptanceTest` 是显式启用的生产验收入口：必须提供临时 loopback 描述服务，未配置时跳过，不自动访问生产。它使用真正过期和重新签发的 HTTPS URL，在原生播放器中验证恢复、1.5 倍速和 40 秒定位。签名只通过临时内存通道传递，不作为命令行参数或提交内容；此入口的生产执行结果尚待自然 TTL 到期。

## 发布

本批只修改 Android，无需重新部署后端/Web。Android 修复提交后按既有授权推送；仍需正式分发 App。生产签名有效期保持 3600 秒，没有改生产时钟、权限或签名配置。
