# 第三十九批：回收站后端与读取边界

本批交付 G7 的后端基础，双端入口进入下一批；尚不能记作用户可用的完整回收站。

- 迁移 `0185_record_lifecycle`：独立 `deleted_at` / `lifecycle_revision`，不修改原文 revision 或历史快照。
- 所有者可对已停止的上传/采集记录执行 `PATCH meeting-records/{id}/lifecycle/`，传 `target=trashed|active` 与 `expected_revision`。同一次丢响应重试不重复操作，旧回收/恢复请求不能覆盖后续反向操作。
- `GET meeting-records/trash/` 只列本人回收记录，每页 30 条，返回游标和必要元数据。普通列表、内容、历史、媒体与旧采集接口统一经过可见性过滤。
- 回收撤销原有记录分享，并关闭自动纪要、递增其配置版本；恢复不恢复分享、不启动新任务。原文/纪要快照保留，外部 Docs 副本及其独立权限不变。
- 活跃录音、转写、纪要、问答、翻译或外部投递阻止回收；不取消已开始的供应商/外部写入。未确认结果的投递先处理完再回收。
- 本批只做逻辑回收，不提供永久删除或自动过期清理；现有媒体保留策略仍生效，恢复不承诺恢复已经按该策略过期的音频。已发出的对象签名在自身有效期内仍可能可用，不承诺瞬间撤销存储 URL。

## 验证

124 个不同后端用例通过（最终生命周期 21，采集 26，以及记录/上传/自动纪要/分享 77），包括迁移一致性、恢复保留原文、分享不复活、自动纪要不重启、权限、分页、重试与正在处理的拒绝。新增服务/测试/API Ruff 和 diff 检查通过。旧采集测试中已经过时的 `speaker_id` 查询改为当前契约 `speaker`；不是生产行为变更。

## 发布约束

`MEETING_RECORD_TRASH_ENABLED` 默认 **false**。可见性过滤始终生效，关闭开关也不会重新暴露已回收记录。需要先完成迁移，再统一发布 backend、summary 及使用本仓库的 agents/worker，使所有记录读取者执行相同规则，然后才允许开启入口；不能在旧 worker 并存时提前启用。

本批无生产操作、无生产删除。永久清理仍待专门实现。第 37/38 批可以正常部署；回收站在整组服务更新及双端验收完成之前保持关闭。
