# 第二十三批：上传分人与服务端全局排序

对应[当前缺口盘点](miaoji-current-gaps-2026-09-20.md) G3 和 G4 的排序问题。实现及以下回归完成；多条件筛选与真实多人识别质量不在“完成”范围内。

## 变更

- Web/Android 上传高级设置增加“区分说话人”，默认关闭，明确区分声音不代表自动识别姓名。普通表单、单次直传的签名/登记、分片声明均传递 diarization。
- 提交后与原有 context/hotwords 一起锁定配置，未知结果重试沿用原导入和分人设置；新选文件可以重新配置。服务端已有配置保存与幂等冲突校验，本批补充三条路径及供应商参数回归。
- 列表支持 `ordering=created_at` / `ordering=-created_at`，服务端在权限过滤后按创建时间和 ID 稳定排序，再分页；非法排序字段返回 400。未传参数的旧客户端继续按原 origin_at/id 顺序，详情原文的分页不受影响。
- Web 移除当前页重排，按服务端顺序呈现；排序进入查询缓存键和分页状态键，切换方向同时重置进行中/归档两组游标，表格与卡片沿用同一顺序。

## 验证

- 后端真实本地 PostgreSQL：列表、普通上传、直传、分片共 80 项通过。新增覆盖 33 条跨页数据、相同创建时间、升降序、私有记录过滤、非法排序，以及分人 true/false 的持久化/冲突和供应商传参。Ruff 通过。
- Web：上传、列表、分片共 42 项通过；TypeScript、修改文件 ESLint、JSON 和语言结构检查通过。覆盖排序切换后弃用旧游标、三条上传路径分人设置透传。
- Android：上传相关 36 项单元/本地 HTTP 测试通过；仪器测试源码编译通过；Pixel 8 / Android 16 的 `RecordingImportPickerTest`、`RecordingImportChunkedTest` 共 3 项通过。验证真实原生表单中的开关、重试锁定和沿用设置、系统选择器及既有分片取消反馈；提交钩子设计 token 检查通过。
- 仪器测试使用受控 API/文件夹具，没有调用生产 ASR 或更改用户共享记录；不等于真实多人样本的分人准确率已验收。大文件恢复、长原文跨页生产验收仍按用户要求延后。
