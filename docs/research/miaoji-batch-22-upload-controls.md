# 第二十二批：只读状态保护与上传取消/进度

对应[当前缺口盘点](miaoji-current-gaps-2026-09-20.md) G1/G2。实现完成，尚未部署或进行生产 UI 验收。

## 变更

- Web 上传详情仅在 `upload.can_control` 明确为 true 时读取所有者转写控制接口；只读分享者和旧元数据不再推定具备该权限。
- Web 普通上传和单次直传使用可取消、可报告进度的 XHR 传输。普通上传仍经过统一鉴权、同登录刷新及响应校验；存储 PUT 只携带签名要求的请求头，不携带应用凭据。
- Android 普通上传通过取消 Retrofit 子任务关闭请求；存储 PUT 使用可取消的异步 OkHttp Call，取消等待响应中的连接。两条路径均报告传输进度，未知大小保留不定进度。
- 字节传输完成仍显示“正在确认导入结果”。停止客户端请求不能保证服务端撤回登记，因此显示结果可能已被接收，保留同一导入 key 和设置重试；迟到的成功结果按成功处理。
- Android 补齐直传票据回传和本地已上传标志；Web 延续原有票据机制。登记失败/停止后重试不再次 PUT 已确认存储成功的文件。Web 提交后锁定转写设置，避免同一导入被误换配置。
- 大文件分片路径及其既有恢复语义保留；没有恢复用户延后的大文件/长原文生产验收。

## 验证

- Web 5 个相关测试文件共 68 项通过：鉴权、XHR 进度/取消、上传 UI、工作区权限、既有分片恢复；TypeScript、修改文件 ESLint、JSON 和语言结构检查通过。
- Android 上传相关 34 项单元/本地 HTTP 测试通过，包含两项真实停滞连接取消测试，以及登记响应丢失后的免重传重试。编译通过；提交钩子设计 token 检查通过。
- 没有用上述测试替代生产 Web/物理 Android 设备验收。没有改后端接口、生产数据或对象存储策略。
