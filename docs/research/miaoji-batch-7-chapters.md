# 第七批：章节入口与可信空态

## 实现

- Web、Android 的记录详情增加独立“章节”页，复用既有纪要版本、分页和历史版本选择；不新增第二套章节存储。
- 章节注明来自对应 AI 纪要，保留生成时间、实时/速记/最终稿、历史版本及识别不完整提示。人工审阅稿仍在原审阅入口，不混称为 AI 章节。
- “尚无纪要”与“本版没有章节”分别呈现；读取失败保留错误状态。当前接口未提供章节缺失原因，因此不臆测“内容太短”，也不把 source_through_ms 当作媒体总时长。
- 原文入口仍受 read_transcript 限制，先读取并匹配不可变快照引用，再显示有媒体权限时的回听入口。章节页不加载生成、分享、通知、人工审阅、导出等子控件。
- Web 支持 `?tab=chapters`，并沿用录制开始时间与记录时钟的换算。无章节阅读权限时回到信息页。

## 验证

- Web：RecordSummaryPanel 21 项、MeetingRecordWorkspace 14 项通过；TypeScript 构建与改动文件 ESLint 通过。
- Android：Pixel 8 / Android 16 模拟器新增 3 项通过，覆盖章节独立入口与快照引用、仅纪要权限不读原文、无章节与无纪要空态。构建同时编译 Android 测试源集。
- 无后端或数据库变更。没有调用真实模型生成章节；没有宣称真实模型章节质量、生产视频定位或历史数据已验收。

本批测试检查章节分支与权限/引用接线。原媒体签名、跨页定位和播放器恢复的验证见前序批次。
