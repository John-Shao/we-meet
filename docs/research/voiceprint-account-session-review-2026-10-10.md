# 人工身份标记的账号切换走查

日期：2026-10-10。范围为记录级识别 API、建议决定事务、身份队列及 Web 人工标记的登录会话与缓存边界。本轮修复人工标记的账号切换缺口，不代表跨端自动识别交互或真人效果验收完成。

## 已复现的问题

`MeetingRecordViewSet.speaker_identity_decision` 原来仅对 confirm_suggestion／reject_suggestion 校验可选 `X-Voiceprint-Owner`，通讯录读取以及 select_contact／set_label／clear 忽略该标识。前端人工标记 hook 也没有发送标识或绑定打开面板时的登录会话。切换账号后仍存活的面板，可能用新账号的凭证读取通讯录或提交旧操作；即使新账号也有编辑权限，该操作仍不属于其打开的面板。

修复前新增的 4 个后端回归用例均失败：通讯录读取和三种人工标记在 owner 不匹配时全部返回 200，set_label／select_contact 实际写入了身份。前端新增的会话测试中 3 个失败，旧登录可以发起操作，读写请求均未发送预期账号标识。

## 修复

- 通讯录读取和全部 identity-decision 操作共用账号标识检查，在读取记录、通讯录或执行事务前拒绝不匹配的标识，返回 401 和 private、no-store。该标识保持可选，已有客户端的实际权限校验继续由服务端完成；Web 人工标记读写始终发送预期 viewer ID。
- Web hook 固定 viewer、record 与打开时的登录会话，发请求前及接收响应后复核会话。同登录的 token 刷新可以继续使用；切换账号／退出／重新登录后，旧操作不能重新发起，迟到结果不能进入旧 viewer 的缓存。
- 通讯录 query key 包含会话边界，只保存会话 ID，不包含 access token 或 refresh token。会话变化后的旧操作不再触发旧 viewer 的工作区重新读取。
- 已打开的人工标记面板监听 storage 变化并以 250 毫秒间隔复核会话；变化后关闭面板，取消目录读取并按 gcTime=0 清理其缓存，移除已显示的联系人列表。监听和定时器随面板卸载清理。

服务端在账号切换前已经接受的请求不因前端关闭面板而回滚；返回结果不会再应用于新会话。最终身份、revision、审计及当前权限仍在既有事务中校验。
