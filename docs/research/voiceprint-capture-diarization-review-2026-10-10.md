# AI 录音分人派生版本与代码走查

日期：2026-10-10（Asia/Shanghai）。范围：录音结束后的独立分人任务、原文时间对齐、派生版本原子发布，以及原文读取、人工修订、导出、纪要和删除流程的兼容性。此阶段提供后端基础，尚未接入实际媒体准备、收费 Qwen 分人 worker 或两端操作入口。

## 已完成的基础

新增 `0211_capture_diarization_generations` 迁移及独立 `CaptureDiarizationJob`。显式命令固定当前录音、成功 ASR、当前派生版本、原文与人工修订摘要、音频分片、对象键、保留策略、模型配置和请求 key。它不重试原 ASR，也不覆盖原始转写、说话人标签或历史段落 ID。相同命令返回原任务，来源变化要求重新提交。

新增分人时间轴与原文对齐。单一明确说话人可以覆盖完整原句；跨说话人的原句仅在原有逐词时间、文本摘要、UTF-16 偏移和字符边界均有效时拆分。没有可信逐词时间、经过人工改写、说话人重叠或时间缺失时保留歧义，不能按多数时长猜身份。分片缺口保持原时间轴，即使 provider 在缺口上报告说话人也保留未知；同一说话人的两个词不能跨缺口合并。Provider 返回的新正文不替换原文。

派生段落保留原 ASR、父段落、时间、字符区间及歧义原因。人工改写保留完整原句，引用既有修订对象并继承修订编号；下一次人工编辑继续追加审计，不伪造先前编辑记录。重新分人保留父链与人工修订历史，新一代说话人身份需要再次确认，不自动复制旧姓名或登记声纹。

发布事务一次写入完整派生段落、校验回执、切换当前版本并推进记录 revision。写入中途失败全部回滚；同结果重放不再次切换版本或推进 revision。读者、导出和新纪要共用当前版本投影，成功 ASR 重试替换该投影，排队或不完整重试保留既有版本。

原文接口可使用 `diarization_job_id` 固定已成功发布的历史派生版本；既有 `transcription_job_id` 固定原 ASR 正文。如果两个 ID 同时出现，必须属于同一个 ASR 来源。历史父段落仍可读取和引用，但不可通过当前编辑接口修改。响应新增 `parent_original_id`、`diarization_job_id` 和 `speaker_mapping`。录音实时预览仅返回原 ASR 段落。

独立开关 `MEETING_CAPTURE_DIARIZATION_ENABLED` 默认关闭。任务期限不超过 24 小时，临时音频还受既有到期策略约束；本阶段没有延长音频保留期限。来源进入内存前在 PostgreSQL 检查最多 20,000 段、原文和有效修订各最多 4,000,000 UTF-8 字节、逐词 JSON 总量最多 32 MiB，分片读取最多 4,321 条以检测越界。发布使用有界批量写入，避免每段完整模型验证造成大量查询。这些是拒绝上限，不是生产容量测试结果。

## 走查发现与修复

| 问题 | 修复与验证 |
|---|---|
| `select_for_update` 覆盖 nullable 请求人 join，在实际 PostgreSQL 上失败 | 仅锁任务表自身，记录保持先锁；实际数据库任务领取、发布和并发重放通过 |
| 等待记录锁前已读取 CaptureSession，可能继续使用过期指针或 revision | 锁后重新读取 CaptureSession；真实并发锁等待测试核对新 revision |
| 发布没有先锁请求账号，账号停用可与写入竞争；请求人为空会抛属性异常 | 请求账号 → 记录 → 任务的锁顺序；停用竞争拒绝发布，空请求人领取失败，不开始处理 |
| 持久化正文、人工改写和逐词 JSON 在加载前缺少总量门禁 | PostgreSQL 按实际 UTF-8 字节及 JSON 大小检查；三种超限均拒绝创建任务 |
| 全部派生段落消失时，纪要可能接受空结果；回执未覆盖全部来源标识 | 根据当前成功发布指针核验数量及摘要，即使结果为空也必须检查；原文、来源轨道篡改与全部缺失均拒绝纪要和再次分人 |
| 人工修订继承仅检查同记录，可能引用另一个父段落的修订 | 必须属于直接父段落或父段落已有继承链，且保持原句；错误继承拒绝，合法多代继承通过 |
| 常规 source revision 更新保留实时／快速纪要，但分人替换不是追加原文 | 取消旧来源的全部进行中纪要任务；既有已发布纪要及历史引用保留 |
| 删除流程没有识别进行中的分人任务 | 有效排队／运行任务阻止删除，过期任务不永久阻塞；整条历史派生与修订链可随记录级联删除 |
| 发布中途异常可能留下部分段落、说话人或新指针 | 故障注入先真实写入一条派生段落再抛异常，验证事务完整回滚 |

## 验证证据

新增 34 项实际 PostgreSQL 服务用例和 29 项时间对齐用例。只有本地合成 WAV、模拟 provider 时间与既有内部 ASR 测试契约，没有使用真人录音、真实麦克风、收费 ASR、云端存储或生产部署。

- 第一组 126 项通过：派生发布、时间对齐、原 ASR、直传 ASR、录音实时转写、纪要、人工修订及逐词对齐。
- 第二组 227 项通过：扩展后的派生测试、有效原文、导出、纪要边界和草稿、搜索、人工身份决定、上传及上传纪要来源、原文编辑接口。
- 第三组 203 项通过：发布完整性与继承、删除／清空、临时音频清理和保留策略、说话人统计、录音纪要、草稿及翻译归档。
- 收尾 113 项通过：全部 63 项新增用例、账号停用竞争与空请求人，以及原 ASR、直传 ASR、实时转写和逐词对齐回归。

各组有重复用例，不能相加作为不同用例数量。日志分别保存在工作区 `work/capture-diarization-core-regression-2026-10-10.log`、`capture-diarization-reader-regression-2026-10-10.log`、`capture-diarization-final-regression-2026-10-10.log`、`capture-diarization-auth-regression-2026-10-10.log`，不提交测试数据。

修改服务、接口、设置、迁移和测试通过 Ruff；新增独立文件通过格式检查。`models.py` 保留已有格式，只格式化新增类；与 HEAD 基线相比仍是相同的 9 项既有 lint 诊断，没有新增诊断。迁移漂移检查通过，迁移只在隔离验证数据库应用，不代表生产已迁移。

## 后续完整接入

本阶段没有对外发起分人任务的 API、分人 Celery worker、媒体下载／版本证明、保留缺口的单声道媒体准备、收费任务的一次提交及不确定结果恢复，也没有 Web／Android 的分人操作及派生版本分页绑定。`CaptureTranscriptionPanel` 现有 ASR 固定分页仍读取原 ASR，不能将它描述为已经展示了派生版本。

身份匹配的可信来源目前仍限定导入文件，尚未把录音派生版本接入声纹查询。后续必须固定分人和匹配共同使用的私有媒体对象及内容／版本证明，不能直接放宽上传来源的对象键门禁。操作入口、候选选择、身份队列、审计和临时媒体清理需要一起完成；逐词时间也必须来自可信 provider 管线，而不是客户端声明。

可信通话采样、暂停与共享设备排除、实际设备分组、部署调度、版本化清理与可信恢复，以及获授权真人和生产容量验收仍属于完整目标。Qwen 优先；本轮没有真人评测证据，未触发 CAM++ 替代部署。
