# 第 61 批：短语检索与回答证据约束

日期：2026-09-21。基线：we-meet `280dfa78d`；生产 backend `8452f82de` / Helm 387。仅 backend 运行代码变更，无迁移、Web 或 Android 改动。

## 具体问题与改动

第 60 批实际问题“‘两者之间最大的区别’是什么？”仍带入旧 TranscriptChunk 噪声；自然问法回答额外解释“严格控制成本”，引用没有直接依据。

- 成对引号中的 2–80 字短语保持完整，支持英文双/单引号与中文 `“”`、`「」`、`『』`，最多三条；多个短语按 OR 查找。单词内撇号不视为短语。
- 统一记录与旧纪要：完整短语优先，同时保留引号外的查询词，总数最多三个。不会再把短语本身拆成零散词；这不是完整查询语言，也不是所有引用都必须逐字包含短语的保证。
- 旧 TranscriptChunk：在可见房间、非统一记录、日期边界内，正文或标题须命中至少一个完整短语后才进入 BM25/向量排序。未带有效引号的查询保留原向量召回。标题约束只控制候选，不承诺旧标题命中必然产生引用。
- 回答规则补充逐事实证据支持、观点归属、部分未知、冲突不自动选最新版，以及资料中的指令仅作为数据。共享提示词影响普通与流式 GlobalAsk，包括其他 scope；检索词变更仅用于会议来源，IM/日历保持原抽词。

首次严格限制所有来源只搜短语导致 `corrected_obsolete`、`reviewed_obsolete` 退化。最终保留引号外的“批准”等查询词，使“300万元批准了吗”仍能取得当前30万元；从未恢复返回旧300万元。没有更改冻结题目或 gold 来让比较通过。

## 验证与结果

- 116 项测试通过（16 条既有警告），包括 8 项新短语检查：拆词噪声、旧向量噪声、大小写/纪要、标题、私有记录、多个短语和单词撇号；同时覆盖有效修订、权限与 API。
- 原 31 题对比第 59 批逐题无退化：有证据题仍 **21/25** 完整；应为空 **5/5**。四道同义/跨语言缺口不变，尚未达到原建议至少22/25门槛。
- 混合 12 题逐题无退化：完整证据 **9/9**、应为空 **3/3**。比较器不评判回答语义。
