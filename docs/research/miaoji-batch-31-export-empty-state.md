# 第三十一批：导出历史空态遵循实际权限

第 30 批生产 App 验收发现：只读账号的信息页没有个人导出回执，却仍提示“可在纪要版本中创建”。用户实际没有导出权限，提示与操作能力不符。

## 修正

- Web / Android 将“尚未导出”与创建提示分开；只在 document-exports 响应明确 `available=true` 时展示创建提示。
- 只读用户、导出功能关闭、旧响应缺少能力字段时，保留中性空态，不引导无法执行的操作。
- 创建权限关闭后仍可读取已有回执和允许打开的独立文档，原分页、记录权限及 Docs 权限不变。没有新增导出或后台写入。
- Web 五种语言、Android 中英文同步更新；复用现有能力契约，无后端改动和数据库迁移。

## 验证和发布

- Web 12 项组件回归通过，覆盖能力 true/false/缺失、旧回执可读、账号切换、撤权和前后分页；TypeScript、ESLint 通过。
- Android 11 项 Pixel 8 / Android 16 仪器测试通过，包括同一页面恢复时导出能力 false → true → false；设计 token 检查通过。
- 5 种 Web 语言键集合和 2 份 Android XML 校验通过。新版 debug APK 已重新安装到 Pixel 8。
- Android 提交 `e17dda59` 已推送；Web 需发布 frontend，新版 Android 正式分发另行完成。本批没有再次进行生产身份写入，生产 UI 提示复测待客户端更新。

第 30 批的生产流程和清理证据保持有效；Web 实际页面、物理设备、正式分发及明确延后的大文件/长原文仍不可标记已验收。下一项产品开发优先 G4 服务端时间范围/所有者组合筛选，沿用已有来源和创建时间排序，双端重置分页，避免只筛当前页。
