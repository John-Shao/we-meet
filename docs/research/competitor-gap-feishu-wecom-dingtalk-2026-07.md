# we-meet vs 飞书 / 企业微信 / 钉钉 — 产品功能与体验差距调研报告

> - 基准快照:飞书 V7.65、企业微信 5.0.9(2026-06-23)、钉钉 8.3.40(2026-06-29),调研时间 2026-07,建议有效期半年(竞品 AI 迭代极快)。
> - 方法:三轮 deep-research 工作流(fan-out 搜索 → 抓取来源 → 每条论断 3 票对抗核验)+ 我方代码级功能盘点(非自述)。
> - 我方基线:主仓 Django 后端 + React Web 前端、Android 原生、Electron 桌面、自研 jusi-light-im、LiveKit 会议。
> - 引用规则:标注「N-0」为核验票数;「未核验」条目不得直接写入对外材料;厂商自报数字(MAU/成熟度评级/识别准确率)均无第三方审计。

## 一、结论速览

1. **基础协作层(IM/会议/日历/通讯录/审批)差距比预想小得多**——消息级能力(引用/合并转发/撤回/表情回应/已读/@所有人/语音)、大厅候场、会中 AI、基础审批流均已实现,与竞品是「打磨差距」而非「功能代差」。
2. **真正的代差在「AI 全域打通层」**,且三家 2025-2026 全部押注于此:
   - 飞书:aily 以 Agent 形态常驻联系人列表(有记忆、主动工作,专业版可自主跨模块读群聊/会议/文档);「知识问答」零搭建全域 RAG(V7.46)。
   - 企微 5.0:智能搜索(自然语言跨聊天/文档/会议/邮件检索)、智能总结(跨场景项目摘要)、智能机器人(SOP 问答 + 经 API 触发 OA)。
   - 钉钉:AI 助理平台级化(智能沟通/协同/管理,官方文档 5-0 核验),2026 官网叙事已全面 Agent 化(悟空独立 APP、Agent OS),IM 侧消息总结/群问答机器人/工作概览(3-0)。
   - 我们的 AI 是「会议域内很强,域外为零」。
3. **我们的底牌**:跨会议 RAG(embeddings + hybrid retrieval + TranscriptChunk)已在生产。把这套栈从会议转写扩到 IM 消息 + 日历,就是竞品 AI 基线的七成——补齐成本最低、留存收益最高。
4. **会议 AI 纪要是三家共同的高地,也是我们离基线最近的模块**:飞书 AI Notes(自评 M4:三板块 + 可编辑 + 机器人推送三路由)、钉钉 AI听记(8.1.5 图文纪要:章节内插表格/时间轴/流程图/思维导图、72 语言翻译、待办一键同步,3-0 核验)。我方摘要 + ActionItem + 推 IM + 推 Doc 雏形全在,差的是结构化、可编辑、推送路由与触达打磨。
5. **三块硬空白应明确战略定性**:文档/多维表格(放弃自研,深化 La Suite Docs 集成)、企业邮箱(放弃)、微信客户生态互通(结构性不可复制,放弃 SCRM 赛道)。
6. **最影响移动端留存的不是任何 AI 功能,是离线推送缺失**——IM 收不到通知在中国 SMB 场景是卸载级硬伤(个推保活路径已定,须排期落地)。

### 2.4 中国 SMB 市场结构性事实(艾瑞报告,3-0)

1. SMB 采购渐进式:首购只买核心需求(IM/会议/日历),随发展逐步增购。
2. 免费/基础功能是获客主通道:国内办公软件付费率 <15%(欧美 >70%);钉钉付费企业 19 万 vs 2600 万组织,转化率 <1%。
3. 飞书主攻头部大客户;钉钉 2024 年起考核转 ARR、大客户占比升(未核验单源)——**SMB 中低端存在「轻量 + AI」差异化空间**。

## 三、我方功能底稿(代码级盘点,2026-07)

> 状态三档:已实现 / 禁用(代码在但生产关闭)/ 仅设计(文档或字段占位)。证据路径见盘点原文,此处摘要。

- **视频会议**:建会/大厅候场审批/参会者管理(静音/踢人/改名/举手/权限)/屏共/虚拟背景/评分/SIP 电话接入——已实现。录制——**禁用**(`RECORDING_ENABLE=False`,策略性)。
- **会议 AI**:实时字幕+翻译、转写入库、摘要+ActionItem 抽取、纪要推 IM 群(`_push_summary_to_im`)、纪要落 La Suite Docs(`_push_summary_to_doc`)、Room AI 会中问答侧边栏、跨会议 RAG 个人 AI(embeddings/hybrid_retrieval/TranscriptChunk)——已实现。rerank/聚类/自定义提示词——搁置。
- **IM(对接 jusi-light-im)**:单聊/群聊/建群拉人退群、文本/图片/文件/语音、引用回复、合并转发、撤回墓碑、表情回应、已读回执、@所有人、多选删除、未读 badge——已实现。注意:表情回应与撤回为**客户端控制消息约定**(非服务端原生)。消息全文搜索——**缺失**(待 jusi 服务端端点)。
- **日历**:事件/RSVP/内外部与会人/可见性/关联房间一键入会/提醒经 IM 推送——已实现。重复日程(RRULE)——**仅字段占位**。
- **通讯录/组织架构**:组织/部门树/成员角色/邀请开通注销/审计——已实现。
- **全局搜索**:Ctrl+K 面板,搜人(服务端)+ 会议(客户端过滤)——已实现;消息标签留白待服务端。
- **审批**:模板/提交/审批/拒绝/撤回/催办/委托代批 + 独立导航入口——已实现(无可视化流程编辑器/条件分支)。
- **管理端**:自研 Web 管理台(仪表盘/成员/组织/审计/邀请)+ Django Admin 定制——已实现(「M端过渡」既定策略)。
- **认证**:OIDC/Keycloak、短信 OTP、扫码登录——已实现。
- **推送**:会中 toast/IM 系统消息(在线态)——已实现;**离线推送为零**(FCM 搁置、HMS 不接,个推保活路径已定未做)。
- **Android**:5 tab(消息/日历/会议/通讯录/我的),会议室全功能(含画中画/字幕/会中 AI)、IM 全功能、日历、审批、AI 中枢、OTP+扫码登录——已实现。
- **完全无代码痕迹**:企业邮箱、网盘、in-app 文档协同/多维表格/知识库、表单问卷、打卡考勤、报销人事等 OA 细分、开放平台应用市场(仅 OAuth Application 基础)、机器人开放 API。

## 五、优先级建议(中国 SMB 获客/留存视角)

**P0(直接决定留存)**
1. **移动端离线推送**(个推保活路径)——收不到消息的 IM 没有留存可言,优先级高于一切 AI 功能。
2. **消息全文搜索**——推动 jusi-light-im 服务端搜索端点,补全局搜索「消息」标签;也是后续 AI 化的数据前提。
3. **纪要闭环打磨**——雏形全在(`meeting_summary.py` 推 IM/推 Doc),补:三板块结构化 + 智能章节、纪要可编辑、推送路由(会议群/1对1 私聊)、行动项同步待办。对标飞书 M4 与钉钉图文纪要。→ 详细设计见 `docs/features/meeting_summary_closure.md`。

**P1(构建差异化的 AI 牌)**
4. **全局搜索 AI 化**:在消息搜索之上,把 hybrid retrieval 栈扩到 IM 消息 + 日历实体,「自然语言提问 → 带引用作答」。三家该能力多有付费/灰度门槛(飞书 aily 专业版、Lark AI Notes 仅 Pro+、钉钉 AI 免费边界未决)——**免费开放即获客差异点**(强度取决于竞品免费版实际权益,见缺口 6.2)。
5. **个人 AI 常驻 IM 入口**:PersonalAIDrawer 升级为 IM 联系人形态 Agent(对标 aily/悟空的形态,不对标其自主性),RAG 底座现成。
6. 重复日程 RRULE 展开 + 忙闲视图。

**P2(打磨)**:IM Pin/稍后处理、表情回应/撤回迁服务端原生、残留 confirm 样式化、入会动线实测对齐。

**战略性放弃/延后**:文档与多维表格自研、企业邮箱、微信 SCRM、OA 细分、开放平台市场。

## 六、证据局限与待办问题
