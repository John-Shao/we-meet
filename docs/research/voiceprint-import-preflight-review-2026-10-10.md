# 导入身份预检：后端接入与走查

日期：2026-10-10。分支：`feature/speaker-identity-voiceprint`。

本阶段将[单声道媒体准备](voiceprint-import-media-preparation-2026-10-10.md)接入上传任务，在收费文件 ASR 前执行身份导入预检，并补充派生对象的持久清理记录。Qwen 优先路线不变；本阶段没有评估真人识别准确率，也没有启用 CAM++。

## 请求与状态

普通上传、直接上传的签名／完成请求及断点续传 begin 均可携带以下可选声明：

```json
{
  "diarization": true,
  "identity": {
    "organization_id": null,
    "candidate_user_ids": ["当前用户的 UUID"]
  }
}
```

携带身份声明时必须提供与当前登录用户一致的 `X-Voiceprint-Owner`。声明字段、作用域及候选必须明确；个人库仅允许当前本人，组织库要求当前组织许可及有效真人成员，候选去重后固定排序，数量受校准政策限制。不扩充为整本通讯录，不以外部联系人姓名或共享设备账户建立匹配候选。

新请求检查识别开关、校准政策和本地 FFmpeg／FFprobe 配置。配置项 `MEETING_VOICEPRINT_MEDIA_CONFIG_FILE` 指向仅包含绝对 `ffmpeg`、`ffprobe` 路径的 JSON 文件。已上传字节的直接完成请求核对声明形状和当前账户，后续任务仍重新检查全部识别许可；不会因完成请求采用了字节而取得识别权限。上传任务采用后，身份声明保存在私有配置中，后续重试不能变更该声明。

原有 ASR 状态值保持兼容。身份预检使用独立的 `identity_state`：

1. 上传任务 `queued/pending`，领取十分钟预检租约后进入 `queued/preflighting`。
2. 预检完成，保存媒体／候选／政策证明，释放租约，进入 `queued/ready`。此配送不提交 ASR。
3. 后续配送读取固定对象版本，核对对象元数据，并在签名后再次复核账户、候选、源配置、政策、期限及租约，再提交一次 ASR。
4. 提交前失败进入 `failed/awaiting_choice`，提供可解释且经过白名单限制的原因；自动配送和普通失败重试均不能启动收费任务。

只有上传者可以调用 `POST /api/v1.0/recording-uploads/{record_id}/identity-preflight/`，请求必须绑定当前账户，并携带严格整数 `expected_attempt` 和 `action`：

- `retry_identity`：重新检查当前配置，下一次尝试重新预检；保留原始身份声明。
- `continue_without_identity`：明确关闭本次身份识别及分人，复用原上传字节进行普通 ASR。声明保留用于追溯，不把普通转写伪装成已分人来源。

同一决定的重放返回同一尝试，不增加收费任务；相反或过期决定返回冲突。已经发起的 ASR POST 若结果不确定，仍为既有 `submission_unknown`，不会被归入可自动重试的预检失败。

## 不可变输入与清理

单声道复用原始固定对象版本；2～8 声道生成完整 24 kHz、16 位单声道 WAV，保留原时钟、零偏移及最多 1 ms 的时长差。身份来源仍沿用 512 MiB、两小时和唯一音轨限制，不能据此宣称所有两小时编码都可识别。普通 ASR 的上传限制不由这些身份限制替代。

派生 PUT 前先提交 `RecordingImportInput` 预留记录，再在可终止子进程中上传固定 UUID 对象键。显式凭据通过有界输入传入，不使用 SDK 环境凭据发现或代理；输出核对固定对象版本、大小、摘要元数据和本地文件快照。没有固定版本或结果不确定时，不采用远端对象，保留清理记录。

ASR URL 和发布后的身份查询绑定同一个派生回执及 `VersionId`，URL 期限不超过该输入期限。播放继续绑定原始对象版本。派生引用纳入来源 generation 证明；错误、过期、已删除或来自其他尝试的派生引用直接拒绝，不能回退为当前可变对象键。

派生输入的可访问期限不超过对应上传尝试的 24 小时执行期限，不延长原有来源保留；物理清理仍须等待写入窗口并由部署调度完成。前一次已提交或结果不确定的收费 ASR 输入保留到原期限，避免重试时使仍在读取的任务失去输入。

记录通过 `SET_NULL` 在上传任务硬删除后继续存在。命令 `purge_recording_import_inputs --limit 20` 有界清理过期或来源已删除的输入，不依赖识别开关。仍可能写入的 worker 结束窗口和失败退避均须满足后才能清理；旧租约失败只使其自身预留失效。

清理仅删除确切 UUID 键的版本及删除标记，核对二次版本列表后才登记物理删除。存储错误、缺少列表完成标志或截断列表保留待清理状态，不能把删除标记或不完整响应当作清除证明。部署调度、实际桶策略及备份传播仍待验证。

## 本轮发现并修复的问题

- 新决定 API 引用了不存在的 serializer 模块，导致 Django URL 检查失败；改用现有严格 serializer。
- 存储 HEAD／签名期间可能撤权或更换租约；在提交前增加最后复核，旧 worker 不能覆盖新租约。
- 新预留模型的空回执、空删除时间和空上传外键未声明 `blank=True`，被现有 `BaseModel.full_clean` 拒绝；修正模型及未发布迁移。
- 清理空响应曾可能被误认为空版本列表；现在要求明确的列表完成标志及有效条目。
- 来源删除的清理记录不应等到原执行期限才进入扫描；预留时就建立清理扫描时间，具体删除仍受写入窗口及退避限制。
- 派生输入校验补充规范 WAV 大小、摘要、零偏移、同尝试及期限约束；缺失／清空派生指针不能退回原文件，签名期限取输入与上传任务的较早期限。
- 候选预算须遵守当前校准政策；普通 ASR URL 的既有有效期保持不变。

## 验证与剩余工作

测试使用隔离 PostgreSQL／Redis、合成音频、本地 HTTP 对象服务及此前核验的 FFmpeg／FFprobe 9.0.2。真实子进程验证 PUT／固定版本 HEAD、无版本拒绝、撤权及超时终止；单声道和立体声完整路径验证真实下载、媒体准备、上传、模拟 ASR 发布及同版本身份来源读取。未采集真人声音，未调用收费 ASR，未写云端对象或部署生产。

十四组组合回归 `357 passed, 3 skipped`；最终再补三项派生指针丢失拒绝用例，预检／派生／native 全链路／来源四组 `132 passed`。去重共 360 项通过，其中新增 89 项，不累计专项重跑次数。原始上传、直接上传、断点续传、来源、媒体准备／解码／下载／租约、查询和独立身份队列均纳入此次回归。三项跳过是既有实际 Qwen 编码器用例，本轮未配置外部模型运行环境，不能计为通过。Ruff 检查和格式检查通过，`git diff --check` 通过。Django 检查仅报告开发验证数据库尚未应用 `0209`；迁移一致性检查无新增变更，隔离测试已执行该迁移。既有 Django 弃用及本地 static 目录提示不属于新功能验证结果。

本阶段完成后端预检与决定契约；Web／Android 的导入前显式选择、失败决定界面、跨端能力展示，以及 ASR 发布后的独立身份请求调度仍待接入。通话可信采样、AI 录音后分人、部署／清理调度／可信恢复、真人效果及生产验收继续属于完整开发范围。现有原始录音清理策略也须另行核验版本化桶支持，派生清理通过不代表原始对象或备份已物理清除。
