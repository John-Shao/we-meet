## 实际结果

- **生产排序 API 通过**：所有者已有 21 条记录，创建时间正/倒序各返回同一组记录，按 `(created_at, id)` 单调且互为逆序；非法字段返回 400。生产只有一页，不能替代跨页验收；本地 33 条跨页回归见第二十三批。
- **权限基线通过**：所有者测试视频详情 `upload.can_control=true`；第二账号读取未分享测试视频及所有者转写状态均为 404。本批没有增删分享授权，不替代第十九批已完成的分享/撤权矩阵，也不证明 Web UI 的条件挂载已实测。
- **App 普通上传进度通过**：系统选择器选取视频，展开高级设置，“区分说话人”默认关闭，开启后提交。观察到 12% 以及 100% 上传进度、等待导入结果的独立提示；提交后分人选项锁定。
- **等待结果阶段停止/重试通过**：点击停止后，App 提示“请求已停止，服务端可能已收到文件”，保留原文件和已开启、锁定的分人设置。再次提交后进入新记录，生产转写状态最终 `succeeded`，`attempt=1`。列表由 21 条变为 22 条，期间仅新增测试记录 `25b88336-e890-4a04-be48-cbd64b09fe0f`（14:23:42），未出现重复记录。此处证明等待响应阶段的真实停止恢复；没有赶在字节传输完成前点击停止，不能标记传输中停止已生产验收。
- **分人链路通过，质量未结论**：新记录 speaker API 返回 `identity_type=diarized`、`Speaker 0`、识别区间 43,280 ms；App 原文与发言人页显示同一标签、0:43 和识别发言时长占比 100%。这证明开关至生产处理和展示已贯通，不代表多人区分准确、全部语音覆盖或与妙记的质量一致。

当前生产普通上传上限 100 MiB；Android 对本次 19.86 MB 文件走普通 multipart POST。不能将本次结果算作 App 单次对象存储直传或大文件分片验收。

## 发现并修复的 UX 问题

高级设置展开时，进度及停止按钮原先位于同一滚动内容底部。实际需滚动两次才能完整看到停止按钮，等待导入时仍可能看起来没有响应。

Android `a5edbcd9` 将配置内容放入独立滚动区，进度、等待确认和停止后的反馈留在其下方；停止按钮放入弹窗固定操作区。保持取消语义、幂等 key 与配置锁定不变。

验证：Pixel 8 / Android 16 的 `RecordingImportPickerTest`、`RecordingImportChunkedTest` 共 3 项通过。增强回归在高级设置保持展开时断言进度及停止按钮可见，并实际点击停止。该分片测试为受控夹具，不是用户延后的生产大文件验收。提交检查通过；修复后的 debug APK 已重新安装到模拟器，正式分发仍待完成。
