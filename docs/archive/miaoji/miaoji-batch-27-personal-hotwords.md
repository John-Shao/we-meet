# 第二十七批：个人热词复用

本批补齐 G5 的个人词表复用：Web、Android 的文件上传高级设置可管理自己的词表，并明确合并到本次上传。生产部署与真实识别质量验收尚未执行。

## 范围与行为

- 每个账号一份私有词表，服务端持久化，重新打开或明确重新载入时读取最新版本。每行一个术语，去首尾空白、按首次出现顺序去重，区分大小写；最多 100 词、单词 40 字符，总文本 4000 字符。留空保存清空词表。
- “复制本次热词到编辑区”只填编辑草稿；“保存个人词表”只保存个人词表；“合并到本次上传”才改变本次任务的热词文本。先保留本次手填词，再追加词表中的新词，合并超限整批拒绝，不截断、不静默丢词。
- 不自动启用词表、不自动上传或发起 ASR。用户仍能编辑本次热词。任务一经提交，入口和热词字段一起锁定；普通、直传、分片及重试使用既有冻结配置，后续修改词表不会改变任务或已生成的原文/纪要。
- 保存使用 `expected_revision`，事务锁定当前用户行，支持首写竞争、无变化保存和一次保存响应丢失后的幂等重试。409 保留本地草稿，需明确放弃并重新载入；清空保留递增版本，旧请求不能恢复已清空词表。未保存草稿关闭后丢弃，不缓存到磁盘。
- `GET/PUT /api/v1.0/recording-hotwords/` 仅操作登录本人，不能选择其他用户。GET 不创建词表，返回 private/no-store；每账号 30 次/分钟。客户端切换账号清理词表，接口响应也受既有会话隔离保护。
- 上传能力新增 `personal_hotwords_available`，旧后端缺省 false；双端不显示不受支持的入口。复用 `hotwords.py` 中的统一解析规则，既有上传参数结构及供应商任务配置不变。

## 验证

- 后端 82 项通过：个人词表 13、普通上传 22、直传 18、分片上传 29。真实 PostgreSQL 并发首写仅一方成功；账号隔离、重复词、超限、清空、防止旧请求恢复，以及词表修改后上传配置/重试仍保持原值均覆盖。
- Web 41 项通过：个人词表 8、上传控件 18、分片逻辑 15。实际组件连接覆盖手填词合并到 FormData，保存不会自动应用，冲突保留草稿、超限不改任务、账号切换与提交后锁定。TypeScript、目标文件 ESLint、JSON 和五语言结构检查通过。
- Android 38 项相关单元测试通过（个人词表 6、既有上传 32）；Pixel 8 / Android 16 的 6 项仪器测试通过（个人词表 4、系统选择器 2）。真实导入夹具证明明确应用后首次上传和响应丢失重试都使用相同热词，提交后入口不可更改。设计 token 检查、debug 构建通过。
- `makemigrations --check --dry-run` 无漂移；本地应用 `core.0184_personal_hotwords` 成功。新增后端文件和修改的 API/路由/测试 Ruff 通过。
