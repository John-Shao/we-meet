> 状态:实现中
> 日期:2026-07-11
> 前置:P1 通话已上线;接通后两端都进**完整视频会议 UI**(参会人网格 + 会议
> 工具栏),对 1:1 语音通话过重。
> 范围(拍板):**仅语音通话**接通后改极简页;**视频通话暂保持会议 UI**(共用
> 管道已为视频铺好,视频极简页列为后续)。

## 0. 目标形态(对照飞书/企微语音通话中)

居中大头像 + 姓名 + `mm:ss` 通话时长;底部三键:**静音 / 挂断(红) / 扬声器⇌
听筒**。默认走**听筒**(会议默认扬声器,语音通话应默认听筒,贴近打电话)。

## 1. 实勘结论(两端一致)

1. **进房后无法区分「1:1 通话」vs「普通会议」**:
   - Android:`Routes.room(...)` 10 个参数里只有 `cam`(由 media 降维),无
     isCall/peerUid/media。
   - Web:`enterRoom` 只在 router state 放 `{autoJoin, callAudioOnly}`;且进房
     瞬间 `finishQuietly` 清空 callStore,peer 名/头像/media 全丢。
   → **必须把 `isCall + peerUid + media` 通过路由带进房。**
2. **对端头像/姓名拿不到自 LiveKit**:participant 只有显示名、无照片,identity
   不保证等于 IM uid。→ 用 `peerUid` 走目录解析(Android `UserDirectory`、
   Web `resolveImUsers`),两端都有现成先例(CallScreen / CallOverlay)。
3. **切入点干净**:Android 在 RoomScreen 的 Connected 分支平级分叉;Web 在
   Conference 用 `<CallStage/>` 替换 `<VideoConference/>`(保留
   `<RoomAudioRenderer/>`)。复用现有麦克风开关 / 挂断 / 音频路由。
4. **无现成通话时长计时器**:极简页自起 `setInterval`/`LaunchedEffect` 每秒刷新,
   起点锚定接通(Connected)时刻。
5. **桌面端**(Electron)复用同一前端,Web 改完自动继承。

## 2. Android 改动

### 2.1 路由管道(带 isCall + peer + media 进房)
`AppNav.kt`:
- `Routes.ROOM` 追加可选 query:`?peerUid={peerUid}&media={media}`(path 参数不动,
  query 保持普通会议向后兼容——不传即会议)。
- `Routes.room(...)` builder 加 `peerUid: String? = null, media: String? = null`,
  非空才拼 query。
- ROOM 的 navArgument 补 `peerUid`(默认 "")、`media`(默认 "")。
- composable 读出,传给 `RoomScreen`;`CallUiEvent.EnterRoom` 分支传
  `peerUid = ev.info.peerUid, media = ev.info.media`(`ev.info` 已有,之前被丢弃)。

### 2.2 RoomScreen 分叉
`RoomScreen.kt` L130-143 签名加 `callPeerUid: String? = null, callMedia: String? = null`。
Connected 分支:`if (callPeerUid != null && callMedia == "audio")
MinimalVoiceCallContent(...) else RoomContent(...)`(平级分叉,复用同一 viewModel)。

### 2.3 MinimalVoiceCallContent(放 feature-im,复用 userDirectory)
- 放 **feature-im**(那里能直接用 `session.userDirectory` 解析对端,和
  CallScreen 同款);对 RoomViewModel 的依赖用**回调参数**注入,feature-im 不引
  app module。签名约:
  `MinimalVoiceCallContent(peerUid, fallbackName, micEnabled, speakerOn,
  onToggleMic, onToggleSpeaker, onHangup)`。
- 头像 `MemberAvatar` + 名 `peer?.displayName ?: fallbackName`;时长自起每秒计时。
- RoomScreen 用 viewModel 状态 + `AudioOutputController` 构造这些回调;
  `onHangup = { viewModel.leave(); onLeave(false) }`。
- **默认听筒**:call 模式初值 `AudioOutput.Earpiece`(覆盖会议的 lastChoice)。

## 3. Web 改动

### 3.1 进房带 peer(router state)
`callController.ts` `enterRoom(slug, info)`:state 补
`{ isCall: true, callMedia: info.media, peer: { uid: info.peerUid, name:
info.peerName, avatar: info.peerAvatar } }`(controller 此刻手里就有 info)。

### 3.2 透传 + 分叉
- `Room.tsx`:读 `history.state?.isCall / callMedia / peer`,传给 Conference。
- `Conference.tsx` L298-311:`isCall && callMedia === 'audio'` 时渲染
  `<CallStage peer=... />` 替换 `<VideoConference/>`,**保留 `<RoomAudioRenderer/>`**
  (远端音频);`<LiveKitRoom>` 已按 audioOnly 只发音频轨。

### 3.3 CallStage(新组件)
- 头像 + 名(来自 props peer,或 `resolveImUsers(peerUid)` 取最新头像)+ 自建
  `setInterval` 计时。
- 麦克风:`useTrackToggle({ source: Microphone })`。
- 挂断:`room.disconnect(true)`;**规避挂断跳 feedback 页**——参考
  `LeaveButton.handleEndRoom` 先 `navigateTo('/im')` 再 disconnect;离开时
  Conference 的 `notifyCallRoomLeft` 仍会写通话时长 log(继承)。
- 扬声器⇌听筒:Web 无「听筒」概念(浏览器走系统默认输出),做「扬声器输出设备
  切换」或**先隐藏该键**(Web 语音通话默认系统输出即可,移动端 App 才有听筒)。

## 4. 边界
- **视频通话**:~~`callMedia === 'video'` → 仍走完整会议 UI(本期不改)~~
  → 已实现极简视频页,见 §7。
- **对端未进房/掉线**:极简页显示「等待接通/对方已离开」——复用房间的
  participant 变化;1:1 里对端离开即结束(P1 已有 ParticipantDisconnected 兜底)。
- **刷新**:Web router state 刷新丢失 → 回退完整会议 UI(通话刷新本就掉线,可接受)。
- **群里/多人**:极简页仅 1:1 通话进(isCall + 单对端);多人会议不受影响。

## 5. 测试要点
- 语音通话接通:两端(App/Web)显示极简页(头像+名+时长),非会议网格。
- 静音 / 挂断 / (App)听筒⇌扬声器 均生效;挂断双方收敛、落 call-log 时长。
- 视频通话仍走会议 UI(未受影响)。
- 桌面端(Electron)语音通话继承极简页。
- 普通会议 UI 完全不受影响(未传 isCall)。

## 6. 验收结论(2026-07-11,全部 ✅)

首轮实机验证发现 3 个缺陷,均已修复并复验通过:

1. **App 挂断按钮文案误用「取消」** → 新增 `im_call_hangup`(挂断)×5 语言
   (android `a54dfc0`)。
2. **Web 被叫侧显示 UUID + 字母头像**:被叫 `onInvite` 的 CallInfo 里
   `peerName` 只是 uid 兜底(设计上由来电弹窗解析),但 `enterRoom` 把未解析的
   info 原样放进 router state。修法:CallStage 复用 CallOverlay 同款
   `resolveImUsers` 进房后重新解析(顺带规避 state 携带的预签名头像 URL 过期)
   (web `c91dd6f4`)。
3. **一方挂断另一方无感知**:挂断只是自己退出 LiveKit 房间,会议语义下不影响
   他人,极简页又不显示参会人。修法(两端同语义):极简页监听远端参会者,
   **见过对方入房后**远端归零(1.5s 防抖避开重连瞬态)即视为对方挂断,自动
   离房返回;对端崩溃/掉网由 LiveKit 参会者超时剔除同路覆盖
   (android `3581409` / web `308ddbd1`)。选房间成员而非 WS hangup 帧,
   因接通后 CallController 已归位 idle——房间即通话,成员状态是真相源。

## 7. 极简视频通话页(2026-07-11,参考微信)

语音页验收通过后按用户要求补齐,按钮风格沿用语音页。分叉从 `media==audio`
扩到 `audio|video`,对端挂断自动结束、call-log 时长等语义两种媒介共用。

**版式(微信式)**:全屏对方画面(对方关摄像头→回退头像+姓名+时长,同语音页);
右上角**镜像**自视窗(自己关摄像头则隐藏);对方画面在时顶部中央时长胶囊。

- **Android**(`c8ee679`):`MinimalCallHost` 统一承载两变体,视频默认**扬声器**
  (语音仍听筒)。`MinimalVideoCallScreen` 留在 feature-im 纯 UI——视频画面由
  app 模块以 `VideoTrackView` **slot 注入**(feature-im 不依赖 LiveKit),
  按 `sessionGeneration` re-key 防重连后 SurfaceView 绑死旧轨。控制:
  麦克风/扬声器⇌听筒/摄像头/翻转 一行 + 挂断居中。RoundButton/色值改
  internal 供两页共用(CallScreen 的同名私有色值随手去重)。
- **Web**:`Conference` 分叉改为 `callPeer` 即极简(`video={!audioOnly}`);
  视频通话进房**强制开摄像头**(对方接受的是视频通话,不改用户会议偏好持久值)。
  CallStage 视频变体:`useTracks([Camera])` 取远/近端轨(muted/未发布即缺席,
  兼作"摄像头是否开"信号),`<VideoTrack/>` 渲染,自视窗 CSS `scaleX(-1)` 镜像;
  控制:麦克风/挂断/摄像头(Web 无听筒/翻转概念)。
- 字符串:App `im_call_camera_on/off`、`im_call_flip`;Web `call.stage.cameraOn/Off`
  (各 5 语言)。
