**顺序：Docs → meet 后端 → meet 前端 → App。**
中间态是安全的：

- **新 Docs + 旧 meet**：meet 不会调新端点，走原来的 authenticate，等于今天的行为。
- **新 meet + 旧 Docs**（顺序做反）：客户端拿到票据 URL，Docs 返回 404 → iframe 里是
  一张 404 页 → 12 秒后落到兜底遮罩。**能点，但比今天难看**，所以别做反。

## 3. 阶段 A — Docs（先上）

### A1. 构建机 build + push（3 个镜像，约 10–20 分钟）

- [ ] ```bash
  cd /mnt/d/workspace/we-meet/we-meet-docs
  git checkout docs-dev && git pull       # 期望到 ccfa5118
  REGISTRY_USER=<火山CR用户> REGISTRY_PASS=<火山CR密码> \
    API_ORIGIN=https://docs.we-meet.online \
    bash deploy/aliyun-docs/build-and-push.sh
  ```

  > 只改了后端，但脚本的 tag 是单一来源、3 个镜像共用（`docs.values.yaml` 里 3 处
  > `${DOCS_IMAGE_TAG}`），所以 3 个都要在新 sha 下重出一份。别手动只推 backend。

### A2. 生产 ECS：helm upgrade

- [ ] ```bash
  cd /opt/we-meet-docs && git checkout docs-dev && git pull   # 与构建机同 commit，tag 自动对齐
  bash deploy/aliyun-docs/deploy-impress.sh
  kubectl -n docs rollout status deploy/impress-docs-backend --timeout=180s
  ```

- [ ] 端点自证（不需要登录态，用 s2s token）：

  ```bash
  S2S=<DOCS_S2S_TOKEN>
  # 1) 签票据：期望 200 + {"ticket": "...", "expires_in": 60}
  curl -sS -X POST https://docs.we-meet.online/api/v1.0/users/session-ticket/ \
    -H "Authorization: Bearer $S2S" -H 'Content-Type: application/json' \
    -d '{"sub":"smoke-test-not-redeemed"}'

  # 2) 无 token 必须 401
  curl -sS -o /dev/null -w '%{http_code} no-token(期望401)\n' \
    -X POST https://docs.we-meet.online/api/v1.0/users/session-ticket/ \
    -H 'Content-Type: application/json' -d '{"sub":"x"}'

  # 3) 假票据必须 302 回 authenticate（而不是 500 / 建出会话）
  curl -sS -o /dev/null -w '%{http_code} %{redirect_url}\n' \
    'https://docs.we-meet.online/api/v1.0/session-from-ticket/?ticket=bogus&next=/'
  ```

  > 第 1 步签出来的票据**别去兑换**：兑换会按那个 sub 建一个新 Docs 用户。60 秒后自然失效。

## 5. 验收（这才是本次的正题）

**主场景 —— 复现原 bug 的那条路径：**

- [ ] 用**新开的无痕窗**登录 meet（无痕 = 一定没有历史 KC cookie），点「云文档」
      → **直接出文档列表**，不出现登录页、不白屏
- [ ] F12 控制台**不再有** `Framing 'https://id.we-meet.online/' violates … frame-ancestors`
- [ ] 关掉浏览器再打开（KC 会话 cookie 已随浏览器关闭消失）→ 云文档仍能直接进
- [ ] Network 面板里 `session-from-ticket` 是 **302**，紧接着 `docs_sessionid` 被 Set-Cookie

**顺带修好的（以前 query 会被 authenticate 整串吃掉）：**

- [ ] 从聊天里点一张 doc-card → 深链直接落到**那篇文档**，不是文档列表
- [ ] meet 切深色 → 云文档跟着深色（首帧就是深色，不闪白）

**兜底遮罩（B 部分）：**

- [ ] 临时把 Docs 停掉（或用 devtools 把 `/docs/session/` 请求 block 掉）→ 进云文档
      → 12 秒后出现「云文档需要重新登录」遮罩，「重新登录」跳顶层 KC 登录页（能正常渲染），
      登完回到 `/docs` 且能进 → 恢复 Docs 后点「重试」也能进

**回归面（本次动到的共用入口）：**

- [ ] 全局搜索里搜文档 → 结果照常（走的是另一个 s2s 端点，不该受影响）
- [ ] 「分享云文档到聊天」→ 选会话 → 发出卡片 → 接收方能打开（授权链路未动）
- [ ] 从未登录过 Docs 的新员工：进云文档 → 能进且看到别人分享给他的文档
      （兑换时补建用户 + 转 Invitation）

## 7. 观察面（上线后 24h）

- [ ] meet-backend 日志里 `docs session bootstrap degraded` 的条数：常态应为 0，
      持续出现 = Docs 不可达或 s2s token 对不上
- [ ] Docs 日志里 `session-from-ticket: invalid or expired ticket`：偶发正常（用户
      放着页面很久才加载完、或重复刷新），持续大量 = 票据被重复使用，查客户端是不是
      在重试里复用了同一个 URL
- [ ] `docs_session` throttle（30/min/人）的 429：正常用量到不了，出现即说明有
      页面在循环换票

## 8. 回滚预案

| 对象 | 方式 |
|---|---|
| Docs | `helm rollback impress -n docs`（或 `TAG=<上一个 sha> bash deploy/aliyun-docs/deploy-impress.sh`） |
| meet 后端 | `kubectl -n meet rollout undo deploy/meet-backend` |
| meet 前端 | `kubectl -n meet rollout undo deploy/meet-frontend` |
| **迁移** | **不涉及**——两侧均无迁移 |
| 票据数据 | 存在 Docs 的 cache 里、60 秒过期，回滚后自然消失，无残留 |

回滚顺序与上线相反：**先 meet 前端 → meet 后端 → 最后 Docs**。
只回 meet 前端就能立刻退回原行为（老的 authenticate 进站），Docs 侧新端点留着无害。

## 9. 本次没做的事（别在验收时找）

- **Keycloak remember-me**（让 KC 会话 cookie 落盘）：讨论过，未做。它只把「关浏览器
  就掉」推迟到 14 天，过期后仍是死路，且要改 `keycloak-phone-auth` 插件重新出镜像。
  票据方案落地后它不再是必需项。
- **KC 的 `frame-ancestors` 放行 meet**：明确不做——等于给登录页开点击劫持。
- **App 端的兜底遮罩**：App 是顶层 WebView，登录页能正常渲染，不存在 web 那种"白屏
  无从自救"，因此只做了进站方式的修复。
