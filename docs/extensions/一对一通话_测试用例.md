# 一对一通话 & 会议入口 —— 测试用例

> 覆盖本轮新增:P0 入口(抽屉/快速会议/群聊会议/单聊通话面板)、
> P1 通话信令(振铃/接听/拒接/取消/超时/忙线/多端/call-log)、
> P2 离线推送来电 + 全屏来电 + 回铃音、Web/桌面端通话。
> 用途:发版前手工回归清单。每条给前置/步骤/预期,勾选记录。

## 设备与账号准备

- **A / B 两个账号**,互为好友(存在 direct 会话)。
- **A**:主叫机(Android APK)。
- **B**:被叫机(Android APK),另可在 Web(`https://meet.we-meet.online`)
  同账号登录,用于多端 / Web 用例。
- 均已授予:麦克风、摄像头、通知(POST_NOTIFICATIONS)、
  **全屏通知(USE_FULL_SCREEN_INTENT,Android 14+ 需在系统设置手动开)**。
- P2 冷杀用例还依赖**个推 `im_calls` 渠道 + 厂商通道审核已通过**(见设计文档
  顶部「上线阻断项」;未通过时 TC-P2-03/04/05 跳过或只观察不判定)。

图例:优先级 P0=冒烟必过 / P1=核心 / P2=边界。

## A. P0 UI 入口

### TC-P0-01 我的抽屉留缝(P1)
- 前置:登录,进「消息」Tab。
- 步骤:点顶部头像打开「我的」抽屉 → 观察右侧;点右侧露出的消息区。
- 预期:抽屉占屏约 88%,右侧留约一指宽缝隙露出底层消息;点缝隙处关闭抽屉。

### TC-P0-02 快速会议按钮(P2)
- 步骤:首页查看主行动按钮。
- 预期:文案为「快速会议」,图标为**闪电**(非摄像机);点击进创建预览页。

### TC-P0-03 群聊发起快速会议(P1)
- 前置:进任一**群聊**会话。
- 步骤:点顶栏视频图标。
- 预期:进创建预览页,会议名已预填「{群名}的视频会议」;点开始会议建房进房。
- 反例:**单聊**顶栏无此视频按钮(见 TC-P0-04 是通话按钮而非会议)。

### TC-P0-04 单聊通话面板(P0)
- 前置:进任一**单聊**会话。
- 步骤:点顶栏通话(电话)图标。
- 预期:底部弹出三项面板:**语音通话 / 视频通话 / 拨打电话**;
  「拨打电话」置灰不可点(后端暂无手机号,P3)。
- 反例:群聊顶栏无此通话按钮。

### TC-P0-05 语音通话进 audio-only 预览(P1)
- 步骤:单聊面板点「语音通话」(注:P1 上线后此项直接走真信令呼叫,
  见 TC-P1-*;若仍走预览版本则)预览页摄像头默认关闭且无摄像头开关,
  仅麦克风 / 扬声器。
- 预期:符合语音通话语义,不显示本地画面。

## B. P1 通话信令(A↔B 双机在线)

### TC-P1-01 语音接听全链路(P0)
- 步骤:A 单聊点语音通话呼 B → B 来电页点接听 → 通话约 60s → 任一方挂断。
- 预期:
  1. A 呼出页「正在发起语音通话…」;B 收到 invite 后 A 变「等待接听…」。
  2. B 来电页有头像/姓名/铃声/振动 + 拒接(红)/接听(绿)。
  3. 接听后双方进房,语音通,摄像头关。
  4. 挂断后双方聊天各出现一条「语音通话 · 01:0X」(时长一致,±1s)。

### TC-P1-02 视频接听全链路(P0)
- 步骤:同上,选「视频通话」。
- 预期:呼出页背景为本地相机预览;接听后进房摄像头开;call-log 为「视频通话 · mm:ss」。

### TC-P1-03 被叫拒接(P0)
- 步骤:A 呼 B → B 点拒接。
- 预期:A 侧收敛,聊天显示「语音通话 · 对方已拒绝」;
  B 侧聊天显示「语音通话 · 已拒绝」(视角文案不同,均落库)。

### TC-P1-04 主叫取消(P1)
- 步骤:A 呼 B → 未接前 A 点取消(或返回)。
- 预期:B 来电页立即消失;A 聊天「语音通话 · 已取消」,B 聊天「语音通话 · 对方已取消」。

### TC-P1-05 无人接听超时(P1)
- 步骤:A 呼 B → 双方都不动,等 60s。
- 预期:约 60s 后 A 呼出页与 B 来电页各自消失;A 落 call-log(未接/已取消类);
  两端时钟独立,不依赖对方在线。

### TC-P1-06 被叫忙线(P1)
- 前置:B 正处于另一通话或会议中。
- 步骤:A 呼 B。
- 预期:A 很快收到忙线并收敛,提示「对方忙」;B 当前通话/会议不受打扰、无来电页弹出。

### TC-P1-07 多端一端接听(P1)
- 前置:B 同时在**手机 + Web**登录。
- 步骤:A 呼 B → B 在手机接听。
- 预期:手机进房;**Web 端来电界面自动消失并显示「已在其他设备接听」**(反之亦然)。

### TC-P1-08 多端一端拒接(P1)
- 前置:B 手机 + Web 同时在线。
- 步骤:A 呼 B → B 在手机拒接。
- 预期:Web 端显示「已在其他设备拒绝」;A 侧为「对方已拒绝」。

### TC-P1-09 通话中对端离开兜底(P1)
- 步骤:接通后,强杀 B 的 App 进程(或断网)。
- 预期:A 依据 LiveKit ParticipantDisconnected 感知对端离开,通话收敛退房
  (不依赖 hangup 帧送达)。

### TC-P1-10 接听与取消竞态(P2)
- 步骤:A 呼 B,在 B 点接听的**同一瞬间** A 点取消。
- 预期:不出现单边卡死;B 若已进房但对端已走,约 15s 内自动挂断并提示「通话已取消」;
  A 侧忽略迟到的 accept。

### TC-P1-11 双方互拨(P2)
- 步骤:A、B 几乎同时互相发起呼叫。
- 预期:双方各自回忙线并收敛,提示「对方忙」;不出现双方都进不同房的错乱。

### TC-P1-12 普通会议不产生 call-log(P1)
- 步骤:走「快速会议 / 群聊会议」正常开会并结束。
- 预期:聊天/会话**不**出现任何「语音/视频通话 · …」call-log 消息
  (call-log 仅一对一通话链路产生)。

## C. P2 离线推送来电(Android 被叫)

> 依赖个推/厂商渠道审核已过(见准备)。审核未过时 ①② 仍可测(进程存活路径)。

### TC-P2-01 前台在线对照(P1)
- 前置:B 的 App 在前台、WS 已连(顶部「已连接」)。
- 步骤:A 呼 B。
- 预期:走 WS 正常振铃(TC-P1-01 路径),**不触发离线推送**(不应出现系统通知栏来电)。

### TC-P2-02 后台进程存活 + WS 断(P0)
- 前置:B App 退到后台但进程未被杀;制造 WS 断(如切飞行几秒再关,保持进程)。
- 步骤:A 呼 B。
- 预期:透传到达 → **直接弹全屏来电页**(不需点通知);接听可进房。

### TC-P2-03 冷杀被叫响铃(P0,依赖渠道审核)
- 前置:B 的 App 进程被**彻底杀死**(最近任务划掉)。
- 步骤:A 呼 B。
- 预期:B 收到**来电级系统通知(响铃 + 高优横幅 / 锁屏全屏)** → 点击拉起 App
  → 进来电页 → 接听 → 进房通话;A 侧全程正常。

### TC-P2-04 冷杀 + 主叫中途取消(P1,依赖审核)
- 步骤:TC-P2-03 中,B 尚未点接听时 A 取消;随后 B 点通知/接听。
- 预期:B 接听后房间已关 → 提示「通话已结束」,不会空房干等。

### TC-P2-05 冷杀 + 不理会(P1,依赖审核)
- 步骤:TC-P2-03,B 收到通知但不操作。
- 预期:约 55s 后来电通知不再响 / 自动消失(TTL 55s);A 侧 60s 超时并落 call-log。
- 反例:**不应**出现「几分钟后手机才响」的迟到铃声。

### TC-P2-06 陈旧推送丢弃(P2)
- 步骤:构造 / 观察一条 ts 已超过 55s 的来电推送到达(弱网延迟场景)。
- 预期:客户端静默丢弃,不弹来电页、不响铃。

### TC-P2-07 seed 后 accept 重试(P2)
- 前置:B 冷杀被唤醒,WS 仍在重连的窗口内点接听。
- 预期:accept 帧带重试(≤5×1s),最终 A 收到、B 进房;不出现「B 进房而 A 仍空振铃」。

### TC-P2-08 前台不叠通知(P2)
- 步骤:B 在前台时收到来电(TC-P2-01)。
- 预期:仅 in-app 全屏来电页,**不**额外弹系统通知栏来电(isForeground 抑制)。

### TC-P2-09 通知清理(P2)
- 步骤:来电通知出现后,进入来电页 / 呼叫被取消 / 通话终止。
- 预期:对应 call_id 的系统通知被清除,不残留。

## D. 回铃音(450Hz 国标 1s/4s)

### TC-RB-01 Android 主叫回铃(P1)
- 步骤:A(Android)呼 B,B 未接,注意 A 的听感。
- 预期:**B 的设备开始响铃后**(A 显示「等待接听」),A 听到 450Hz「嘟——(1s)停(4s)」
  回铃;A 取消 / 接通 / 超时后回铃停止。
- 反例:B 还没响铃(拨号/唤醒中)时 A **不**应有回铃音。

### TC-RB-02 Web 主叫回铃(P1)
- 步骤:A 在 Web 呼 B,同上观察。
- 预期:同款 450Hz 1s/4s;浏览器 autoplay 被拦时静音但浮层仍显示「等待接听」(不报错)。

## E. Web / 桌面端通话

### TC-WEB-01 Web 单聊呼叫入口(P1)
- 步骤:Web 进单聊,顶栏点 📞 / 📹。
- 预期:发起语音 / 视频呼叫;呼出浮层「等待接听」,取消按钮为**挂断话筒图标**(与 App 一致)。

### TC-WEB-02 Web 接听进房(P0)
- 步骤:A(App)呼 B(Web)→ B 点接听。
- 预期:Web 来电浮层 → 接听 → 导航进 `/{room_slug}` LiveKit 房通话。

### TC-WEB-03 Web↔App 互通矩阵(P1)
- 组合:App→Web 接听 / Web→App 接听 / App→Web 拒接 / Web→App 取消。
- 预期:四条均正常收敛,call-log 双端视角文案正确。

### TC-WEB-04 桌面端(Electron)继承(P2)
- 步骤:在 Electron 桌面壳内重复 TC-WEB-01/02。
- 预期:与浏览器行为一致(桌面壳复用同一份前端)。
