# 会议室固定五级层级 — 部署步骤

## 发布前

- 备份 PostgreSQL，重点确认 `meet_meeting_room_node`、`meet_meeting_room` 和 `meet_meeting_room_booking` 可恢复。
- 告知管理员：升级会清空管理端当前可见的会议室结构，上线后需要重新创建真实层级和会议室。
- 记录仍在使用的会议室名称、编号、容量、设施和预订策略，便于升级后重建。

## 数据迁移

执行 Django migration `0088_retire_legacy_meeting_room_hierarchy`。迁移会把全部现有层级和会议室设置为已删除、已禁用，不会物理删除会议室、日历事件或预订记录。

该迁移不提供反向恢复。需要回滚数据时应恢复发布前数据库备份，不能只执行 `migrate` 回退。

## 上线后重建

1. 进入 `/admin/meeting-rooms`，从空态开始创建国家/地区。
2. 依次创建城市、园区、楼栋、楼层；城市必须选择 IANA 时区。
3. 选中第 5 级楼层后添加会议室，并恢复编号、容量、设施和预订策略。
4. 员工端验证层级树、会议室搜索、可用性、时间轴和日历预订。

## 验收查询

```sql
SELECT depth, count(*)
FROM meet_meeting_room_node
WHERE deleted_at IS NULL
GROUP BY depth
ORDER BY depth;

SELECT count(*)
FROM meet_meeting_room r
JOIN meet_meeting_room_node n ON n.id = r.node_id
WHERE r.deleted_at IS NULL AND n.depth <> 4;
```

第一条查询仅应出现 `0` 至 `4`；第二条必须返回 `0`。抽查升级前的历史日程，会议室名称和旧路径应仍可显示，但旧会议室不应出现在新的预订选择器中。
