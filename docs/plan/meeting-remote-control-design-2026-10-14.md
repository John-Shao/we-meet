## 1. 目标与关键决策

参会者 A 向同一会议中的参会者 B 申请操作设备。B 明确同意并选择共享屏幕后，A 在会议内观看 B 的屏幕，使用鼠标和键盘操作 B 的设备。B 可随时停止控制，继续普通会议或屏幕共享。

建议采用现有 LiveKit 传输屏幕与操作消息，新增业务授权服务、会议控制界面、Electron 原生输入模块。无需另建远程桌面媒体服务器，也不引入独立远程桌面产品账号。

| 项目 | 建议决策 |
| --- | --- |
| 首期被控端 | Windows 10/11 x64 Electron 客户端；具体系统版本以打包运行时支持矩阵和实机验证为准 |
| 首期控制端 | PC 浏览器与 Windows Electron；首批验收 Chrome/Edge，其他浏览器验证后开放 |
| 首期共享范围 | B 明确选择的一块完整显示器；支持多显示器中选择一块，暂不支持同时控制多块、单窗口被控 |
| 控制能力 | 移动、左右中键、双击、拖拽、滚轮、常用键盘与快捷键、显式文本输入 |
| 控制关系 | 每个被控设备最多一个控制者；每个连接最多一条控制关系；首期禁止 A→B→C 控制链和相互循环控制 |
| 同账号多设备 | 首期不支持同账号多设备同时加入同一会议；连接替换终止旧授权 |
| 授权 | 每次申请单独确认；主持人不能代 B 同意；普通共享屏幕不构成远程控制授权 |
| 授权保管 | 服务端签发短期许可，本机主进程持有最终执行开关；操作事件另做会话签名和防重放 |
| 不在首期范围 | 无人值守、开机常驻控制、文件传输、剪贴板同步、音频专用链路、提权、登录/锁屏界面控制、AI 自动操作 |
| 后续扩展 | 手机控制电脑、macOS 被控、Android 被控分别验收；iOS 被控先提供查看和指示标注 |

首期支持普通桌面会话内的应用操作，不承诺任意系统界面均可操作。Windows `SendInput` 受 UIPI 等系统权限约束，不自动提权或绕过 UAC、安全桌面。

## 3. 产品交互

### 3.1 A 申请，B 已共享屏幕

1. A 在 B 的共享画面或参会者菜单点击“申请远程控制”。只允许申请当前在线且声明可被控的具体连接。
2. A 看到“等待 B 同意”，可以取消。申请有效期默认 30 秒。
3. B 收到原生确认框，显示 A 的服务端身份、所属信息（如可用）、当前共享显示器，以及“允许对方使用鼠标和键盘操作此屏幕”的说明。按钮为“拒绝”“允许本次控制”，默认拒绝。
4. B 同意后进行共享源、轨道、版本、原生执行器、撤销热键检查。成功后创建许可并握手；A 收到 READY 后才显示“正在控制 B”。
5. A 主动进入控制视图并点击画面取得输入焦点。仅此视图捕获键鼠事件；聊天、会议按钮和其他页面正常使用。
6. B 的原生置顶控制条持续显示“正在被 A 控制”“停止控制”和紧急快捷键。会议内同时显示状态。
7. A 结束控制或 B 停止后，先在本机关闭执行门、释放键鼠，再异步同步服务端和另一方。普通屏幕共享默认继续。

请求入口先检查 B 当前连接的被控 capability。B 使用普通网页、未安装/未运行桌面客户端或 capability 过期时，入口禁用并提示“请让对方使用支持远程控制的桌面客户端加入会议”；不创建无人处理的申请。客户端状态只是界面预检，服务端创建与批准时仍须核验。等待期间 B 退出或能力消失立即取消，不一直等待 TTL。

原生确认界面显示服务端提供的有效期与倒计时。推荐独立隔离的受信确认窗口，关闭 Node 集成和通用 API 桥，由主进程负责时间、状态及按钮；不假定既有异步 `dialog.showMessageBox` 能实时更新按钮或自动关闭。到期/取消/离会时立即禁用允许并关闭或展示“申请已失效”；迟到的点击不得签名或提交 approve。实际 UI 机制在 P0 验证，不能自动关闭的实现必须仍在主进程拒绝迟到动作。进入 PREPARING 后显示独立的 60 秒准备期限，不能把原已过期的 PENDING 重新变为有效。

已知体验代价：真实断线、连接替换及 heartbeat 超时都终止授权，重连后必须再次申请。后台标签页的定时器限速也可能使授权终止；双方给出明确结束原因与重新申请入口，不为弱网体验默默继承旧许可。

### 3.2 B 尚未共享或正在共享窗口

- 尚未共享：B 同意申请后主动选择整块显示器，再发布屏幕；取消选择、采集失败、无发布权限均不建立控制。
- 正在共享窗口：提示“远程控制需要共享整块显示器”，由 B 主动切换；拒绝切换则继续原窗口共享。
- 确认框中的屏幕必须与最终绑定屏幕一致。选择改变时重新展示确认信息，不沿用此前对另一屏幕的确认。
- 停止控制不自动停止共享；停止共享必须终止控制。界面分别提供两个动作，明确当前状态。

### 3.3 撤销、失焦与并发

- B 本地停止入口和本地紧急键优先级最高；远程输入不得触发“同意”“恢复”或点击原生控制条。
- 建议紧急键候选改为 `Ctrl+Alt+Shift+F10`，P0 实测后固定；不使用 Windows 为调试器保留的 F12。注册失败则本次不开放被控能力。注入层按 §8.2 拦截构成该组合的 down，保留正常释放；该组合不能用于远程目标应用，并在快捷键说明中提示。
- B 检测到本地真实键鼠输入时进入业务 PAUSED（§6.3），释放远程按键；只允许 B 在本地明确恢复。原生输入标记用于区分本地与注入事件，须专项验证。
- A 画面失焦、切换标签页、打开弹窗时进入本地 `CAPTURE_SUSPENDED`，停止捕获并请求 B 关闭输入门、释放按键；业务许可可保持 ACTIVE。回到控制视图后，仅在 B 未暂停/撤销、许可及链路仍有效时，由 A 点击并完成新输入代次握手后继续；具体状态见 §6.3，不自动恢复拖拽或按住键。
- 已有控制关系时其他申请返回 BUSY；不静默替换控制者。并发同意通过服务端原子锁及本机单会话锁双重限制。
- 首期 A、B 使用不同的已认证账号，不支持同账号多设备同时加入同一会议。当前登录用户 LiveKit identity 固定为 `user.sub`，相同 identity 的新连接会替换旧连接；SID 仅用于绑定当前连接，不能实现同账号并发。检测连接替换后终止旧许可，不迁移控制关系。

## 4. 平台范围与扩展策略

| 平台 | 控制端 | 被控端 | 交付约束 |
| --- | --- | --- | --- |
| Windows Electron | 首期 | 首期 | 普通权限桌面应用；锁屏、UAC、安全桌面不支持 |
| PC Web | 首期 Chrome/Edge | 不支持整机被控 | 浏览器无法从屏幕共享授权获得系统级输入权限 |
| macOS Electron | 后续验证 | 后续专项 | 需系统录屏与辅助功能授权、原生适配、签名/公证和打包验证 |
| Linux | 后续评估 | 后续评估 | X11 与 Wayland 输入/采集机制差异大，不按 Electron 跨平台自动承诺 |
| Android | 第二阶段控制 PC | 独立后续阶段 | 被控需 MediaProjection、前台服务及额外控制能力；厂商差异、分发要求需验证 |
| iOS/iPadOS | 第二阶段控制 PC | 查看与人工指导 | 不将 FaceTime 系统能力等同于自研 App 可用的整机输入接口 |

Android 无障碍手势接口存在，但“技术上可发手势”不等于所有应用可控或可以直接发布；后续单独评审适用性、授权说明、分发要求、文本输入、受保护页面及设备矩阵。不得要求 root、ADB 常驻或隐藏开启权限。

手机控制 PC 的交互采用触控板模式、长按右键、双指滚动、软键盘和常用组合键工具栏。沿用同一会话授权协议，但移动后台/锁屏必须立即停发并释放输入。

## 5. 总体架构与信任边界

```text
A 控制视图 ── 屏幕订阅 ──────────────── LiveKit ← B 屏幕轨道
    │
    ├─ HTTPS：申请、取消、状态、结束 ─── Django 远控授权服务
    │                                      │ 签名许可/短期租约
    └─ 签名键鼠事件 → LiveKit 定向数据 → B 会议 Renderer
                                             │ 最小 IPC（转交签名消息）
                                       B Electron 主进程
                                      /      │        \
                             原生确认/控制条  验签/会话门  采集源绑定
                                             │ 受限 stdio
                                       Windows 输入 helper
                                             │ SendInput
                                         B 普通桌面

独立原生 release guardian ← 共享输入台账 / 进程存活监控 → 输入 helper
    └─ helper 故障：确认终止后，仅对台账中的候选按下项发送释放
```

LiveKit 负责媒体与实时消息，不承担业务同意，也不会执行操作系统输入。服务端负责身份、组织策略、并发授权和审计；B 本机持有最终执行开关，必须匹配本地确认记录后才接受服务端许可。服务端批准状态本身不能替代 B 的本地同意；首期不声称服务端能独立证明原生来源或真人点击，具体保证范围见 §6.2。

采用 Renderer 转发数据便于复用现有 LiveKit 连接，但不把消息 payload 中的 `from` 当作身份。Renderer 检查 SDK 返回的 participant identity/SID；主进程另外验证服务端绑定的控制者会话公钥与每条事件签名，阻止其他参会者伪造输入及跨会话重放。

安全边界不包含已被攻陷的 B 操作系统或本机管理员。控制者浏览器被同源脚本完全攻陷仍可能滥用其已获授权的会话，因此限制作用域、使用原生同意、短期租约和随时撤销，不宣称签名可以解决所有 XSS 问题。

首期传输采用现有部署的 TLS/DTLS-SRTP 等链路保护；定向发送和签名不等于端到端保密。不新增“远控消息端到端加密”的产品承诺。若组织要求服务端也不可见操作内容，需另行加入密钥协商与 AEAD 并评审后上线。

## 6. 授权服务与状态模型

### 6.1 服务端对象

建议新增 `RemoteControlSession`，控制会话数据库主键与展示用 request ID 分离但可关联：

| 字段 | 含义 |
| --- | --- |
| `id`、`request_id`、`protocol_version` | 随机 UUID、幂等申请 ID、协议版本 |
| `organization_id`、`room_id`、`room_sid` | 业务会议和当前 LiveKit 房间实例；不能只绑定可重复使用的会议号 |
| `controller_user_id/identity/participant_sid` | A 真实用户、LiveKit 身份及当前连接 SID |
| `target_user_id/identity/participant_sid` | B 对应身份和连接 |
| `target_device_session_id` | B 主进程启动生成的临时设备会话标识，不采集硬件指纹 |
| `controller_public_key`、`target_public_key` | 此次控制者事件签名公钥、B 授权证明与 challenge/ACK/READY 签名公钥；公钥绑定不等于设备远程证明 |
| `request_digest`、`consent_digest`、`authorization_challenge_id` | 不可变申请摘要、最终同意绑定摘要、服务端一次性授权挑战；挑战含用途和有效期 |
| `share_instance_id`、`track_sid`、`display_binding_hash` | 本机共享实例、屏幕轨道和可信显示器绑定摘要 |
| `state`、`state_version`、`epoch` | 服务端状态、乐观锁版本及授权代次 |
| `requested_at`、`approved_at`、`expires_at`、`ended_at` | 生命周期，使用服务端时间 |
| `end_reason`、`policy_version` | 结束原因和授权策略快照 |

状态：`PENDING → PREPARING → ACTIVE ↔ PAUSED → ENDED`；PENDING/PREPARING 可转 `REJECTED/CANCELLED/EXPIRED/FAILED`。终态不可回到 ACTIVE。新申请必须创建新 ID、密钥及 epoch。

数据库对目标设备的未终结会话建立唯一约束，并在事务内锁定设备会话；同时限制控制者连接参与的活动关系。跨实例请求不能仅用进程内锁。申请幂等键绑定申请人及请求摘要，重复请求返回原结果，内容不同返回冲突。

### 6.2 拟定接口

前缀建议 `/api/v1.0/rooms/{room_id}/remote-control/`，实施时按现有 router 规范落位。全部使用 TLS、现有认证与 CSRF/Origin 策略；会话 UUID 不是访问凭据。

| 方法与路径 | 调用方 | 行为 |
| --- | --- | --- |
| `POST requests/` | A | 指定 B 连接、A 会话公钥、capability 版本；校验在线、权限、限流后创建申请 |
| `GET requests/?target=self` | B | 查询本人当前连接的待处理申请；原生主进程读取真实申请详情再提示 |
| `POST {id}/prepare/` | B 主进程流程 | 提交本机生成的会话公钥、采集/轨道绑定和 prepare 用途签名；验账号、摘要、一次性挑战、有效期及版本后进入 PREPARING |
| `POST {id}/approve/` | B 主进程流程 | 原生确认最终绑定后提交 approve 用途签名；服务端验不可变摘要、挑战和绑定后原子同意并签发许可；不把自签公钥等同于原生证明 |
| `POST {id}/reject/` | B | 拒绝未批准申请 |
| `POST {id}/cancel/` | A | 取消尚未激活申请；与 approve 竞态由版本校验决定 |
| `GET {id}/` | A/B | 返回脱敏状态和本方所需签名许可，不返回第三方会话 |
| `POST {id}/lease/` | B 主进程 | 验证仍在线及策略后续租；A 无权替 B 续租 |
| `POST {id}/pause/` | A/B | 同步暂停状态；本地先关门，重复调用幂等 |
| `POST {id}/resume/` | B 主进程本地确认流程 | 仅 PAUSED 可用；递增 epoch、签发新许可，重新 READY 后开放，远端无权触发原生恢复 |
| `POST {id}/end/` | A/B；管理员限撤销 | 幂等终止并记原因；管理员可撤销，不能批准 |
| `POST {id}/authorization-challenge/` | B | 获取仅限本次状态版本、用途和有效期的一次性挑战，不能改变申请摘要或延长已过期申请 |

服务端核验 A/B 实际在同一当前房间且不在等候室，A/B 非录制机器人或 AI Agent，并验证共享发布权限、数据发布权限、房间未结束及轨道属于 B。连接 SID、房间实例从受信服务查询/会话映射解析，不采信调用者自行填的值。实名显示使用服务端用户记录，避免仅依赖可修改昵称。匿名访客首期不开放远控。

客户端不得只靠 `LiveKitTokenAuthentication` 验证 token 即放行：还要核验 room grant、当前实际连接、组织及目标角色。不能因主持人身份、同组织或普通屏幕共享自动批准。

所有远控业务入口显式要求 `user.is_authenticated and user.is_active and user.sub and not user.is_device`，并执行各动作的 A/B/管理员角色校验。无对应用户的 LiveKit token、匿名和设备账号直接拒绝，不依赖认证类返回对象后由后续流程隐式兜底。会议 token 和用户 API token 采用各自适用的认证类，不把主进程 OIDC Bearer 当作 LiveKit token 解析。

**授权证明与本机门控的首期边界：**首期采用普通用户认证、会话签名及本机原生确认双重门控，不引入设备远程证明。服务端验签只能证明提交方掌握所绑定私钥，不能仅凭临时自签公钥证明它来自原生客户端或证明真人点击。用户级凭据被盗可能伪造服务端批准状态；这不能直接打开 B 本机执行门。产品状态不得只根据服务端 ACTIVE 显示“可以操作”，必须等待 B 原生签名 READY。

主进程从可信服务读取并固定 request_digest；其覆盖房间实例、A/B 用户/identity/SID、A 会话公钥、协议版本、请求有效期和权限范围。prepare/approve 的签名另覆盖 request_id、request_digest、主进程自行生成的 B 公钥/设备会话、share_instance_id、track_sid、display_binding_hash、state_version、epoch、操作用途、挑战 ID 及有效期。签名语义和编码沿用 §7.2，prepare/approve/resume/lease 的用途不得互换。服务端事务内消费挑战并核验状态；幂等重试返回原结果，内容改变拒绝；原申请公钥等关键字段不得被 prepare 改写。

授权证明的 audience 固定为远控授权服务，scope 固定为本次申请的权限范围，两者均纳入签名。服务端产生不可预测的一次性挑战，绑定申请 ID、B 账号、用途、state_version、epoch 和有效期；接收方依据当前记录重建待验签内容，不以调用者自报的摘要或有效期为准。挑战到期、状态变化或绑定变化即失效；幂等重试只读取已保存的原结果，不能再次消费挑战、再次批准或延长许可。

B 主进程只在原生确认最终绑定后产生本地 consent record，不提供 Renderer 任意内容签名接口；helper 只能装载与本地记录、自己所属进程生成的会话公钥、可信采集实例、登录 epoch 完全匹配的服务端许可。服务端返回了另一个 target_public_key、控制者、显示器或扩大权限时拒绝激活，即便许可签名有效。原生确认超时、取消或绑定变化使记录失效；服务端续租/恢复状态不能重新创建本地同意。resume 另需 B 本地动作和新的用途挑战，lease 只为已持有的许可续期。

若以后要求“服务端可验证原生来源”，必须另立可信设备密钥登记/证明方案，明确密钥保护、注册信任来源、换绑、撤销和恢复。让普通 Renderer 凭同一个用户 token 注册任意新公钥不满足该要求；target_device_session_id 只是临时标识。即使有设备签名也只证明密钥参与，真人确认仍依赖受信 UI 的本地门控。P1 前必须评审这一保证范围与本机匹配契约。

服务端签名许可使用独立用途的非对称签名密钥与 `kid`，不下发 LiveKit API secret。许可包含上述绑定、公钥、操作范围、签发/到期时间、最大会话到期和 audience。公钥通过受信服务配置/HTTPS 获取，支持轮换；拒绝未知算法、未知 key、错误 audience 和旧 epoch。

建议申请 TTL 30 秒、准备 TTL 60 秒、单次最长 30 分钟；B 主进程每 5 秒续租，许可有效期 15 秒，达到最长时长需重新申请。初始许可、续租都不能改变已确认屏幕/控制者/权限。

LiveKit topic 中状态通知仅用于唤醒读取，不作为批准依据。服务不可达时不能批准或续租，旧许可到期后停止。B 本地停止立即生效，服务端撤销在推送正常时立即传达；推送丢失时最迟随租约到期失效（目标上界 15 秒），不得宣称服务端撤销零延迟。

15 秒是正常运行的本机最终注入门停止接受新输入的许可上界，不是“目标应用动作回滚”或“所有故障下按键必已释放”的上界。helper 在每次注入前及独立计时器检查租约，不能仅依赖主进程 JS 回调。租约用受信服务时间/往返预算建立单调截止时刻，保守扣除传输耗时，墙钟回拨不延长许可；无法建立时拒绝开放。helper/主进程卡死另外由 guardian 的原生监督路径关闭、终止和释放，目标及保证边界见 §9.1、§14；两条路径取最先可生效者，不能简单相加或宣称任意故障都在 15 秒内完成释放。

业务 PAUSED 会立即作废当前本地挑战并清空队列。其恢复必须由 B 本机真实交互发起，服务端原子递增 epoch 并重发许可；重置 seq、挑战和 pressed set 后重新握手。旧 epoch 的队列、心跳和异步结果全部丢弃。业务暂停期间服务端只允许维持暂停许可，不允许普通续租把状态改回 ACTIVE。A 暂停捕获输入另按 §6.3 处理，不适用此恢复权限。

### 6.3 业务许可与输入捕获的两层状态

业务状态 `PAUSED` 表示 B 的执行许可暂停，只能由 B 本地恢复；A 的 `CAPTURE_SUSPENDED` 仅表示暂时不捕获键鼠，不能调用业务 `/resume/`。ACTIVE 是建立输入的必要条件，不代表输入门始终开放。B 的原生执行状态另包含 `INPUT_OPEN/INPUT_CLOSED` 与 `inputGeneration`。

| 触发 | 业务状态与执行门 | 恢复主体与条件 |
| --- | --- | --- |
| A 切到会议聊天、视图失焦、切换标签页 | ACTIVE 可维持；A 立即停发并发送签名 `INPUT_SUSPEND`，B 关闭门、作废挑战、清队列、释放并 ACK；健康心跳继续 | A 返回后主动点击，完成新输入代次握手；不能继承按键状态 |
| A 返回且暂停 ACK 尚未收到 | 保持 CAPTURE_SUSPENDED，不发输入 | 等待 ACK；请求超时或 heartbeat 失效则结束，不能直接重开门 |
| B 本地接管或点击暂停；视频确认不可用 | 本地及业务 PAUSED，输入门关闭 | 只有 B 原生恢复操作可递增 epoch、重签许可并 READY；A 仍须主动取得输入焦点 |
| A 发现输入 ACK 超时、状态事件缺口、执行器故障 | 本地关闭门，业务结束/FAILED | 原会话不可恢复，重新申请；不走 A 自助恢复路径 |
| 断线、连接替换、停止共享、撤销或许可到期 | 终止、关门 | 新会话重新申请 |

`INPUT_SUSPEND` 与捕获状态 heartbeat 使用 A 的 signal 序号串行处理；较新的 suspended heartbeat 先到时同样关门，迟到的旧状态不能重开门。收到 suspend 后 B 返回带新随机恢复挑战的签名 ACK。A 的 `INPUT_RESUME` 必须引用该一次性挑战；B 再核验 ACTIVE、epoch、许可、视频就绪及全部安全条件，分配新的 `inputGeneration`、挑战和 READY 后才允许输入。恢复挑战有效期 3 秒，过期只能刷新挑战，不能放宽授权。

输入、输入 ACK、挑战均绑定 inputGeneration；切换代次使旧输入立即失效。A 的焦点恢复不得清除 B 的 PAUSED，普通 heartbeat 或旧 READY 不能开启输入门。暂时失焦期间允许 `captureReady=false` 的健康 heartbeat 维持连接，但不执行输入；`videoReady=false` 则触发业务 PAUSED。若后台定时器被限制而 heartbeat 超时，按断线结束，返回后重新申请。

同账号并发若后续立项，须先设计连接级 identity、用户映射与可信设备登记，并复查 `LiveKitTokenAuthentication`、参会者管理、踢人/静音、通知和审计的身份假设；不在本方案首期改造用户 identity。

## 7. 实时消息协议

### 7.1 Topic 与消息类型

| Topic | 方式 | 用途 |
| --- | --- | --- |
| `we-meet.remote-control.v1.signal` | reliable，定向 | READY、状态提示、END、挑战、heartbeat/heartbeat ACK、INPUT_SUSPEND/RESUME 及其 ACK、输入 ACK、错误 |
| `we-meet.remote-control.v1.input` | reliable，定向 | 按键、按钮、滚轮、文本及首期鼠标移动 |

每次必须显式设置唯一 `destinationIdentities`。接收端同时校验 topic、room、session、身份、签名、大小和版本；没有 participant 上下文的服务端数据包不得当作用户输入。

已安装 `livekit-client@2.17.1` 的 DataReceived 回调为 `(payload, participant, kind, topic, encryptionType)`，未透出 destination_identities。定向发送是发送端契约；接收端不依赖读取 destination 字段，使用 SDK participant identity/SID、许可绑定的公钥及逐条签名进行校验。测试核对发送参数，并以 A/B/C 三参会者联调观察非目标方不接收；部署服务端版本的具体转发行为在 P0 记录。定向路由不替代业务授权，也不作为端到端保密证明。

首期所有输入走同一有序 reliable 通道，移动事件合并到每秒最多 30 次，避免跨 reliable/lossy 通道的移动与点击乱序。每次按钮、滚轮事件自带坐标，先定位再执行。后续只有经拖拽乱序专项验证后才考虑 lossy 移动通道。

LiveKit reliable 属于 best effort，不保证断线期间交付，不在服务端持久缓存。必须有应用层握手、ACK、超时与幂等，禁止重连回放此前输入。

本地 SDK 的 handleDataMessage 串行处理到达包，且在 SDK sequence >0、participantSid 非空时，以 participant SID 保存最近 sequence，丢弃小于等于已接收值的包；这一去重发生在 JS DataReceived 之前。SDK sequence 与本方案 input seq 不是同一个计数，应用无法要求每个重复网络包都进入自己的 ACK 逻辑。单 reliable 通道简化到达顺序，但不保证交付，更不保证应用签名/队列提交正确；应用 seq 用于防重放及拒绝跳号执行，不是补齐丢包的机制。

前向缺口可能来自应用发送/转发缺陷、中间层丢弃或故障注入；只有后续输入到达才可直接发现。若最后一条输入未交付且没有后续事件，则通过输入 ACK 超时发现。§14 在模拟 transport 或测试转发层丢弃一条已签名事件构造确定性缺口，同时单独验证 SDK 自身去重；不以生产中自然复现乱序作为验收前提，也不取消缺口保护。

### 7.2 信封与事件

```json
{
  "v": 1,
  "sessionId": "uuid",
  "epoch": 1,
  "inputGeneration": "opaque-native-generation",
  "shareInstanceId": "uuid",
  "seq": 42,
  "challengeId": "opaque-random-id",
  "type": "pointer.button",
  "body": { "action": "down", "button": "left", "x": 0.42, "y": 0.61 },
  "signature": "base64url-signature"
}
```

签名覆盖除 signature 外的完整规范化信封。建议使用 WebCrypto 与 Windows helper 均可支持的 ECDSA P-256/SHA-256，JSON 按 RFC 8785 规范化；签名编码统一为 64 字节 IEEE P1363 后 base64url，明确禁止混用 DER。实施采用已审查依赖或固定二进制编码，双方必须通过跨语言测试向量；不要自行拼接 JSON 字符串作为签名格式。

2026-10-15 实施选定：高频输入使用固定小端二进制编码，签名覆盖前 640 字节，追加 64 字节 P1363 签名；上方 JSON 仅说明字段语义，不作为实际输入签名格式。布局见 `src/desktop/native/remote-input/protocol.h`，编码器为 `src/desktop/src/remote-control/wire.ts`；已完成 WebCrypto→Windows CNG 验签测试。批准/租约绑定仍使用限制域的规范 JSON（ASCII 对象键、无浮点数、拒绝非良构 Unicode）和独立用途签名。

控制者临时私钥在当前会话内存中持有，浏览器使用不可导出的 CryptoKey，终止后丢弃；B 临时私钥仅主进程/原生执行器持有。公钥在批准前固定，改变即重新申请。能力广播不携带私钥、许可或可复用凭据。

输入、A 的 heartbeat/READY 使用 A 会话密钥签名；B 的 challenge、ACK、READY 和执行状态使用 B 原生会话密钥签名，均包含 sessionId、epoch、递增消息序号及必要绑定。A→B input、A→B signal、B→A signal 分别使用独立序号空间，不能用 heartbeat 序号推进输入 ACK。B 的有效 READY 必须同时具备已验证的许可、采集实例、轨道绑定、安全守护进程就绪及本次 inputGeneration。单纯广播 ACTIVE 或调用转发 IPC 不能激活 helper。

| 事件 | 核心字段与约束 |
| --- | --- |
| `pointer.move` | x/y 为 `[0,1]` 有限数；越界拒绝，不把黑边点击夹到屏幕边缘 |
| `pointer.button` | action 为 down/up；button 为 left/middle/right；自带 x/y |
| `pointer.wheel` | 自带 x/y，归一化离散增量，范围限制；不直接透传浏览器 deltaMode |
| `keyboard.key` | DOM code 白名单、down/up、repeat；原生映射为扫描码，区分左右修饰键 |
| `keyboard.text` | 用户显式提交的 Unicode 文本；每条最多 256 字符且受总字节上限限制 |
| `input.releaseAll` | 释放本会话注入的键/按钮；幂等，不清空无关本地按键 |

未知字段按 schema 策略拒绝；未知事件/版本仅在 §12 所述可识别、已认证的协商上下文中返回 UNSUPPORTED，不响应未知广播或签名失败包。拒绝 NaN、无穷、过深 JSON、无界数组及非法 code。输入包上限 4 KiB，状态包上限 8 KiB；每秒总输入上限初值 120 条，文本每秒最多 4 条。参数属于调优起点，不是测试结论。

只有尚未分配 seq/签名的无状态 pointer.move 可合并或丢弃；分配 seq 后不删除中间事件。任何已进入有序输入流的事件因限流、过期、校验或执行失败而无法处理时，禁止跳过后继续执行：关闭本地门、作废当前输入代次、清队列、释放台账按键并终止会话，报告失败原因。特别是 key-up/button-up 不得静默丢弃或等待下一次网络 releaseAll 才恢复；repeat、文本、滚轮也不得盲目重试。

本机 `closeAndRelease` 为独立高优先级安全路径，可由主进程、helper 或 guardian 触发，不进入普通输入队列、不受网络速率配额限制，也不要求已过期挑战继续有效。它只能关闭及释放，不能恢复或注入 down。网络 releaseAll 仍须校验签名和会话；无效网络包不得触发任意系统输入。

### 7.3 时效、ACK 与防重放

- input seq 在 `(sessionId, epoch, inputGeneration)` 内从 1 连续递增，签名、发送、接收验签、注入均串行提交。仅接受预期的下一个序号；已经执行的重复 seq 只重发 ACK，不能再次执行；出现前向缺口立即关门并终止，不跳号执行。signal 使用其独立序号检测重放；丢失关键捕获状态转换则关门结束，不能以较新普通 heartbeat 代替恢复握手。
- B 每 1 秒发出带原生签名的随机挑战，挑战在 B 单调时钟下 3 秒过期；A 验证后把 challengeId 放入事件和 heartbeat。主进程只接受未过期的已签发挑战。
- 单靠发送端时间戳不能防止排队旧点击；挑战 TTL 为排队操作提供可验证的寿命上界。即便挑战仍有效，发生撤销、暂停、共享源改变或换 epoch 后事件也必须拒绝。
- A 每秒发送独立递增 heartbeat，携带捕获/视频状态并引用有效挑战；B 返回带对应 heartbeat 序号的签名 heartbeat ACK。两端连续 3 秒无有效对端存活响应即关闭门、释放并结束，不依赖有没有输入；原生 helper/guardian 另监控主进程及彼此存活，不能依赖 Renderer 定时器兜底。
- B 在事件通过系统执行后返回 `lastAppliedInputSeq` 累计输入 ACK 与执行状态，建议最多延迟 50 ms 合并一次；它只确认连续成功执行的输入前缀，不能确认跳过或失败的事件。ACK 表示注入 API 已处理，不保证目标应用完成业务动作。heartbeat ACK 不得冒充输入执行 ACK。
- A 仅在存在待确认输入时启动执行超时，以最早未确认事件首次交给 transport 的本地单调时刻计时。累计输入 ACK 推进后移除已确认项，再以剩余最早项原始时刻计时；重复 ACK、普通 heartbeat ACK 不能重置计时。超过 1 秒未确认则停发、请求本机关闭释放并结束会话，不重发点击或文本；重新操作需要重新申请。
- 没有待确认输入时不启动输入 ACK 超时，空闲仅由 heartbeat、租约和视频健康机制管理；正常空闲 60 秒不应误停。输入队列长度/等待时间有界，超过 250 ms 的本地排队目标阈值即关闭门、释放并终止，避免可靠传输拥塞后集中执行。挑战校验在最终注入前再次进行。

## 8. 屏幕、坐标与输入细节

### 8.1 采集源与坐标

B 主进程在原生选择时保留 `desktopCapturer` source 与显示器标识、物理像素区域、缩放因子、旋转方向、共享实例 ID。不能根据 Renderer 传来的任意 display ID 建立可执行绑定。

具体接入现有 main.ts 的 setDisplayMediaRequestHandler：普通共享继续允许 screen/window；远控准备使用主进程保存的、与 request/登录 epoch 绑定的一次性采集意图，只枚举 `types: ["screen"]`，不混入窗口。现有 source.name、slice(0,20) 不能作为类型或身份判断；改为稳定标识与可区分显示器的标签，选择器分页/滚动而非静默截断。只有 screen 源可建立被控绑定；既有窗口源共享须由 B 主动重选整屏。

原生选择成功后、调用采集 callback 前，在主进程注册 pending share_instance_id 并保留 source.id、source.display_id 等原始标识；发布回报后核验同一采集意图和服务端轨道归属再转为已绑定，取消/失败/超时清理 pending。source.id 字符串格式或 display_id 不直接当作 Win32 物理显示器标识。display_binding_hash 对已确认的源标识、映射后的物理区域、方向/DPI 及共享实例规范化后计算，是绑定一致性摘要，不是授权凭据。

P0 实测 source↔Electron Display↔Win32 显示器映射，包括混合窗口源、源数量超过 20、负坐标、混合 DPI 和热插拔。映射缺失/歧义、系统采集权限拒绝、无源、源已消失或轨道发布失败时，远控准备失败且无许可激活；保留已有正常共享或由 B 主动继续普通共享，不静默选择第一块屏幕或窗口。首次采集授权与失败提示按实际平台系统机制验证，不假设 Windows 必定存在 macOS 式录屏权限弹窗。

共享轨道发布成功后由服务端验证归属并将 track SID 与本机实例绑定；采集源到显示器无法无歧义映射时只允许查看。实施阶段重点验证 Electron source display_id、Electron DIP、Win32 物理像素的映射，禁止默认二者相等。

A 根据视频实际显示内容区域计算归一化坐标：

```text
u = (pointerX - contentLeft) / contentWidth
v = (pointerY - contentTop) / contentHeight
physicalX = displayLeft + round(u * (displayPhysicalWidth - 1))
physicalY = displayTop  + round(v * (displayPhysicalHeight - 1))
```

content 区域排除 object-fit 黑边、工具栏和裁剪。首期远控视图强制完整画面 contain 展示；坐标应来自 PointerEvent.clientX/Y 与同坐标系的 DOM rect，不能混用 screenX、CSS 像素与 devicePixelRatio。

Win32 将物理坐标转换为整个虚拟桌面绝对坐标并使用 `MOUSEEVENTF_ABSOLUTE | MOUSEEVENTF_VIRTUALDESK`，支持副屏负坐标。控制范围仍限制在已确认的那块显示器内。热插拔、旋转、分辨率、DPI、采集实例或 track SID 改变立即停止控制，重新绑定并重新申请。

“只控制某块显示器”仅限制指针落点，不是应用沙箱；全局快捷键、焦点变化仍可能影响其他显示器上的应用。批准界面必须说明这一点。若需要严格单应用隔离，应另设计窗口/应用沙箱方案，不能把窗口共享等同于窗口控制隔离。

### 8.2 键盘、中文与焦点

- 快捷键使用物理 key code/扫描码；中文等文本使用 A 的显式文本输入框，通过 Unicode 注入。避免同时发送组合输入的 key 事件与文本，造成重复输入。
- 显式文本框及发送按钮位于本地工具栏，不属于远程键盘捕获区域。进入文本框先按 §6.3 停止键盘捕获并释放远程按键；编辑中的 keydown/keyup、Enter、composition 及发送按钮点击都不得转发为键鼠事件。默认以按钮提交；如提供 Ctrl+Enter 提交，只处理本地命令且忽略 composing 状态下的提交，正文换行由输入框保留。提交仅产生一条 keyboard.text，不追加远程 Enter；需要远程回车时用户另点独立工具按钮。
- 文本编辑期间业务许可不扩大。准备发送时进行一次性显式提交握手：在 B 仍 ACTIVE、视频/许可有效、未本地接管的条件下取得新输入代次，发送文本并等待 ACK，然后再次关闭输入门；不恢复文本框内的持续键盘捕获。若条件已失效保留本地草稿并提示，不排队延后自动发送。重复点击发送在 ACK 前禁用，不因超时重发文本。
- 首期不读取或同步剪贴板；文本输入框明确显示即将发送的内容，由用户提交。密码框是否可注入取决于目标应用，不记录输入内容。
- 操作系统/浏览器保留快捷键可能被 A 本机拦截，界面提供已测试的常用远程组合键按钮；不承诺浏览器能完整透传所有键。
- 禁止发送安全注意序列、提权/锁屏相关首期禁用组合、紧急撤销组合，以及未支持的系统键。操作目标仍由 B 当前前台窗口决定，UI 提示 B 可随时接管。
- 紧急撤销按组合级拦截，不禁用全部 F10。helper 根据远程 pressed set 与当前有效系统修饰键状态，在每个 down 注入前计算组合；任何按键顺序将凑齐候选 Ctrl+Alt+Shift+F10 时，拒绝该 down 并执行 closeAndRelease/结束，防止按 F10 后补修饰键绕过。up 安全释放始终可执行。本地真实输入优先接管；混合物理/注入修饰键与其他注入源导致的误触在 P0 验证，实际系统热键一旦触发也只停止，不允许恢复。该保留组合对远程应用不可用，单独 F10 与其他已测试组合可用。
- down/up、repeat、拖拽和取消维护会话级 pressed set 与独立进程可读的候选按下台账；失焦、断线、撤销和失败都清理。正常释放只处理本会话已注入项；崩溃恢复按 §9.1 处理不确定项，不发送所有系统键的全量 key-up。
- 双击采用顺序 down/up，沿用 B 系统双击设置，不把浏览器 click/dblclick 再发送一遍。

## 9. Electron 与 Windows 原生执行器

建议新增 Windows C++ 输入 helper 与独立 release guardian（Win32 API），随桌面包交付，通过受限继承管道与共享台账通信。helper 的业务通信使用 stdio 长度前缀协议；guardian 不接收远端事件。采用系统输入 API，避免依赖未经验证的通用自动化包，也避免 PowerShell 执行任意字符串。

两个原生进程均不监听 TCP、不暴露本地 HTTP、不执行 shell、不接收脚本或文件路径。主进程只启动包内固定可执行文件，启动验证版本、平台、文件摘要；正式交付纳入签名与安装包完整性校验。构建原生资源的工具链、许可证和 CI 环境在 P0 确定并记录。

建议主进程负责服务访问、原生确认、许可验证与 UI；helper 负责最终会话门、事件验签、challenge/seq、输入白名单、物理屏幕映射、正常键鼠释放；guardian 独立持有执行关闭标志与候选按下台账的读取权，负责输入 helper 故障后的释放。主进程经握手为两个原生进程装载当前会话的受限配置；helper 每次输入前重验当前许可、输入代次、事件时效及 guardian 存活。协议不得包含无会话上下文的裸 `SendInput` 指令。

### 9.1 独立释放兜底与崩溃窗口

guardian 在第一次输入前启动并确认就绪，使用继承的私有句柄绑定主进程、helper 及当前会话台账；台账不经 Renderer、网络或磁盘持久化暴露。guardian 只能发送台账允许集合中的 key-up/button-up，不能发送 down、文本、移动或开启许可。单纯主进程持有 JavaScript pressed set 不构成崩溃兜底。

1. helper 在任何 down 注入前，通过跨进程同步把该键/按钮记入候选台账并提交给 guardian 可见；未提交则禁止调用 SendInput。台账是有界扫描码/按钮集合，按会话和输入代次隔离。
2. down 已由 API 插入输入流后更新执行记录；up 仅在返回数量满足预期且按下述规则确认前后处于同一普通输入桌面时，才从候选集合移除。该记录不证明目标应用完成动作。批量输入返回部分成功时保留所有可能仍按下的候选项，立即关门失败，不假定整批成功。
3. guardian 监测 helper 进程句柄和独立生命信号。发现退出或超时后先设置不可恢复的关闭标志；对仍存活但卡住的 helper 请求终止并等待确认退出，确保不会发生“guardian 释放后 helper 又注入 down”。未确认退出前不得报告清理成功。
4. helper 确认退出后，guardian 对候选台账发送必要 up，检查返回结果，清理成功才记 RELEASED；失败记 RELEASE_FAILED、禁用被控能力，并向 B 明确提示需要本地检查/释放。guardian 不得自动重建活动 helper 或恢复原会话。
5. guardian 故障时，仍存活的 helper 必须先关闭门、按自己的台账释放并退出；guardian 未就绪或失联时不能继续注入。主进程退出时 guardian 先关闭门并监督 helper 退出/释放，最后自己退出；打包/Job Object 配置不得把 guardian 在清理前与主进程一起直接杀死。

因为系统注入与共享内存记录不能组成同一事务，存在“已记录候选 down、尚未实际注入即崩溃”的不确定窗口。故障释放会对保守候选集合发送 up；如果 B 同时物理按住相同键，可能影响该同名按键状态。批准/故障说明应明确本地接管后需松开再按；不得承诺能分别保持远程与物理键的独立系统状态。其他未在台账中的本地按键不释放。

保证范围为正常输入桌面内的单进程故障及主进程退出；操作系统/电源故障、helper 与 guardian 同时被强制终止、切入安全桌面导致释放被系统拒绝时，不能承诺自动释放成功。出现无法确认清理的情况阻止新会话，直到 B 本地检查并重新初始化原生执行器。P0 必须验证候选记录前后、down/up 前后、部分成功、卡住后终止以及主进程退出的故障注入，未通过则不得进入 P1。

SendInput 返回的是成功插入输入流的事件数量，不证明目标应用完成动作；UIPI 阻止时调用失败，但错误信息不能明确区分 UIPI 原因，不写成“UIPI 拦截仍返回成功”。安全桌面/输入桌面切换与注入完成存在竞态：每批输入和清理前后检查桌面代次；任一检查无法确认同一普通桌面，立即关门、作废输入代次并进入 RELEASE_UNCERTAIN，保留候选台账，不因 up 返回数量满足预期就删除台账或报告 RELEASED。已经确认的桌面切换事件本身也使清理确认失效。回到普通桌面后仍需 B 本地检查与受控清理才能重建执行器，不自动恢复授权。正常桌面下 ACK 表示插入 API 已处理，安全桌面不确定状态返回失败状态而非成功累计 ACK。

### 9.2 本地 UI、桥接与生命周期

本地控制条应独立于共享 Renderer 生命周期，目标显示器内固定置顶、提供托盘停止后备入口。远程指针在控制条及原生批准/恢复框命中区域内拒绝执行；保留区域、热键与注入识别一起验证，确保远端无法恢复自己的权限。置顶条与当前窗口权限无法可靠维护时停止控制。

命中测试使用 Win32 物理桌面坐标，以受信 UI 的实际窗口区域及少量安全边距建立保留区；每次鼠标注入前重新核验，不使用 A 视频布局或 Renderer 上报 rect。控制条移动、尺寸/DPI 改变时先关闭输入门再原子更新区域；映射或窗口可见状态无法确认就暂停。保留区内拒绝点击、滚轮及拖拽目标，事件拒绝按状态输入失败规则释放终止；原生同意/恢复 UI 还须隔离远程键盘焦点与提交命令，不能只防鼠标点击。§14 覆盖 UI 移动、DPI 变化、拖拽穿越、Tab/Enter 尝试及迟到输入。

本地真实输入监听只检测交互发生及紧急组合，过滤注入标记，不采集/保存其他程序键入内容。所有监听在会话结束后卸载。锁屏、用户切换、休眠、当前输入桌面改变、输入 API 拒绝或 helper 崩溃均停止控制，不自动恢复。

拟定 preload 最小 API：`capabilities()`、`showRequest(requestId)`、`bindPublishedTrack(bindingRef)`、`forwardSignedMessage(message)`、`stop(reason)`、`onState(listener)`。只有主进程在可信服务读取申请并取得原生用户确认后才能激活；不得提供 Renderer 可直接调用的 `approve=true`、任意坐标点击或任意命令接口。

全部 IPC 校验 sender/frame/origin、参数个数、schema、当前登录 epoch、会议及本机共享实例。登录退出、换号、重载、窗口关闭、render-process-gone、主进程退出均先使许可失效并触发原生 closeAndRelease。helper 父进程 EOF 路径覆盖主进程故障，guardian 路径覆盖 helper 故障；退出顺序须等待清理结果或显式报告无法确认，不能仅依赖 JavaScript finally。

主进程新增专用 `remoteControlCloudRequest`，仅接受枚举动作、经校验的 room/session UUID 和对应 schema 数据，由内部固定模板生成 §6.2 路径与方法；不接收任意 URL、路径片段或请求头。请求固定到受信 service origin，禁止重定向，在取凭据前、发送前及响应后核对登录 epoch。总请求超时上限 8 秒，流式读取响应时执行 2,100,000 字节硬上限；远控可采用更严格的限制，不以 Content-Length 代替实际读取计数。错误只向 Renderer 返回白名单化的稳定 code，未知错误统一映射为通用失败，不返回服务端原始正文、堆栈或凭据。退出/换号后到达的响应不得激活或续租许可。

既有 Work Agent 与远控 helper 相互独立，不借用 Work 执行权限或任务审批。终止会议远控不能终止无关 Work 任务，Work 任务许可也不能激活会议远控。

## 10. 生命周期与故障契约

| 场景 | 必须行为 |
| --- | --- |
| 申请拒绝/取消/过期 | 两端清理待处理 UI；任何迟到 approve/READY 被版本或终态拦截 |
| 原生确认框到期/取消后迟到点击 | 主进程禁用同意、作废本地记录及挑战；不签名/提交，关闭或显示已失效；服务端再次校验终态 |
| B 停止或触发紧急键 | 本地先关闭执行门/清队列/释放并终止，再同步；原会话不可恢复，后续控制须重新申请 |
| B 本地真实输入接管或点击暂停 | 本地先关闭执行门/清队列/释放，进入业务 PAUSED，再同步；仅 B 本地明确恢复可按 §6.3 重签许可 |
| A 结束 | A 先停发与释放；B 收到后本地终止；消息丢失由 heartbeat 兜底 |
| 停止共享/轨道静音/移除/源切换 | 立即终止；新共享不继承旧许可 |
| A 切换聊天/标签页、视图失焦 | CAPTURE_SUSPENDED，B 关闭输入门/释放，按 §6.3 握手恢复；未发新 inputGeneration READY 前不发输入 |
| A 屏幕订阅失败、视频确认不可用 | A 停发，报告 videoReady=false，B 进入业务 PAUSED；恢复需 B 本地确认，不能按普通失焦自助恢复 |
| LiveKit reconnecting/disconnected、A/B 离会 | 立即本地停止；重连需新申请、新密钥、新 epoch |
| 被踢出/房间结束/权限撤销 | 事件驱动终止，并由服务端拒绝后续租约；推送缺失受 15 秒租约上界约束 |
| 服务端不可达/签名未知/续租失败 | 不建立新控制；当前许可最迟到期停止，不靠客户端无限续期 |
| 输入 helper 停止响应/崩溃 | guardian 关门，确认 helper 退出后释放台账；报告 FAILED 或 RELEASE_FAILED，不自动恢复 |
| guardian 停止响应/崩溃 | helper 本地关门并释放退出；守护恢复前禁用被控能力 |
| 状态输入超限、事件缺口/过期/执行失败 | 本地安全路径关门、清队列、释放并终止；不能跳过 up 后继续依赖 heartbeat |
| 正常空闲/待确认输入超时 | 空闲不启动输入 ACK 计时；仅未确认输入超过 1 秒触发失败结束，heartbeat 独立管理 |
| 锁屏/休眠/显示器变化/登录变更 | 本机终止；解锁、唤醒或登录恢复不能激活旧会话 |
| 安全桌面/输入桌面代次不确定 | RELEASE_UNCERTAIN，关门并保留候选台账；普通桌面恢复后 B 本地检查，未确认前不能新授权 |

视频健康依据订阅状态、轨道状态和解码统计判断，不根据“像素没变化”判断静止桌面掉线；阈值通过 P0 测试确定，初值 3 秒无解码进展暂停。首期不保证每个输入与视频帧精确同步，界面显示等待执行/暂停，网络严重拥塞时停止。

本地 PAUSED 是强制执行状态，服务端未及时收到暂停也不能让 helper 继续。CAPTURE_SUSPENDED 则按 §6.3 关闭输入门且保留原业务许可，两者不得混用恢复路径。关闭门后作废 inputGeneration 并清队列，异步任务返回时再次核对代次，避免撤销后排队任务继续运行。

## 11. 权限、审计与组织策略

- 组织功能默认关闭；房间策略可进一步关闭，不能突破组织限制。支持允许被控用户范围、控制者范围、最大时长、访客禁用和紧急关闭。
- 申请限流建议同一控制者/目标 60 秒最多 3 次；B 拒绝后相同连接 60 秒冷却；并发待处理申请有上限，避免原生弹窗轰炸。阈值可配置。
- 审计记录申请、拒绝、同意、暂停、恢复、续租异常、停止与结束原因，关联用户、房间、设备会话、版本及时间。可以记录事件数量/丢弃数量，不记录键值、文本、屏幕截图、密码或完整事件包。

- 会议已有录制仍按原会议规则执行。批准框提示共享画面可能被会议录制；本方案不新增键盘日志或单独录屏。
- 签名许可、公钥绑定、state version 和授权操作审计纳入后端权限测试；签名许可不写普通访问日志。

## 15. 灰度、回滚与运维

默认关闭 → 内部测试组织 → 指定人员/会议 → 小范围组织 → 扩大开放。每步记录服务端、前端、桌面/helper 版本；只有支持版本交集的双方可进入批准流程。灰度监控申请成功率、拒绝/到期、控制建立耗时、异常结束、看门狗触发、队列丢弃与输入 API 错误率，不采集输入内容。

紧急关闭组织/全局开关：停止新申请，拒绝续租，通知活动会话结束；本机收到立即关闭，丢失通知最迟随 15 秒租约失效。保留正常音视频和屏幕共享。桌面紧急停止在服务故障时仍须可用。

上述租约上界适用 §6.2 的正常最终执行门，不承诺撤回已发生的应用动作。原生故障及安全桌面不确定清理分别报告 FAILED/RELEASE_FAILED/RELEASE_UNCERTAIN，按 §9.1 阻断；运维不能仅看到服务端 ENDED 就把本机键鼠清理判为成功。

先部署向后兼容后端，再部署前端与含 helper 的客户端，最后启用白名单。回滚先关闭开关、等待租约清空，再回退业务版本；数据库采用新增表/字段的向后兼容迁移，首次回滚不删审计和会话数据。服务端签名 key 轮换同时保留尚未过期旧 key 的验证窗口，紧急泄露则全部失效并重新申请。

客户端卸载/升级在会话结束后进行，不从远控消息下载或替换 helper。正式安装升级需复验资源摘要、签名、卸载残留及首次运行权限提示。
