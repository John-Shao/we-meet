## 阶段 3 第一批（累计第二十批）：人工修订纪要

已实现 D04 的人工修订部分。行动项转任务将在下一批接入；本批保存不会创建任务或发送通知。

### 交付

- 新增 `MeetingSummaryReview` 和迁移 `0159`，人工稿按记录递增，保留 AI 基础版本、前一人工版本、作者及原文快照关系。AI 重生成不覆盖人工稿，也不会因人工编辑重新触发模型。
- `meeting-records/{id}/human-summary/` 支持当前人工稿读取与显式保存。仅当前会议管理员或独立记录所有者可编辑；仅纪要分享者只能读。写入受 `MEETING_SUMMARY_REVIEW_ENABLED` 与记录开关控制，默认关闭。
- 编辑使用预期修订号和用户请求键；并发修改返回冲突，网络重试返回原保存结果及最新版本。改变 AI 基础版本必须明确选择。
- 引用必须准确匹配基础 AI 版本的原文快照；人工新增可不附引用，但界面明确标注。负责人和日期保持文字描述，不推断用户身份或日期。
- Web 在现有记录纪要页加入摘要、决策、章节、行动项和待确认问题编辑器。草稿不随 AI 刷新覆盖；保存结果不明时冻结该意图并复用请求键；冲突保留草稿，明确指导用户处理。

### 验证与边界

- 隔离 PostgreSQL：7 项测试通过，涵盖不可变性、重新生成、引用隔离、读写权限、撤权重放、请求幂等及双线程并发。
- Web：4 项测试通过，涵盖显式保存、草稿冲突、网络结果不明、只读用户；TypeScript、ESLint、JSON 检查通过。
- 迁移在隔离开发数据库执行；生产部署和浏览器人工体验由用户后续测试。本批不宣称 M3 整体完成。
- 当前 UI 展示最新人工稿，前序版本仍不可变保留；历史人工版本浏览、任务转换、文档和通知将在后续批次补齐。

## 阶段 3 第二批（累计第二十一批）：确认行动项与任务

本批完成新版本纪要的显式任务转换与状态回显，不自动从 AI 名称或模糊日期推断指派。

### 行为与权限

- 最新人工稿的行动项提供“核对并转为任务”，用户确认任务内容、组织内负责人、明确截止日期（可不设置）。只有当前纪要编辑者可转换，记录组织必须与用户当前任务组织一致。
- `meeting-records/{id}/summary-tasks/` 返回当前人工稿的转换状态与可指派成员，支持姓名搜索，每次最多 50 人。请求固定人工版本与行动项索引，版本改变返回冲突。
- 开关 `MEETING_SUMMARY_TASKS_ENABLED` 默认关闭，并依赖记录和人工修订写入开关。关闭后保留已有转换状态读取。
- 新记录使用 `MeetingSummaryTaskLink` 关联已有 Task 模型，复用任务指派、创建历史、通知及读取权限服务。无需把独立录音伪装成 Room，也不把整个纪要、原文或房间名称复制给任务负责人。
- 任务模块是任务状态的唯一来源，纪要直接读取有权查看的任务状态。纪要修订不会覆盖任务，任务编辑也不会回写不可变的人工稿。

### 去重和恢复

- 请求键按用户唯一，所有成功请求（包括复用已有任务）都有持久回执；网络结果不明时 Web 冻结表单并重试原请求。
- 同一记录中去掉首尾空白后完全相同的行动项文字复用一个任务，跨人工版本、重复点击、不同请求键和并发请求均不会重复创建。文字重写视为新候选，仍需用户明确确认；语义相似性不由模型猜测合并。
- 返回“已存在”时明确说明本次表单没有覆盖原任务；已删除任务保留转换回执，不因重新生成或重试自动重建。
- 迁移 `0160`、`0161` 分别创建关联和请求回执。实际任务已创建但通知失败时沿用既有任务通知恢复机制，不重做任务转换。

### 验证

- 隔离数据库 6 项测试：显式确认、原稿不变、相同/冲突请求键、跨修订去重、删除回执、过期版本、错误指派、开关关闭、撤权重放、组织成员与任务读取隔离、并发创建。
- Web 本批 4 项测试及人工稿 4 项回归通过：必须选择负责人、不解析模糊日期、丢响应重试、删除回执、过期人工稿。
- TypeScript、ESLint、Ruff、迁移检查通过。真实 IM 投递、浏览器端操作和生产迁移由用户部署测试；未标记为实测通过。

下一批继续人工历史版本可访问性及会后资料交付链路；独立音频、多人同传频道、Android 对齐等仍按总计划跟踪，M3 尚未整体验收。

## 阶段 3 第三批（累计第二十二批）：人工纪要历史浏览

已保留的人工修订现在可以从纪要页展开浏览。分页每页最多 10 条，按不可变修订号定位；详情显式使用人工版本 ID 与原文快照，历史引用不会跳到最新原文。

- 读取继续检查当前 record 权限，关闭编辑开关不隐藏已有稿件，撤销资料权限则同时禁止最新和历史读取。
- 列表只返回修订元信息，选中后才获取正文；历史稿只读，不能从历史行动项直接转换任务。
- 页面使用用户、记录路径、版本和游标隔离缓存，关闭历史收起正文；访问错误不继续展示查询中的旧正文。
- 新增历史接口测试覆盖 12 个版本分页、非法游标、跨记录版本、关闭开关、只读方法与撤权；人工修订和任务回归共 14 项通过。
- Web 新增 2 项历史测试，与人工稿和任务确认合计 10 项通过；TypeScript、ESLint、Ruff 通过。本批无数据库迁移。

后续资料交付不能照搬旧版自动文档逻辑：现有 Docs `create-for-owner` 客户端未带服务端幂等键，创建后丢响应可能重复建文档。新链路需要上游幂等创建／结果查回契约，或明确进入“结果待确认”而禁止盲目重建；助手通知必须独立去重，并按当前资料权限校验接收者。

## 阶段 3 第四批（累计第二十四批）：记录级问答

实现 D06 的有界单轮问答入口，使用所选纪要版本对应的不可变原文快照，模型为 `MEETING_SUMMARY_MODEL`（默认 `qwen3.8-flash`）。资料页可以选择原文版本、提问、查看结果和按原快照回查引用。

### 约束

- 必须有当前 record 的原文读取权限，仅纪要共享者不能读取未共享原文。问题和答案只对提问者可见，其他资料读者不能读取别人的提问记录。
- 快照严格属于同一记录，后续补录不偷偷混入；每次新请求最多 250,000 字节原文、2,000 字符问题，超限明确失败，不截断后宣称覆盖全场。
- 输出 JSON 校验 answerable、答案、至多 12 条准确原文引用；引用的 ID、修订和时间必须完整匹配。无依据时使用固定空答案状态，不能展示模型附带的猜测。
- 结构和引用检查不等于语义质量证明；长会、冲突观点、专业词和模型遵循率仍需真实评测。当前版本选择来自已生成纪要的原文快照，没有快照时不伪造上下文。
- 一名用户同一时间只能有一个待执行问题；请求先落库，执行再独占认领。SDK 关闭自动重试、请求超时 30 秒、执行截止 90 秒；超时或失败不自动再付费执行，用户明确新请求才再次尝试。
- 网络丢响应时复用原请求键查询同一意图，已开始执行的请求不可被另一个执行器重跑。最近 10 次私人提问可以恢复查看；原文权限或账户状态变更时拒绝提供答案。
- 模型调用前和结果发布前均复核权限；模型错误仅存固定错误码。用现有用量服务按记录问题、提问者和组织归集供应商实际用量，关闭本次 HTTP client。

### 配置与验证

新增默认关闭开关 `MEETING_RECORD_QA_ENABLED`，依赖 `MEETING_RECORDS_ENABLED` 和 DashScope 配置；不要求开启自动总结，不会因打开资料页调用模型。关闭后已有问题仍按当前原文权限读取。

迁移 `0162_record_questions` 新增私人问答意图、固定来源、执行认领和结果。隔离数据库测试：本批 8 项，加旧会中问答访问回归 4 项通过；覆盖并发、重复执行、超时、跨快照／越权、费用重试边界及错误清理。

Web 新增 3 项，与现有纪要页 10 项回归通过；TypeScript、ESLint、Ruff、JSON 和迁移检查通过。真实模型质量和生产运行仍由部署测试核验。

Docs 上游仓库／幂等契约问题已向用户异步询问；此批为不依赖 Docs 的独立进展。后续继续独立录音与资料工作区等计划项。

## 阶段 3 第五批（累计第二十五批）：独立录音的私有音频存储

实现 D01 音频保存的后端基础。每片接收真实单声道 16 kHz PCM16 WAV，最长 10 秒、320,044 字节；校验容器、样本数、SHA-256、顺序及时间重叠，不信任文件名和 MIME。

- 上传前持久化分片身份及私有对象键；相同序号必须保持内容和时间一致。存储成功但响应／数据库确认丢失时，原请求校验已有对象并恢复回执，不生成第二份文件。
- 音频下载经过当前账号、所有权和原文资料权限检查；共享纪要／原文不会自动获得音频权限。不返回桶键和公开 URL，响应禁止缓存。S3 小文件连接／读取超时为 3／10 秒、关闭 SDK 重试，使用 private ACL；这些是单次网络操作限制，不宣称整条请求具有严格总超时。
- 停止后提交最终序号，形成不可修改的封存清单。分别展示已存时长、缺失序号、时间空隙和未验证的覆盖状态；连续确认序号不能跨过缺片。音频清单不代表 ASR 完成或实际声音完整。
- 有音频意图的采集必须先封存才能完成控制状态；封存后不能补写新片。丢失／损坏的已确认对象不会静默覆盖或虚报下载成功。

默认关闭开关 `MEETING_CAPTURE_AUDIO_ENABLED` 依赖记录和独立采集协议开关，当前仅允许保留音频模式。迁移 `0163_capture_audio_storage` 新增分片和封存清单。

隔离库 36 项测试通过（本批 10 项，已有独立采集 26 项），覆盖真实 WAV、错误格式、权限、恢复、缺片、不可变性和状态回显；Ruff、TypeScript、迁移检查通过。尚未连接浏览器麦克风、独立录音 ASR 和播放器，不作为端到端录音已完成验收。下一批接浏览器持久化采集与恢复，并补开关关闭时的安全收尾。

## 阶段 3 第六批（累计第二十六批）：浏览器采集与本地日志

新增独立录音的浏览器底层，尚未作为首页用户入口发布。

- AudioContext 请求 16 kHz，核对真实采样率后由浏览器执行重采样；AudioWorklet 分帧为 5 秒单声道 PCM16。固定大小缓冲区，最多两份未确认音频跨线程传输；主线程持久化后才确认，写入堵塞会停止采集。
- IndexedDB 按登录账号隔离数据库，创建意图、设备租约、序号与音频日志保存在本机。音频内容、下一个序号和本地时长在一个事务提交，写入失败不能留下假序号。待传数据最多 32 MiB，累计至多 4,320 片（正常 5 秒片约 6 小时；频繁暂停产生短片会提前到达片数上限）。
- 收到字段完全匹配的服务器音频回执才释放本地二进制，重复确认不重复扣减待传大小；保留回执元数据。仅当前浏览器本地状态，不宣称跨设备恢复、浏览器缓存永不丢失或崩溃前未提交尾音可恢复。
- 使用 Web Locks 防止同一账号在多个标签页同时持有采集器；不支持 Web Locks／AudioWorklet 的浏览器明确不可用。麦克风需要用户操作和浏览器许可，内部验证使用合成音源。
- 后端开关关闭时允许已存在采集读取、停止、封存与完成，继续检查当前账号和租约；不能开启新采集或上传新音频。关闭开关不把已有录音卡死在停止流程。

验证：后端 37 项采集回归通过；PCM 单元测试 2 项通过，TypeScript、ESLint、Ruff 通过。另用本机 Chromium 的真实 IndexedDB、Web Locks、AudioWorklet 运行 `scripts/check-capture-browser.mjs`，验证刷新重开后的音频、错误回执、事务失败、账号隔离、跨标签排他及合成音源输出；未使用真实麦克风或供应商。

运行浏览器检查：启动 `npm run dev -- --host 127.0.0.1 --port 3187 --strictPort`，再执行 `node scripts/check-capture-browser.mjs`。下一批连接用户入口、控制／上传与恢复界面；独立 ASR 和完整资料页继续推进。

## 阶段 3 第七批（累计第二十七批）：Web 独立录音入口

## 阶段 3 第八批（累计第二十八批）：独立音频回放

录音保存后可直接播放；本机历史记录也能打开回放。支持全局音频位置、暂停／继续、0.75–2 倍速以及缺片提示。

## 阶段 3 第二十七批（累计第 47 批）：仅纪要分享预览与授权后端

新增记录管理者使用的候选接收者、权限预览和明确授权接口。预览与确认分开：确认携带预览摘要和请求 UUID，权限或接收者变化后必须重新预览。

- 范围明确为该记录当前及以后产生的全部纪要版本，包含人工修订；不增加原文、媒体、独立文档权限，也不发送 IM 或邮件。现有原文授权保持原状。
- 组织记录只从对应组织的有效成员选择；个人记录只从共同组织或该会议已知账号选择。参会人入口只列本场实际参与且已绑定账号的用户，重连去重，匿名说话人不猜身份。
- 预览列出原有直接授权、现有有效权限以及确认后的权限；撤销仅移除直接纪要授权。因会议角色或记录所有权仍可读取时明确告知，不把撤销分享冒称为彻底收回访问。
- 每次确认保存不可变回执。同一请求重复提交只返回原回执，即使后来已撤销分享也不会恢复授权。账号、记录、成员关系和现有授权锁定后重新核对；批量上限 50 人。
- 仅管理者可预览/授权或查看分享名单。候选和已有授权分页，缓存禁用。共享读者不能继续扩权；停用或离开组织的旧接收者仍能被管理者撤销。
