# 阶段 2 第七批（累计第十三批）：在线采集控制服务

本批完成 C04 的后端控制契约；Agent 执行器和 Web 按钮继续下一批。新开关 `MEETING_ONLINE_CAPTURE_ENABLED` 默认关闭，不应单独开启本批后端并期望已经能够实际开始／停止采集。

## 已实现

- `GET/POST /api/v1.0/online-captures/control/` 要求 room UUID + 当前 LiveKit SID。开始前可读取控制状态，只有当前组织有效成员中的房间 owner/admin 能启动或结束；公开入会、历史参与和只读分享不授予控制权。
- 开始请求创建同一场次的会议笔记及一次采集运行，预留送达账本。用户幂等键保存原操作结果，返回最新状态；`expected_run_id` 防止旧页面停止新一轮采集。场次锁、记录锁和条件唯一约束保证一个活跃正式写入者。
- Agent 用独立进程 UUID 认领预留账本。后续原文、完成清单和心跳都必须匹配；旧的无账本写入及另开账本不能绕过已经进入新版采集的场次。旧链路已有开放账本时拒绝中途接管。
- 状态为 starting → recording → stopping → stopped / incomplete。停止请求不代表完成；已确认尾段可继续送达，只有通过连续序号及 ASR 观察校验的终态清单才确认结束。不会结束会议或操作云录制。
- 启动行兼作持久投递意图，LiveKit 调用在提交后执行，8 秒超时、15 秒重投间隔；多个投递只能有一个进程认领。既有 15 秒 Celery Beat 调度同时巡视采集。启动 60 秒、心跳 45 秒、停止 120 秒的超时均封存为 incomplete，阻止迟到写入，不能自动重新收费开一轮。
- 回退开关不截断现有运行的原文、心跳和完成上报。权限撤销后心跳要求收尾；自动纪要的旧流程跳过已经采用新版采集的记录。

## 验证

隔离 PostgreSQL 已应用新增迁移 `0157_online_capture_control`，没有生产迁移或部署。采集／送达／内部 API 24 项测试通过；会议笔记、统一记录、版本纪要、自动总结及阶段总结 72 项回归通过；迁移差异检查、变更范围 Ruff 和 diff 检查通过。

测试覆盖并发启动、幂等重放、未生成文字的空笔记、准确场次与控制权限、独占写入、旧写入阻断、停止时尾段、缺失序号拒绝成功、失联封存、迟到旧进程、开关回退、角色撤销、投递超时。LiveKit 投递使用模拟适配器，没有调用付费模型。

## 下一批及实测边界

Agent 必须先消费 dispatch metadata、认领账本并开始心跳，才可以订阅音轨进行转写；心跳停止命令需要驱动真实 drain，网络失联也必须主动关闭 ASR。本批尚未包含这部分执行器，不算完成 C04。

下一批接 Agent 执行及会中按钮，再衔接“记录停止但会议继续”的速记／最终纪要。部署时需同时升级后端与 Agent，再开启对应能力。既有旧 Agent 正在运行的场次保持旧路径直到自然结束，不在中途接管。端到端真实音频、设备、云录制并行以及退出尾段验证由用户部署后执行。
