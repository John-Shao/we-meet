# 阶段 3 第七批（累计第二十七批）：Web 独立录音入口

会议首页新增受开关控制的「录音」入口，地址 `/meeting/recording`。支持命名、开始、暂停、继续、结束保存、本机未完成记录恢复、待传片段下载和缺片结束。当前界面明确只保存音频；独立 ASR 和智能纪要尚未接入，不以占位文字冒充识别结果。

- 录音前先打开用户授权的麦克风，控制成功后才开始收集样本；暂停会释放麦克风。用户离开页面或切换账号时关闭设备、取消当前 HTTP 请求、释放标签页锁；下次打开不会自动开启麦克风。
- 创建键和控制意图先持久化再请求；网络结果未知时复用同一键，CAS 拒绝才解除旧意图。服务端回执可以恢复已存音频的确认，不必重传整个文件；只有逐片字段完全匹配才释放本地音频。
- 上传完成后先封存音频，再完成控制状态。上传失败保留本机片段；用户可明确选择保留缺片状态结束，并逐片下载待传音频，不把这些片段称为完整录音。
- 非正常退出或采集器故障持久化 `client_interrupted`，即使全部已知片段送达，也生成 incomplete 清单。封存参数同样冻结；不能靠重试改变历史完整性。正常暂停后刷新不虚报尾音丢失。
- 页面只列出当前账号此浏览器的本地记录，未接云端全量资料库；清除浏览器数据会丢失尚未上传的音频，这一限制在界面告知。

新增迁移 `0164_capture_audio_interruption`，已在隔离库执行。测试：新增控制器 5 项，PCM 2 项；音频后端 12 项与既有采集协议回归通过；TypeScript、ESLint、Ruff、117 个 JSON 和生产构建通过（6,177 模块，既有 SVG／大包警告仍在）。

原生 Chromium 的 `scripts/check-capture-ui.mjs` 使用合成麦克风及内存 HTTP 服务替身，验证开始、WAV 字节校验、暂停、刷新、回执恢复、封存和完成；布局截图已检查。此项不代替真实后端存储、真实麦克风、网络环境和移动端实测。下一批继续回放与独立转写。
