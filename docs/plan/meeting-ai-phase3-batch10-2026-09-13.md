# 阶段 3 第十批（累计第三十批）：独立音频转写 Worker

新增 `python capture_transcriber.py`，复用现有 Qwen WebSocket 协议，不创建虚拟会议。Worker 只处理已由用户明确创建的任务。

- 领取的清单限定音频格式、总长度、分片数与顺序；每片 WAV 下载后验证 SHA-256、实际帧数及 PCM 参数。每次只保留首片和当前短分片，按 100 ms 帧和音频时长发送。
- 缺片对应独立供应商任务，最终文字映射回各区间原始时间。使用有界文字队列和稳定输入／文字回执，先排空尾句再上报完成。
- 开始请求只尝试一次。丢响应、撤权、取消、进程退出、音频校验失败或文字送达失败均不自动重放。终态回执重试后仍不明时退出进程，旧任务由后端截止时间收敛。
- 供应商时长区分未知、实际零和小数；保留原始回执，费用统计对总秒数向上取整。拒绝 NaN／无穷值。日志只包含任务 ID 和固定错误说明。

使用 Agent 镜像单独运行该命令；配置 `AGENT_BACKEND_API_URL`、内部令牌、DashScope 密钥／workspace、ASR 模型／地区。开发 compose 提供 `capture-asr` profile 和无密钥 `.dist` 示例。后端与 Worker 的模型／地区必须一致，Worker 不会领取其他配置的任务。部署由用户执行。

验证：Agent 78 项测试通过，含新增真实 Qwen 协议封装配合模拟后端的独立转写生命周期；后端转写 12 项通过；Ruff 通过。未调用真实供应商，未做生产长录音吞吐／听写准确率测试。Web 入口下一批连接，目前仍显示只保存音频。
