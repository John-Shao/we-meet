# 阶段 3 第三十二批（累计第 52 批）：共享同传音频 Agent

新增 `src/agents/qwen_interpretation_agent.py`，接通上一批的频道授权与独立发言人音频执行器。

- 以 `SUBSCRIBE_NONE` 入会，认领频道代次后先设置译音轨道的服务端收听 ACL。只订阅授权名单中、参与 SID 一致的标准参与者麦克风，排除屏幕声音及 Agent 输入。
- 每位发言人使用独立的 Qwen 实时翻译会话和译音轨道，16 kHz 单声道输入、24 kHz 单声道输出。握手成功后才开始接收音频并通知轨道就绪；启动期间的内容不承诺转译。
- 输入采用单个有界 FIFO，最多暂存一秒 PCM；超限明确中断整个频道。音频会话失败不自动重连、不重放音频；同一参与记录的麦克风轨道替换或结束后重建也会中断频道，需要显式重新开启。
- 译文逐人定向发送，携带频道、代次、发言人参与记录/SID、译音轨道及接收者订阅 ID/修订号。保留 response/item 标识用于前端去重。单包上限 14,000 字节，超限失败；一位接收者发送失败时取消其余待发送任务，避免遗留后台队列。
- 新收听者或新订阅修订号会收到已有轨道的就绪信息。授权过期、断开或成员种类/SID 不一致时停止输出；断开事件立即更新服务端 ACL。LiveKit ACL 按 identity 生效，本地同时检查具体 SID，Web 仍须以当前连接和订阅修订号校验数据。
- 正常停止只有后端明确授权的听众能收到尾段。权限撤销直接中止待发送输入和输出。完成回执分别记录供应商结束和本地消费完成；本地消费完成不表示远端用户已经听到。任一响应缺少的用量字段保持未知。

验证：15 项运行时测试，加授权、个人翻译控制和 Qwen 协议回归，共 53 项通过；Ruff 与差异检查通过。全部使用模拟音频/网络，没有模型调用或实际会议接入。

部署要求：复用 Agent 镜像，新增独立工作负载，命令为 `python qwen_interpretation_agent.py start`；Agent 和后端配置相同 `ROOM_INTERPRETATION_AGENT_NAME`，并配置现有 LiveKit、内部 Agent 鉴权和 DashScope 环境变量。不要替换原转写 Agent 的启动命令。后端须包含迁移 0170/0171 并运行 Celery worker/beat。

频道开关继续默认关闭。下一批完成 Web 收听与频道控制后，才进入部署联调；多人重叠发言的听感、网络延迟和实际供应商兼容性由真实会议测试验证。完整 M3/M4 及最终技术评审仍未完成。
