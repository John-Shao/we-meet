## 0. 为什么要改

三家控制台价格是动态的，计价维度也不一致：DeepSeek 同一版本分空闲/高峰两价（PC-1），火山缓存存储按"元/百万 tokens/小时"计费（PC-2）。这两条在"单值 `price_version` + cents 账本"里表达不了。继续在 Work 里算钱，等于替三家维护一份永远落后的价表，还要为算错的钱负责。

## 1. 已定事项（2026-10-26）

| # | 事项 | 结论 |
|---|---|---|
| 1 | 费用计算 | **Work 不计算模型费用**。只统计 token；面向客户（企业/组织）的计价规则由我们在 Work 之外自行定义 |
| 2 | 接入账号 | 每个客户组织使用**自己向云厂商申请的账号**，计量与计费由上游云厂商完成；**不设平台兜底账号** |
| 3 | 演示组织 | 系统内单独建一个演示组织，使用我们自己的账号，**只接阿里云 Qwen**；其接入配置**不共享**给任何其它组织 |
| 4 | 凭证形态（方案 i） | 有跨账号角色能力的厂商（阿里云、火山引擎）走客户授权的角色 + STS 短期凭证；无此能力的厂商（DeepSeek）**由平台托管 Key**：加密存储、只写不回读、可即时吊销、变更强审计 |
| 5 | 失控护栏 | **Run 级 token 硬上限**（所有组织）+ 每用户/每组织**周期统计**；客户组织的周期量只告警不阻断，**演示组织的周期量为硬上限** |
| 6 | 用量可见性 | C 端用户可见**自己的** token 用量；组织总量**按模型分列**；两处都标注"仅供参考，以云厂商账单为准" |
| 7 | 管理台写权限 | **扩大 R0a 范围**：组织 owner 可在管理台修改本组织的大模型接入配置，其它角色只读；全部变更强审计 |

## 2. 对外口径修正

此前的表述"我们不会碰客户的接入密钥"在方案 (i) 下不成立（DeepSeek 的 Key 进了平台存储）。对客户、合同与隐私说明统一改为：

> 平台只保存密文，仅模型网关在发起调用的瞬间解密使用；包括平台管理员在内，任何人都没有读取明文的途径。客户可随时在管理台吊销或轮换，吊销立即对新调用生效。

阿里云、火山引擎走 STS 时，平台不长期持有可用凭证，只持有客户授予的角色标识。

## 3. 推荐细则（随本单一起签）

以下是把 §1 落成设计时必须定的参数。签"通过"即按推荐执行；要改就写进"附修订"。

| # | 细则 | 推荐 |
|---|---|---|
| R1 | 每组织生效配置数 | R0a 每组织**一条**生效接入配置（provider + model + endpoint/region + 凭证引用），不做跨厂商自动切换。这同时回答了 C15 单 §8 的权重/失效/会话一致性问题：R0a 不路由 |
| R2 | 跨组织隔离 | 接入配置与组织一对一绑定；网关只能按 Run 所属组织取配置；跨组织引用在**数据层**拒绝（外键 + RLS + 领域命令校验），并有负例冒烟——"不共享"必须可测 |
| R3 | 护栏机制 | 保留现有 reserve/settle/release/adjust 的幂等、单调修订、one-active-reservation 不变量，**单位从 cents 换成 token**：派发前按 `max_tokens` 预留，结算按上游 usage；缺 usage 按预留上界记，不记零 |
| R4 | Run 上限的默认值 | DR1 定数值；推荐 input+output 合计计数，缓存命中单列统计、不计入上限 |
| R5 | 周期统计粒度 | (组织, 用户, provider, model, 自然日)；input / output / cached 三列分存；组织总量与按模型分列都由此聚合 |
| R6 | 读权限 | 用户接口只返回本人数据（跨用户负例测试）；组织按模型分列只对组织管理角色开放 |
| R7 | Key 托管实现 | KMS 信封加密（沿用 D-03 的 CMK/DEK 层级），密钥带版本；接口只回指纹与后四位；日志/trace/错误体有明文不出现的负例测试 |
| R8 | 吊销语义 | 吊销即对新调用生效；在途调用以受控错误结束（不静默换凭证重试）；Run 进入可重投状态，由用户决定 |
| R9 | 管理台写的强审计 | 仅组织 owner；近期重新认证（≤10 分钟）；变更生成版本，可回滚到上一版；审计事件含操作人、组织、时间、旧/新版本号与密钥指纹；变更后通知该组织全部 owner |
| R10 | 配置有效性 | 保存前做一次真实连通探测（最小请求），失败不生效；探测请求计入该组织用量 |

价目快照保留，`usableInLedger: false` 变成永久事实：它是给客户看的成本参考，不是账本输入。

## 5. 风险与已接受代价

- **我们持有客户 DeepSeek 密文**：密钥泄露即客户账单与数据风险。需要密钥泄露应急流程（批量吊销、客户通知时限），并进威胁模型 C11。
- **范围扩大**：管理台写与 [P1-A 计划](org-account-lifecycle-p1a-work-plan-2026-10-24.md)"`write` 不预置给任何内置角色"、[大纲](work-r0a-detailed-design-plan-2026-10-25.md)"管理面只读复用 P1-A"口径冲突，本单即显式扩范围的书面依据（owner 写配置不等于预置 `org.work_grant.write`，两者权限码分开）；E2 工作量增加（配置写/吊销/轮换/探测 + 审计）。
- **客户组织周期只告警不阻断**：Run 级硬上限能截住单个跑飞的 Run，但截不住大量正常 Run 叠加，客户账单仍可能超预期；这由客户在云厂商侧设预算告警承担，接入说明里要写明。
- **证据回退**：§4 所列断言修订后须复跑；复跑前对应计数不得在状态文档中当作目标设计的证据。
