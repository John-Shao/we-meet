# 会议实录：字词级播放跟踪设计

日期：2026-09-23。状态：设计草案，尚未实现、迁移、测试或部署。

范围：后端、Web、Android App。本文是后续实施依据，不代表已具备词级跟踪能力。

## 1. 产品目标与决策

播放音视频时，文字记录中的当前字词随声音高亮，支持点击字词回听。保留现有播放器位置、控制条和标签页布局，音频、展开视频、收起视频使用相同的跟踪行为。

- 用真实的字词时间戳驱动高亮，不按字数平均分配句子时长。
- 首期覆盖新导入音视频的原文；独立录音、线上会议和历史记录分阶段接入。
- 有有效字词时间戳时高亮当前字词；没有时沿用现有段级跟踪。
- 不新增【跟随】开关。保留默认跟踪、手动浏览暂停自动滚动、【回到播放位置】恢复的交互。
- 中文允许识别服务返回单字或词组，不承诺每个高亮单元都符合语言学分词。首期沿用上游时间单元，不再用分词算法拆分后猜测时间。
- 先保证同步和可读性，不改成长段落、不重组说话人、不调整页面布局。

## 2. 当前代码基础与缺口

以下为本次设计时核查的本地代码，不代表所有线上记录的数据形态。

| 环节 | 当前情况 | 需要补充 |
|---|---|---|
| 文件识别 | `qwen_filetrans.py` 使用 `qwen-audio-3.0-asr-flash-filetrans`；`sentences()` 只提取句级时间与文本 | 校验并保留 `sentences[].words[]` |
| 导入发布 | `uploaded_recordings.finish()` 写入 `MeetingOriginalSegment` | 同一事务写入字词映射 |
| 原文模型 | `MeetingOriginalSegment` 有 `text/start_ms/end_ms`，没有字词映射 | 可空、版本化的映射字段 |
| 原文 API | `meeting_records.py` 返回有效文本、原文及修订版本 | 只返回与当前有效文本匹配的字词映射 |
| Web | `transcriptSync.ts` 按段时间区间确定活动行；已有分页定位和跟踪暂停机制 | 段内字词定位、文本范围渲染和更细的本地播放时钟 |
| Android | `RecordOriginals.kt` 按段跟踪；`RecordOriginalSegmentDto` 无字词数据；整文件播放器位置轮询为 250 ms | 扩展 DTO、文本范围渲染和播放位置采样 |

仓库另有 `src/summary/summary/core/file_transcription.py` 解析 `WordSegment`，但属于另一条处理链，不能据此认为会议实录已经保存了字词时间。

官方文档说明 Qwen-Audio-3.x 文件转写支持句级与字词级时间戳，`words[]` 含毫秒单位的 `begin_time/end_time/text`。该能力为接入基础；实施前仍须验证当前配置实际返回的数据，尤其是中文、英文及中英混合内容。

参考：[阿里云非实时语音识别文档，“获取时间戳”](https://help.aliyun.com/zh/model-studio/non-realtime-speech-recognition-user-guide)。核查日期：2026-09-23。

## 3. 用户交互

### 3.1 高亮与视觉

- 当前字词使用主题强调色底、对比色文字；Web 与 App 语义一致，深色模式使用对应主题色。
- 字体、字重、行高和字间距保持不变，高亮切换不改变文本排版。
- 有字词高亮时，原有整段大面积底色改为轻量段落定位标记，避免两层强高亮竞争；降级时保留现有段级样式。
- 标点和空白按原文显示，不制造单独播放区间；不在模型无时间数据的静音区间继续亮着上一个词。
- 暂停时保留实际播放位置对应的高亮；播放结束或落在词间间隔时清除词级高亮。段落滚动锚点可以保留。
- 搜索命中仍可辨认：当前播放词优先使用播放底色，重叠的搜索命中使用下划线等辅助标记，不能相互覆盖。

### 3.2 跟踪与手动浏览

- 默认自动跟踪；当前字词仍在文字区域的安全可视范围内时不滚动。
- 当前字词离开可视范围才进行最小必要滚动。可视范围需扣除固定工具栏、键盘和覆盖层。
- 对一段跨多屏的长文本，应定位当前词所在行，而不是反复对齐段落顶部。
- 用户手动滚动、选择文字、搜索或编辑时暂停自动滚动；正在显示的文本仍可以更新播放高亮。
- 【回到播放位置】恢复跟踪并定位当前词；无词级数据时定位当前段。搜索等状态按既有恢复规则处理。
- 恢复或跨页跳转只发起一次必要的时间窗口查询；高频字词更新不能触发高频网络请求。

### 3.3 点击与拖动

- 点击有效字词：调用现有 seek 通路，跳到该词 `start_ms`，恢复跟踪；保持点击前的播放／暂停状态，不新增自动播放行为。
- 点击标点、空白或未对齐文本不触发词级 seek；段落时间戳仍是稳定的回听入口。
- 拖选／长按选择文本、编辑文本时不触发 seek，保留复制和编辑能力。
- 拖动播放器进度条时允许预览候选字词，但不自动滚动正文；松手后等待播放器报告实际落点，再更新跟踪。
- 前进／后退、倍速、音视频收起／展开、全屏切换共用同一媒体时钟，不重建字词映射。
- 无播放权限、媒体不存在或读取失败时，保留原文阅读，不显示可用的词级回听操作。

## 4. 数据契约

### 4.1 存储方案

首期在 `MeetingOriginalSegment` 新增可空 JSON 字段 `word_alignment`，旧数据为 `null`，不立即建立独立词表。逐段读取与现有原文分页相适配，避免每词一行导致写入和查询膨胀。

同时拟新增 `alignment_revision`（非负整数，旧数据为 0）及 `alignment_status`（`missing/available/invalid`，旧数据为 `missing`）。字词校验失败保存 `invalid`，映射为 `null`；未提供字词保存 `missing`。`text_changed` 是读取有效文本时计算出的 API 状态，不写回原文状态。映射成功写入或替换时递增版本，状态和映射原子更新。

以下字段是拟议契约，不是当前接口字段：

```json
{
  "version": 1,
  "provider": "qwen-audio-3.0-asr-flash-filetrans",
  "time_basis": "segment_source",
  "offset_unit": "utf16",
  "text_sha256": "<原始 text 的 UTF-8 SHA-256>",
  "tokens": [
    { "start_offset": 0, "end_offset": 2, "start_ms": 100, "end_ms": 500 },
    { "start_offset": 2, "end_offset": 3, "start_ms": 500, "end_ms": 700 },
    { "start_offset": 3, "end_offset": 5, "start_ms": 800, "end_ms": 1200 }
  ]
}
```

示例原文为“我们来开会。”，三个单元为“我们”“来”“开会”，句号没有独立时间。

- 字符范围和时间范围均为左闭右开 `[start, end)`。
- `segment_source` 表示与该段 `start_ms/end_ms` 相同的源时间轴，不是从段首重新计时。上传件从文件起点计时；采集来源从所属会话起点计时。
- 文本偏移统一使用 UTF-16 code unit，匹配 JavaScript 字符串和 Kotlin 字符串索引。Python 需显式转换，不能直接使用 Python 字符索引。
- 任何范围不得切断代理对或用户可见的组合字符；边界无法安全映射则该段降级。
- 用范围引用原文，不另外复制 token 文本，避免两个文本版本发生分歧；单元身份使用 `segment_id + alignment_revision + token_index`。
- `text_sha256` 基于完整原文，不做隐式 Unicode 规范化、空白折叠或大小写转换。
- 首次导入映射版本为 1；后续回填另加 `alignment_revision` 单调递增，缓存键包含此版本。回填不改变原文身份，不替换用户修订。

### 4.2 解析与校验

1. 句级内容仍走现有校验与发布流程。字词属于增强数据，错误不能让原本合法的全文转写失败。
2. 每个字词时间必须是非负整数，`start_ms < end_ms`，位于该段和有效媒体时间范围内；同段内按时间递增，不接受词区间重叠。
3. 文本范围必须在原文内、递增且不重叠。使用顺序游标匹配上游 `text` 和 `punctuation`，禁止对每个词从全文开头搜索，避免“我们……我们……”匹配错位。
4. 只允许跳过可解释的标点／空白。未映射的实质文字、识别服务改写、文本顺序矛盾或边界歧义，都使整段映射失效；不输出看似准确的局部拼凑结果。
5. 上游标点附在词文本末尾时，解析器可以剥离明确的尾随标点并保留原文范围。不得改变显示原文或拆分一个无内部时间的词组。
6. 无 `words`、零长度时间、非法偏移等情况，保存句级结果并记录固定原因码；不静默补齐猜测值。
7. 增强数据设置上限：拟定每段最多 10,000 单元、每段序列化 JSON 最多 1 MiB。超限整段降级；最终数值在样本评估时确认。现有文件结果和全文大小限制继续生效。
8. 映射与段落在同一发布事务提交。后续录音接入时，幂等校验须包含规范化后的映射，避免重试覆盖不同结果。

### 4.3 API 与兼容

在现有原文分页响应的每段追加可选 `playback_alignment`，不新增逐词请求：

```json
{
  "playback_alignment": {
    "status": "available",
    "version": 1,
    "alignment_revision": 1,
    "text_sha256": "<当前有效 text 的 UTF-8 SHA-256>",
    "time_basis": "segment_source",
    "offset_unit": "utf16",
    "tokens": []
  }
}
```

上例仅展示响应字段；真实 `available` 必须带至少一个通过校验的单元，不能以空数组标记可用。

| 状态 | 意义 | 客户端行为 |
|---|---|---|
| `available` | 映射与当前有效文本匹配 | 字词高亮、词级 seek |
| `missing` | 历史记录或上游未提供 | 段级跟踪 |
| `text_changed` | 有效文本与映射文本不一致 | 段级跟踪 |
| `invalid` | 映射校验失败或超限 | 段级跟踪 |
| 字段缺失／未知版本 | 老服务端或暂不支持 | 段级跟踪 |

非 `available` 响应不下发 tokens。内部 provider 信息不作为客户端逻辑判断依据。

接口遵循原有原文读取权限与缓存策略，不因增加字词数据扩大媒体播放权限。高亮与 seek 仍需满足原有媒体可用条件。旧客户端忽略新增字段；新客户端对缺字段、未知状态和非法结构均安全降级。

## 5. 修订、翻译与历史记录

- **人工修订／批量替换**：映射绑定原始文本。当前有效文本不完全一致时，受影响段返回 `text_changed`，不沿用旧偏移；其他段继续词级跟踪。
- **恢复原文**：当前文本重新与映射文本完全一致且映射合法时，可以恢复词级跟踪。仅修改说话人名称不使字词映射失效。
- **缓存失效**：修订响应到达后立即清除该段词级高亮，按原有修订流程刷新数据；不能等待下一次播放才校验文本。
- **译文**：首期不提供词级跟踪，继续按原文段落关联；原文的词序和词长不能直接套用译文。
- **冻结快照**：首期保持已有行为；后续支持时必须冻结文本及其映射版本，不能用当前原文映射驱动历史快照。
- **历史记录**：默认段级回退，不在打开页面时自动重转写。先评估是否仍有合法可用的原始识别结果；没有则需重新转写或对保存的音频与既有文本进行强制对齐。
- **回填任务**：后续独立设计，明确成本、可取消性和源版本校验。不得覆盖用户修订；媒体已删除时不能生成可靠的新对齐结果。

## 6. 播放时钟与定位

数据流：识别字词 → 校验及原文范围映射 → 段落存储 → 分页 API → 播放器源时钟 → 活动段／活动词 → 局部高亮及必要滚动。

- 播放器是时间唯一来源，不用网络响应时间、系统墙钟或动画累计时长模拟播放位置。
- Web 播放期间通过 `requestAnimationFrame` 读取媒体 `currentTime`，仅在活动词或必要显示状态变化时更新文本；`timeupdate` 保留作状态兜底。后台暂停高频采样，回到前台立即重读。
- Android 在页面可见且正在播放时，拟采用 50 ms 的本地位置采样；使用播放器实际位置，暂停、缓冲和后台时停止高频更新。通过真实设备验证频率与功耗后定值。
- 采集音频和上传件使用各自的源时钟适配器。未来接入多片段媒体时先完成源时间映射，不直接把拼接播放时间套到原文时间上。
- 切换记录、识别代次或播放源时清空活动词和旧映射缓存。异步 seek 完成及缓冲恢复后，以新报告的实际位置重新定位。
- 在当前原文窗口中确定活动段，再对合法有序的字词时间做二分定位；时间必须落在 `[start_ms, end_ms)` 内才高亮。
- 词间空白和音频缺口不高亮相邻词。无效数据不进入二分索引。
- 同一播放源的多段时间重叠时，首期沿用现有段选择规则（已开始的最近段，等时按稳定段顺序），最多突出一个词；多说话人同时高亮留待线上会议阶段设计。
- 倍速直接读取播放器媒体时间，不再次乘倍速。seek 的真实落点可能受媒体格式限制，不承诺点击后每次都精确到毫秒。

## 7. 两端实现边界（供后续实施）

### Web

- 扩展原文响应类型及 `transcriptSync.ts`，保留已有跟踪暂停和分页定位职责。
- 复用当前段落原文渲染入口，以文本范围生成内联高亮；避免为整份逐字稿的每一个字都建立常驻 DOM 或独立定时器。
- 活动词测量与滚动在布局完成后进行，搜索标记、换行、窗口缩放后重新计算。
- 保留正常文本选择。读屏按句／段阅读，不能把每个词变成独立 Tab 焦点或持续播报高亮变化；段落时间戳保留键盘可操作入口。

### Android

- 扩展 `MeetingRecordDtos.kt`，新增独立的字词定位逻辑，与 `TranscriptSync.kt` 段级规则组合。
- `RecordOriginals.kt` 使用同一原文的 `AnnotatedString` 范围样式，结合文字布局结果做点击命中和当前行可见性判断。
- 仅活动段随词变化重绘，避免每 50 ms 重组整页、重新分页或重新测量所有段落。
- 保持选择、复制、TalkBack 段落语义和现有回听入口。词本身可能小于触控目标，禁止为了增加点击热区扩大到邻词；手势歧义时不执行 seek。
- 新视觉使用现有主题 token，验证深色主题、大字体和小屏换行。

## 8. 验收方案

以下均是计划指标，并非已通过的测试结果。

### 8.1 数据与自动化

- 中英文、混合语言、重复词、连续标点、空格、emoji、组合字符的文本范围都能准确还原原文。
- 字词开始／结束边界、静音、缺口、非法时间、重叠、缺字段、未知版本、超限数据行为确定。
- 修订、批量替换、恢复原文、仅改说话人、重转写切换代次后，高亮不引用旧文本。
- 新旧服务端／客户端组合均可阅读和段级回放；字词校验失败不阻止合法句级结果发布。
- 分页窗口切换、跨页 seek、快速连续 seek、长段落多屏跟踪、手动浏览暂停与恢复均稳定。
- 音频、展开视频、收起视频、全屏、0.5×／1×／2×、暂停、缓冲、结束及后台恢复行为一致。
- 权限不足、媒体清理或加载失败时，不产生可执行的词级媒体请求。

### 8.2 同步精度与性能

- 分开评估“上游时间戳与实际语音的误差”和“客户端按时间戳渲染的延迟”，两者不能混为同一指标。
- 受控播放 fixture 下，两端高亮相对播放器时钟的更新延迟目标为 P95 ≤ 100 ms；seek 稳定后不得残留旧词。
- 真实样本至少覆盖中文、英文、中英混合、快语速、背景噪音、长静音；人工标注不少于 100 个边界，报告中位误差、P95 和明显错位比例。建议初始发布门槛为 P95 ≤ 300 ms，样本验证后确认，不把该目标当作模型保证。
- 若样本表明某来源无法达到可接受精度，则该来源继续段级跟踪，而不是用 UI 动画掩盖误差。
- 用长记录验证原文窗口响应大小、内存、滚动流畅度与 Android 功耗。不得全量下载整场字词或按播放 tick 请求 API。
- 页面宽度、字体缩放及高亮切换不导致文本跳行；手动阅读期间没有自动滚动抢占。

## 9. 分阶段实施与回退

| 阶段 | 交付内容 | 进入下一阶段的条件 |
|---|---|---|
| P0 样本验证 | 当前千问配置真实返回样本、文本映射原型、误差与数据体积评估 | 确认时间单元、标点规则及精度可用 |
| P1 后端契约 | 可空字段迁移、导入解析与原子发布、API 投影和校验测试 | 旧客户端兼容，失败安全降级 |
