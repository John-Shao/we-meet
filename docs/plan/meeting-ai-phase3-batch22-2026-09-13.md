# 阶段 3 第二十二批（累计第 42 批）：纪要助手的 IM 去重前置能力

走查发现现有 IM 管理消息接口不支持幂等写入。本地通知账本不足以解决“消息已提交、HTTP 回执丢失”，因此先在同级 `jusi-light-im` 仓库实现持久化回执，再接通知。

- 新增专用 `/admin/messages/idempotent` 与只读 `/admin/messages/receipt`，沿用 HMAC 鉴权和 nonce 防重放，拒绝旧接口降级。
- 数据库事务一起写消息与回执；相同发送者和请求标识只写一次，改变内容或目的会话返回冲突。
- 仅首次写入触发会话恢复显示、广播与离线推送。事务提交后进程崩溃仍可能漏掉实时推送，但消息可在历史中找回；不宣称推送 exactly-once。
- 新建时将发送者成员身份锁定到提交，不降级 SYSTEM。撤回消息、删除消息或整个会话后保留不可用回执，不重新发出。

验证：6 项 PostgreSQL 场景（含并发、回滚、删除、锁占用），3 项新增管理 API 场景及全部现有管理 API 测试通过；go vet 与差异检查通过。数据库由 Testcontainers 隔离，未发送真实消息。

部署前置：先发布包含 `011_admin_message_receipts.sql` 的 IM 服务。Meet 通知客户端、持久化通知任务、页面状态与助手卡片后续接入。此次没有开启任何真实通知开关。
