# 阶段 3 第十四批（累计第 34 批）：统一资料库查询

记录列表和详情新增 `is_ongoing`、`has_summary`、`capture_id`，仍以唯一记录 ID 作为资料身份。列表支持严格布尔筛选 `is_ongoing=true|false`、`has_summary=true|false`，与现有来源、权限范围、标题搜索组合使用。

- 进行中与归档可独立分页，旧的暂停录音不会被新归档挤出；保留时间与 ID 排序，避免布尔排序导致游标偏移上限问题。
- 纪要存在性通过 EXISTS 判断，不因多版本生成重复记录；旧纪要须成功且严格归属当前会议场次和房间。仅逐字稿权限不能通过筛选获知纪要存在性。
- 独立录音只向当前所有者提供精确、唯一的采集 ID。多个历史采集不猜测最新一份；设备租约、设备标识、音频地址不进入资料库响应。
- 当前 ACL 在筛选、分页前执行，列表与详情继续 `private, no-store`。批量预取限定字段，查询数量不随页面条数增长。

验证：新增 6 项与原记录回归 25 项，共 31 项通过（隔离 PostgreSQL）。覆盖跨账号、撤权、进行中与归档互斥、31 条两页、筛选校验、共享纪要权限和固定查询数量。无迁移、无模型或外部服务调用。下一批连接 Web 资料库与独立记录工作区。
