# 阶段 2 第九批（累计第十五批）：记录结束边界与参会提示

本批补齐“结束文字记录但会议继续”的总结时机，以及所有参会者可见的采集提示。仍未进行生产部署或真实音频验收。

## 完成内容

- stop 请求进入 stopping 后，允许针对已收到原文生成速记；送达账本封存前不允许 managed capture 生成最终纪要，即使关闭阶段总结开关也不能绕过。stopped/incomplete 后可基于已保存材料生成完整结构的纪要，并继续保留覆盖范围未验证或送达不完整提示。
- 每个新总结任务固定当前 capture run ID。再次开始记录会取消上一轮排队或运行中的旧总结，防止旧草稿跨新一轮发布；已经发布的历史版本保留，同场笔记不重复创建。
- 自动总结按当前记录运行识别速记版本。修复“第一轮已有最终纪要，第二轮停止时没有新速记”的边界；每轮仍须具备已有明确自动总结授权，开始采集本身不自动开启总结。
- 新增只读 `GET /api/v1.0/meeting-capture-status/`，要求有效 LiveKit room-join token 和准确 room/SID，只返回当前活动场次的状态字段。匿名参会者可获知是否在记录，但不能由此读取原文、纪要、run ID 或控制录制；历史场次不对该接口开放。
- 会中增加独立文字记录状态提示，断线后清除当前 SID；已观察到记录开启而状态查询失败时显示“无法确认”，不谎称已停止。与现有云录制提示分开显示。
- 新增开始操作限流，每用户 6 次/分钟，不限制结束操作；成功认领后清除此前投递失败提示。
