# 会议 AI 阶段 2：第五批（累计第十一批）

日期：2026-09-13。基线：`ee1abec3`。实现 C03 长会输入预算与可复用分段提炼。

## 处理方式

- 默认保持原单次生成预算；开启 MEETING_SUMMARY_CHUNKING_ENABLED 后，完整来源上限为 1,500,000 UTF-8 字节。单次输入不超过 250,000 字节的短会仍只调用一次。
- 更长来源按完整原文段落顺序分组，每组最多 64,000 UTF-8 字节、最多 32 组。不会截掉开头、跳过尾段或拆出虚构引用。单条过长、总量或分组数超过预算时，在创建任务前明确拒绝，原文保留；页面和自动控制状态显示来源预算问题。
- 每组提炼限制 1536 输出 tokens / 7000 序列化 UTF-8 字节；所有组提炼结果共同进入最终汇总，汇总输入最多 250,000 字节，输出保持实时/速记 4096、会后 8192 tokens。以上是本应用的保守预算，不是对供应商模型最大能力的声明。
- 组内提炼不包含阶段指令，按记录、精确源内容、模型、endpoint 和提炼 prompt 版本缓存。相同内容可以在实时/速记/会后和失败重试间复用，重新生成仍重新执行汇总。不同记录不共享缓存。
- 原文追加导致快照 revision 变化时，复用组的引用重新绑定到新快照；原文/说话人/语言/时间变化则该组缓存失效。所有组输出和汇总引用仍经严格校验，汇总不能引用未出现在提炼输入中的源 ID。
- 每段调用前、保存缓存前和最终发布前检查当前任务 attempt/generation、来源及权限/自动开关。段间写入工作者心跳，避免长会在持续工作时被误判为超时；前端可见已提炼进度。
- 版本纪要客户端关闭 SDK 隐式重试，失败由既有显式 attempt 恢复；生成响应必须以 stop 正常结束，不能把 length/content_filter 结束但恰好合法的 JSON 当作完成。其他 LLM 调用保留原默认行为。
