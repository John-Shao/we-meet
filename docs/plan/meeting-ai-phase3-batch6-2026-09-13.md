# 阶段 3 第六批（累计第二十六批）：浏览器采集与本地日志

新增独立录音的浏览器底层，尚未作为首页用户入口发布。

- AudioContext 请求 16 kHz，核对真实采样率后由浏览器执行重采样；AudioWorklet 分帧为 5 秒单声道 PCM16。固定大小缓冲区，最多两份未确认音频跨线程传输；主线程持久化后才确认，写入堵塞会停止采集。
- IndexedDB 按登录账号隔离数据库，创建意图、设备租约、序号与音频日志保存在本机。音频内容、下一个序号和本地时长在一个事务提交，写入失败不能留下假序号。待传数据最多 32 MiB，累计至多 4,320 片（正常 5 秒片约 6 小时；频繁暂停产生短片会提前到达片数上限）。
- 收到字段完全匹配的服务器音频回执才释放本地二进制，重复确认不重复扣减待传大小；保留回执元数据。仅当前浏览器本地状态，不宣称跨设备恢复、浏览器缓存永不丢失或崩溃前未提交尾音可恢复。
- 使用 Web Locks 防止同一账号在多个标签页同时持有采集器；不支持 Web Locks／AudioWorklet 的浏览器明确不可用。麦克风需要用户操作和浏览器许可，内部验证使用合成音源。
- 后端开关关闭时允许已存在采集读取、停止、封存与完成，继续检查当前账号和租约；不能开启新采集或上传新音频。关闭开关不把已有录音卡死在停止流程。

验证：后端 37 项采集回归通过；PCM 单元测试 2 项通过，TypeScript、ESLint、Ruff 通过。另用本机 Chromium 的真实 IndexedDB、Web Locks、AudioWorklet 运行 `scripts/check-capture-browser.mjs`，验证刷新重开后的音频、错误回执、事务失败、账号隔离、跨标签排他及合成音源输出；未使用真实麦克风或供应商。

运行浏览器检查：启动 `npm run dev -- --host 127.0.0.1 --port 3187 --strictPort`，再执行 `node scripts/check-capture-browser.mjs`。下一批连接用户入口、控制／上传与恢复界面；独立 ASR 和完整资料页继续推进。
