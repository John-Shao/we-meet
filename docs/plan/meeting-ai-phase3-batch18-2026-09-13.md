# 阶段 3 第十八批（累计第 38 批）：严格 Docs 交付客户端

新增 `DocsDeliveryClient`，与旧版 Docs 客户端分开，供后续版本化纪要交付使用。调用者必须持久保存请求键、所有者和完整请求内容；客户端不负责生成请求键或自动重试。

- 只调用专用 `create-for-owner-idempotent` 与结果查询路径。技术走查发现旧服务会忽略新请求头，因此在 Docs 仓库增加专用路径（`docs-dev` 已推送 `bf2a0636`），防止新旧副本混跑时旧接口创建没有回执的文档。
- 严格匹配 HTTP 状态与回执状态；通用 404、只返回 ID 的旧响应、非法 UUID、错误重放标志均不能作为成功或未创建依据。
- 保留 `processing`、`not_found`、`conflict`、`unavailable` 的差别；网络错误属于结果可能未知，调用者应查询原请求，不能更换键重建。
- 禁止重定向和自动重试，设置连接/读取超时，响应流最多 32 KiB。异常只保留固定分类，不记录 token、原始响应或纪要内容。这些是连接和单次读取超时，不宣称总耗时上限。

验证：客户端 28 项通过；Docs 新增专用路由后共 9 项回执测试通过；Ruff 与差异检查通过。所有网络使用测试替身，未向真实 Docs 创建文档或发送消息。

部署顺序：Docs 0037 迁移与 `bf2a0636` 或更新版本先部署。Meet 持久化导出任务、页面入口与纪要助手通知仍待后续批次实现；当前客户端尚未连接生产业务路径。
