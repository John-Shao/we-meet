# 阶段 3 第二十批（累计第 40 批）：Docs 后台交付与结果恢复

纪要导出请求提交数据库后进入 Celery，已有 15 秒周期任务补发丢失的队列消息。每轮最多派发 20 项；排队任务至少间隔 30 秒，结果未知的任务至少间隔 5 分钟查询。接口不会通过同步任务降级调用 Docs。

- 首次交付先查询固定请求标识的结果；只有明确未创建且权限、配置和冻结内容仍有效时才提交文档。
- POST 超时保留未知状态，自动恢复只查询原请求；明确重试仍使用同一 Docs 请求标识和冻结内容。不会重建已删除、已转移或已经完成的文档。
- 工作任务使用版本、随机工作者标识和 90 秒写回期限。过期任务失去提交结果权限；连接和读取超时不等于网络总耗时保证。
- 开关关闭或成员权限变化会阻止新建，已经可能发出的请求仍可只读核对回执。Docs 文档是用户确认创建的独立副本，会议权限变化不隐式删除它。
- 新增原导出内容预览与显式重试接口，校验尝试次数和预览哈希；最多 20 次人工重试，内容冲突不允许重试。Docs 地址变化必须恢复原配置后再处理，不能悄悄切换目的服务。

验证：后台交付 24 项测试通过；预览/请求 9 项与严格客户端 28 项回归通过。Django 系统检查、Ruff、差异检查通过。网络、队列用替身验证，数据库并发使用隔离 PostgreSQL；未向真实 Docs 写入。

部署：需要 Docs `bf2a0636` 或更新版本及迁移 0037、Meet 迁移 0166、Celery worker 与 beat。新增任务模块已纳入任务自动发现。页面入口下一批接入，暂保持 `MEETING_SUMMARY_EXPORT_ENABLED=false`。
