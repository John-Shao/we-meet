## 已修复的问题

| 问题 | 影响 | 修复和证据 |
| --- | --- | --- |
| P1：写入／完成回执没有直接检查停止截止时间 | 定时清理前，仍保活的迟到 Agent 可能将超时采集标为成功 | `require_writer` 对活动运行检查停止截止时间；迟到转写、完成、心跳均拒绝，清理结果为 incomplete；新增专门回归 |
| P1：旧会中问答按房间收集全部转写 | 同房间不同场次混读，加入会议的访客也可能调用资料问答 | 固定一场活动 session；只读该场次转写，排除历史和未归属行；加入令牌之外检查当前资料权限；同步响应前、每个流事件产生前后复核权限 |
| P2：问答切换场次后旧流仍可更新本地会话 | 显示旧答案、混入后续提问历史 | Web 按房间、token、实际 LiveKit SID 清空并中止流；旧请求即使继续 yield 也不会更新新会话；新增 2 项测试 |
| P2：模型错误原文直接进入客户端 | 供应商响应细节可能被展示 | 同步和流式问答统一返回固定错误；单独显示会议资料访问提示 |
| P2：内部 Agent 共享令牌普通字符串比较 | 鉴权比较实现不符合密钥比较惯例 | 改用 Django `constant_time_compare`，缺失／错误令牌保持拒绝 |

新资料问答权限是有意收紧：当前资料不可用、未登录、仅加入会议、权限撤销、场次结束时，不返回已落库转写。旧接口仍保留原有模型配置和最近上下文预算；这次修复不是 D06 的完整记录问答实现。

## 其他走查结果

- 采集停止不结束会议；Agent 认领、心跳和最终账本区分真实成功／不完整。原文转写、翻译和人工稿没有互相写回路径。
- 翻译的房间 SID、来源参与设备、运行代次、worker 和私有目的身份均有服务端约束，前端也检查发送 Agent 和代次。当前仅本人麦克风私人翻译，不应以多人同传对外验收。
- 人工稿不可变追加，基础 AI 版本与原文快照明确；历史只读且重查当前权限。任务转换以用户明确选择为准；请求回执与记录内相同文字去重，删除任务不自动重建。
- 任务的可见性仍由现有任务权限决定；转换关联不会给任务负责人授予整份会议资料权限。负责人及模糊日期不会由模型名称自动变成用户 ID／日期。
- 新文档交付不能直接复用旧版失败重建策略：本仓库 Docs 创建客户端未携带上游幂等键。需查明上游代码契约后补全；此项保持待解决依赖。
