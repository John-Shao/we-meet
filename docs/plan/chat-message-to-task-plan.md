# 聊天消息转任务实施计划

> 状态：已完成（2026-09-05）
> 首版目标：用户从一条文本消息创建任务；消息正文进入任务描述，任务标题由用户填写；任务保留可审计、可回溯的消息来源，并默认把任务卡片发送回当前会话。

## 1. 产品原则

1. **消息提供上下文，用户定义行动结果**：不把整条消息直接用作标题。标题为空并自动聚焦；描述预填消息的可读正文。
2. **来源与描述分开保存**：描述允许用户编辑，来源关系保留会话、消息、发送人、时间、内容类型与创建时快照，避免编辑描述后丢失溯源。
3. **默认负责人是创建者本人**：首版不根据聊天对象或 `@` 静默分派；未来 AI 只能建议，不能覆盖用户输入。
4. **创建后回到原会话**：任务与会话建立只读分享关系，并发送现有任务富卡；卡片详情继续沿用任务权限能力字段。
5. **与稍后处理保持语义边界**：稍后处理是个人消息书签；转为任务是有标题、负责人、状态和协作可见性的执行项。

## 2. 首版范围

### 支持

- Web 端文本、富文本和引用回复消息的右键菜单增加“转为任务”。
- 轻量创建对话框：标题、自动带入的描述、来源消息摘要、负责人默认值、截止日期。
- 创建接口接受结构化 `source_message`，服务端验证当前用户属于来源会话。
- 新建 `TaskMessageSource`，一条任务首版最多关联一条来源消息；同一消息允许按需生成多个任务。
- 创建成功后原子建立 `TaskConversationShare`，前端随后向当前会话发送任务卡片。
- 任务详情返回来源消息信息，并提供回到 IM 会话、定位消息序号的链接。
- 本会话任务查询在创建后立即刷新。

### 暂不支持

- 图片、文件、语音、会议/日程/文档卡片直接转任务。
- 多选消息生成一个任务或任务树。
- AI 自动生成标题、负责人或截止日期。
- 服务端主动修改原消息或在消息上持久显示“已转为任务”。
- 消息撤回时自动删除任务；首版保留任务与来源快照，来源定位失败时由 IM 展示现有不可用状态。

## 3. 分阶段实施

### 阶段 A：数据模型与 API（已完成）

- 增加 `TaskMessageSource` 模型和数据库迁移。
- 为任务创建序列化器增加嵌套的 `source_message` 输入校验。
- 在同一数据库事务内创建任务来源和当前会话分享关系。
- 在 `TaskSerializer` 中增加只读 `source_message`。
- 覆盖会话成员校验、默认负责人、来源持久化、分享关系和普通任务兼容测试。

验收：普通任务创建契约不变；携带来源创建时，任务、来源、会话分享要么全部成功，要么全部回滚。

### 阶段 B：消息入口与轻量创建 UI（已完成）

- 抽取消息正文标准化函数，完整保留文本/富文本/引用正文，最大 5,000 字符。
- 消息右键菜单加入“转为任务”，打开轻量对话框。
- 标题必填且自动聚焦；描述预填但可编辑；负责人默认为本人；截止日期可选。
- 对话框展示不可编辑的来源摘要，不把来源元数据混入描述。

验收：用户无需离开会话即可创建；未填写标题不能提交；失败时保留草稿。

### 阶段 C：回发卡片与来源回溯（已完成）

- 创建成功后使用既有任务卡构建器向当前会话发卡。
- 分享记录先于卡片发送；发送失败时任务仍保留，并给出可重试的明确提示。
- 创建成功后刷新任务详情、本会话任务侧栏和任务列表缓存。
- 任务详情中展示“来源消息”，可跳到 `/im?cid=...&seq=...`。

验收：会话成员可按既有 `shared_via` 权限查看卡片；创建者可从任务返回原消息。

### 阶段 D：质量与文档（已完成）

- 前端组件、正文标准化和菜单行为单元测试。
- 后端模型/API/权限回归测试。
- TypeScript、ESLint、Prettier、Django migrations check 与目标测试通过。
- 更新任务功能说明，记录撤回、重复创建、非文本消息和 AI 的当前边界。

## 4. 后续演进

1. AI 异步生成动作型标题；用户开始输入后永不覆盖。
2. 识别明确 `@成员` 和日期表达，只生成可确认的建议。
3. 多选消息合并为任务描述，或建议父任务与子任务。
4. 原消息展示关联任务数量，并提供“查看任务/再创建一个”入口。
5. 将聊天来源、会议行动项和会议纪要统一为任务来源时间线。

## 5. 观测指标

- `message_task_opened`、`message_task_created`、`message_task_card_sent` 漏斗。
- 创建耗时中位数、取消率、失败率和卡片发送重试率。
- 聊天来源任务占新增任务比例及其按期完成率。
- 标题平均长度、描述被清空比例，为 AI 标题与摘要能力提供基线。

## 6. 实施结果

- 后端新增消息来源模型、迁移、创建接口校验和会话分享原子写入；任务 API 全量 69 个用例通过。
- 前端已接入消息右键入口、轻量创建对话框、任务卡回发和任务详情来源跳转。
- 文本、富文本、引用回复的正文标准化，以及创建表单契约共 6 个单元测试通过。
- TypeScript、ESLint、Prettier、Ruff、Django migration check 和 Vite 生产构建通过。
- AI 标题、非文本消息、多消息合并和埋点仍按“后续演进/观测指标”推进，不属于本次首版交付。
