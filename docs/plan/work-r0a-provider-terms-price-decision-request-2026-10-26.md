## 4. 价表上界表（数字来自 2026-10-26 控制台截图；书面价目与变价通知期仍待商务）

R0a 预算按 cents 记账，`reserve/settle/adjust` 依赖已版本化价表；**未版本化的价格不得进入账本**。

| 服务商 / 模型 | input 单价 | output 单价 | cached input | 币种/单位 | 单次 Run 预估上限 | `price_version` | 审批与生效日 |
|---|---|---|---|---|---|---|---|
| 阿里云 `qwen3.8-flash` | 0.8 | 2.7 | 0.1 | CNY 元/百万 tokens | 待产品给 token 上界 | `price-v1`（数字已录，待书面确认） | |
| DeepSeek `deepseek-v4.1-flash-1017` | 1.0 空闲 / **2.0 高峰**（均为缓存未命中） | 4.0 空闲 / **8.0 高峰** | 0.02 空闲 / 0.04 高峰 | CNY 元/百万 tokens | 同上 | **未定**（时段维度未定，见 §4.2-1） | |
| 火山引擎 `doubao-seed-2.1-lite` | 0.8 | 2.7 | 0.16 | CNY 元/百万 tokens | 同上 | **未定**（缓存存储按小时计费，见 §4.2-2） | |

**三家最贵路径（预算上界建议恒取值）**：input **2.0**、output **8.0**、cached input **0.16** 元/百万 tokens。这三个数**不来自任何单家的标准价**——input/output 上界是 DeepSeek 高峰档，cached input 上界是火山缓存档。按最贵路径取正是为了防止路由切换把预算穿透。

约束：三家各有一套 `price_version`，同一账本内不得混用未版本化价格；预算上界按**三家最贵路径**取；变价 = 新版本，历史结算不追改；账单对账差异按 usage 容差处理，超容差进 unknown（不自动重发）。

### 4.1 截图给出的完整价目维度（R0a 只取三档）

- **阿里云 `qwen3.8-flash`**：输入 0.8｜输入（缓存命中）0.1｜输入（Batch File）0.4｜显式缓存创建 1.25｜显式缓存命中 0.1｜输出 2.7｜输出（Batch File）1.35。
- **DeepSeek `V4.1-Flash-1017` / `V4-Pro-0813`**：上下文 1M、最大输出 384K、思考模式默认开启。缓存命中输入 0.02 / 0.04 与 0.15 / 0.30；缓存未命中输入 1 / 2 与 4.5 / 9.0；输出 4 / 8 与 13.5 / 27.0（前值空闲时段、后值高峰时段）；并发限制 **2500 / 500**。功能面 Json Output、Tool Calls、Responses API、Anthropic API、对话前缀续写均支持；FIM 仅非思考模式；图像理解仅 Flash 支持、Pro 不支持。
- **火山引擎 `Doubao-Seed-2.1-lite`**：推理输入 0.8｜缓存命中 0.16｜**缓存存储 0.017 元/百万 tokens/小时**｜批量推理输入 0.4 / 输出 1.35 / 缓存命中 0.16｜低延迟（Fast）输入 1.6 / 输出 5.4 / 缓存命中 0.32｜低优（Flex）输入 0.4 / 输出 1.35 / 缓存命中 0.16｜音频输入 12 / 缓存命中 2.4 / 批量音频 6 / Fast 音频 24 与 4.8 / Flex 音频 6 与 2.4。

R0a 是云端文本任务：音频、图像、FIM、Batch/Flex/低延迟档**不计入预算上界**，只作将来扩展参考。若某档被启用（例如用 Batch 做离线重跑），必须另立 `price_version` 再进账本。

### 4.2 这批数字暴露的三条设计约束（DR2 前要有结论）

1. **DeepSeek 是时段双价，现有 `price_version` 装不下**。单值快照无法表达"同一版本两个价"。两条路：**(a) 预算上界恒取高峰价**（推荐：账本与结算实现不变，代价是空闲时段预留偏保守）；**(b) 价表加时段维度**（要改 D1 的 cents 结算与 usage 归一规则）。高峰/空闲的**具体时段划分截图未给**，须商务书面确认。
2. **火山的缓存存储是时长维度**（0.017 元/百万 tokens/小时），不是 token 维度，进不了现有 cents/token 账本。R0a 要么关闭显式缓存存储，要么把它排除在 Run 预算之外单列为成本项——两者都要写进价表口径，**不能默默计入**。
3. **并发上限按家差异**：DeepSeek Flash 2500、Pro 500。出口限流与容量模型（S6）需要每家一个 concurrency 配置项；阿里云与火山的配额截图未给，仍属 P5 待答。

## 5. 与设计耦合的五条不可协商项

1. **`provider_request_id` 必须可查询**。unknown/对账（F04/F07/F21）依赖它；某模型若不可查询，只能标"保守计费"：unknown 保留预留不释放，产品需接受这部分成本不确定性。
2. **缺 `usage` 不得计为免费**。usage 缺失走对账保留，不写零。
3. **正文不进供应商训练/改进**，条款须覆盖缓存与日志（与 S14"正文/密钥进日志"同边界）。
4. **供应商 Key 只在网关安全域注入**；Runtime/设备/worker 不持长期 Key，条款或配置不得要求把 Key 下放到执行侧。
5. **每家都要能独立核对计量口径**。三家并列可用意味着同一 Run 可能落在不同价表上；`usage` 字段名/含义不一致（尤其 cached input 与 reasoning token）时，网关必须归一后再进账本，归一规则随 `price_version` 一起冻结。

## 6. 证据边界（请勿据此认为条款已确认）

- H02 已用上述三个模型经本地网关做**真实流式请求**，证明的是协议与字段，**不是**条款、驻留、配额或计费承诺。
- **模型 id 已变，协议证据需复跑**：H02 当时测的是 `deepseek-chat`，现在要接的是 `deepseek-v4.1-flash-1017`（1M 上下文、默认思考模式）。三家的 `usage` 字段计法——尤其 reasoning token 是否计入 output、cached 与显式缓存如何分别回报——必须按新 id 各跑一次真实请求才算协议证据。
- §4 的价格来自 **2026-10-26 三家控制台/文档页截图**：数字可核对，但**不是**书面价目或合同附件——没有生效日、没有变价通知期、没有高峰/空闲时段定义、没有币种与汇率口径确认。书面材料归档前 `price-v1` 不得进入账本。
- 现有 `provider id / dataResidency / quota` 值是配置占位；本单归档书面材料前不得当作采购事实。
- D6 的容量模型是算术模型，不是压测；10× 压力（75 rpm、12.96M token/日）已超设计阈值，扩量前需重新申请配额。
- S13 当前 `open`、S14 `partial`，go/no-go 仍 no-go。

## 8. 本单不解决、但阻塞 E5 配置冻结的路由问题（产品 + 后端在 DR3 前定）

三家可路由之后，"怎么选"仍是未定项，当前网关配置里是占位值：

- 权重与优先级：固定主用 + 溢出，还是按价格/延迟动态选择？
- 失效判定：什么信号认定某家不可用、探测间隔多久、恢复后是否立刻回切。
- 会话一致性：同一 Task 的重试是否必须落回同一 provider（影响效果对比与投诉定位）。
- 配额耗尽行为：排队、降级到备用家，还是直接受控失败（与 §3 的 D1 降级声明相关）。
- 质量口径：三家的工具调用与结构化输出兼容性已由 H02 打过真实流式请求，但**效果对齐未测**；黄金任务的通过阈值需按 provider 分别看。

这些不改变 C15 的条款闸门，只影响 E5 能否把路由配置从占位变成可发布值。
