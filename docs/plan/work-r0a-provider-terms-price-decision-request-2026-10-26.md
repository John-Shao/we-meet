## 5. 与设计耦合的五条不可协商项

1. **`provider_request_id` 必须可查询**。unknown/对账（F04/F07/F21）依赖它；某模型若不可查询，只能标"保守计费"：unknown 保留预留不释放，产品需接受这部分成本不确定性。
2. **缺 `usage` 不得计为免费**。usage 缺失走对账保留，不写零。
3. **正文不进供应商训练/改进**：演示组织使用百炼托管 + 演示数据，**不索取 P1–P4 书面确认**；客户组织由其自担。S14 仍约束 Work 侧日志/密钥不落正文。
4. **供应商 Key 只在网关安全域注入**；Runtime/设备/worker 不持长期 Key，条款或配置不得要求把 Key 下放到执行侧。
5. **每个配置的 provider 都要能核对用量口径（2026-10-27 改写）**。平台只对演示组织的阿里云负责；客户自带账号的 provider 由客户按接入说明自担。`usage` 字段名/含义不一致（尤其 cached input 与 reasoning token）时，网关先归一为 Work 的 token 事实，再进 `usage_daily`；不再有价表或 `price_version`。

## 8. 路由问题（已由 D-08 R1 关闭，保留历史）

D-08 R1 已定：R0a 每组织一条生效配置、不做跨厂商自动切换，因此以下问题在 R0a 不再成立；仅客户自建多 provider 时由客户自行决定：

- 权重与优先级：固定主用 + 溢出，还是按价格/延迟动态选择？
- 失效判定：什么信号认定某家不可用、探测间隔多久、恢复后是否立刻回切。
- 会话一致性：同一 Task 的重试是否必须落回同一 provider（影响效果对比与投诉定位）。
- 配额耗尽行为：排队、降级到备用家，还是直接受控失败（与 §3 的 D1 降级声明相关）。
- 质量口径：三家的工具调用与结构化输出兼容性已由 H02 打过真实流式请求，但**效果对齐未测**；黄金任务的通过阈值需按 provider 分别看。

**结论（2026-10-27）**：R0a 不路由、不切换；E5 只需按组织解析一条配置，本节不再阻塞配置冻结。
