## 1. 先纠正一件事：判定任务集用 D5，不用 UX §13.2

UX §13.2 是 R0 全阶段脚本，含 **T2 本机文件夹授权、T3 命令审批、T7 授予席位并调整预算**——这三项**不在 R0a 交付面**：D5 明确 R0a 只显示云端执行、`ask_each` 文案要"避免出现不存在的审批"、成员侧不展示组织额度、管理面只读。照原脚本执行会得到两类假结果：任务做不到（假阴性），以及测试了不存在的入口（违反 D5「没有未实现入口、假审批」）。

**R0a 判定任务集 = 下表 UT1–UT5**（源自 D5 §11.2 + 已落地的管理只读接口）：

| 编号 | 任务 | 界面 | 成功标准 |
|---|---|---|---|
| UT1 | 用一段口述需求提交一个云端文档任务（预览 → 确认 → 提交） | 首页 / Composer | 60 秒内提交；能复述"云端执行、不访问本机、成果存到任务、token 用量上限" |
| UT2 | 在任务工作区等待完成并**采纳**成果（含一次标题编辑） | 任务 / 成果 | 找到待验收并采纳；理解采纳后仍可编辑；编辑冲突时知道发生了什么 |
| UT3 | 经历一次失败或 unknown，判断下一步 | 任务工作区 | 能区分失败 / 未知 / 取消；**不期待自动重试**、不误选重试造成重复 |
| UT4 | 在"我的工作 / Inbox"找到需要处理的项并打开 | 我的工作 / Inbox | 找到"需要你"项；能说出为什么需要自己 |
| UT5 | 管理员在 `/admin/work` 读出席位与配额状况，并发起一次审计导出下载 | 管理只读 | 找到入口；理解席位满 / 配额告警；理解导出文件是一次性短期凭证、不是永久链接 |

T2/T3（本机、审批）保留为 R0b 前瞻观察项：**记录但不计入 U1 判定**。

## 2. 名额与配额（这是数字下限，不是建议）

| 角色 | 最少 | 为什么 |
|---|---|---|
| 知识工作者（主要写文档/方案） | 2 | UT1/UT2 的主体人群 |
| 本地重度用户（文件多在本地、在意"不上传"） | 2 | UT1 的边界复述是 R0a 的核心信任点 |
| 组织管理员 | **3** | UT5 需管理员视角；UX §13.5 的通过标准本就要求"至少 3 名管理员完成管理任务" |
| 合计 | **7–8 人** | 原"5–8 人"在管理员 ≥3 的约束下下限实际是 7，本单把口径固定为 7–8 |
| 组织覆盖 | **≥3 家** | 就绪包 L8：两个场景需在 ≥3 家复现 |

硬性排除：参与 R0a 设计/评审/实现的人；同一家组织最多 3 人（避免单组织主导结论）。

## 4. 邀约与同意（可直接复制）

**邀约文案**：
> 我们在做一款面向企业的 AI 办公助手（云端生成文档/方案），想请 45 分钟试用并给反馈。不是销售演示，没有考核，做不出来是产品的问题。全程录屏仅用于内部改进，不记录你的工作正文内容，可随时中止并要求删除记录。时间是 11/20–11/24，地点线上，另有小额答谢（口径由产品与财务确认）。

**筛选问卷（5 题，对应 UX §13.6 筛选项）**：① 每周产出文档/方案的大致频率；② 是否用过 AI 办公/写作工具，用过哪些；③ 是否管理过团队账号权限或预算（用于识别管理员名额）；④ 是否同意录屏与匿名编号记录；⑤ 所属组织（用于 ≥3 家去重，不收集公司以外的识别信息）。

**知情同意要点（四条，逐条口头确认再开始）**：
1. 录屏 + 观察笔记；记录只含任务、时间、错误、原话，**不记录业务正文**；使用匿名编号。
2. 数据仅用于本次研究与 R0a 改进；不进入模型训练，不写入产品日志（与 D6 S14 同一口径）。
3. 可随时中止、可要求删除自己的记录；删除请求走[删除 Runbook](work-r0a-pilot-operations-runbook-2026-10-26.md)同一路径。
4. 我们不提供真实客户数据；所有材料由参与者自备或主持人提供的虚构样本。

## 5. 环境与分工

- **可点环境**：R0a 中保真原型 + [D2 mock server](assets/work-r0a-design-2026-10-25/mock-server.mjs)（提供 bootstrap → 输入 → 预览 → 提交 → 状态 → 成果 → 管理只读 / 导出凭证全链路，含 `ask_each` 之外的真实 R0a 权限 chip 与错误码）。mock 不接真实模型/Temporal，因此**失败与 unknown 场景由主持人注入**，这一点要在报告里写明边界。
- 每场角色：主持人 1（只读任务、不引导点击）、记录员 1（时间/错误/原话）、观察 1（可选，产品）。
- 场次：7–8 场 × 45 分钟，分布在 11-20～11-24 五天，每天 ≤2 场。
- 材料清单：任务卡 UT1–UT5、同意话术、错误注入脚本（mock 的 `/__test/*` 钩子）、评分表（完成率/时间/错误/SEQ）。

## 6. 通过标准与产出

- T 级：UT1–UT5 **完成率 ≥80%**；SEQ **≥5/7**；**两个场景在 ≥3 家组织复现**（就绪包 L8）。
- 关键认知项：参与者能复述"云端执行 / 不访问本机 / 成果去向 / token 用量上限"，且**不误以为存在本机、连接器或逐次审批**（D5 §11.2 成功标准）。
- 产出：可用性报告（完成率/时间/错误/SEQ/问题分级）+ 修复清单；P0/P1 回写 D5 状态矩阵与文案，回写后在 DR3 复核；未通过则回 D5 修正，**不进入 DR4**。
