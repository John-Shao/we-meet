# 任务时间提醒与逾期管理当前功能说明

本文描述任务日期状态、即时变更通知和任务助手提醒的当前实现。任务当前只有 `todo` 与 `completed` 两种状态。

## 日期语义

`start_date` 和 `due_date` 都是日期，不包含具体时刻。系统分别按每位负责人的 `User.timezone` 解释“今天”：

- `todo` 任务在 `start_date` 当天产生 `starting` 提醒。
- `todo` 任务在 `due_date` 当天产生 `due_today` 提醒。
- `todo` 任务在 `due_date` 之后产生一次 `overdue` 提醒。
- `completed` 任务不产生时间提醒，也不返回时间状态。
- 开始与截止为同一天时只发送“今天截止”，避免连续发送两张卡片。
- 逾期提醒是一次性状态提醒，不按天重复催办。

创建接口未提供开始日期时，按创建人的本地日期填充。开始日期不能晚于截止日期。

## 多负责人、幂等和重试

每位当前负责人独立计算本地日期并获得自己的提醒记录。`TaskImDelivery` 使用 `task + recipient + event + reference_date` 唯一约束，因此定时扫描可安全重跑。

生产维护任务调用 `record_due_task_reminders` 创建缺失记录，并恢复到期的 `pending` 记录。投递失败沿用 Celery 的最多五次退避重试；任务接口提交成功不依赖 IM 当次可用。

投递前再次校验：

- 任务仍为 `todo`。
- 接收者仍是当前负责人。
- 接收者仍有效，日期和其本地“今天”仍符合事件。

负责人变更、改期或完成任务后，失效的待投递记录标记为 `superseded`。新负责人或新日期符合条件时会生成新的幂等记录。

## 即时通知

### 日期变化

任务日期实际变化后，向除操作者之外的全部当前负责人发送通知，展示修改人和“原值 → 新值”。相同值不创建活动或通知；连续改期只保留最新待投递快照。

若同一请求同时变更负责人和日期，只向新增负责人发送分派/转交通知，不再叠加日期通知。任务已完成时不发送日期变化通知。

### 状态变化

任务在 `todo` 与 `completed` 之间实际切换后，向除操作者之外的创建人、全部当前负责人和关注人发送状态通知。连续切换只保留最新待投递状态快照；完成任务会使未投递的日期变化与时间提醒失效。

### 优先级、评论和删除

- 优先级实际变化：通知除操作者外的全部当前负责人。
- 新评论：通知除评论作者外的创建人和全部当前负责人。
- 删除任务：通知除删除操作者外的全部负责人和关注人；通知保存任务标题和操作者快照，可在任务记录删除后重试。

创建或新增负责人时，仅通知新增且不是创建人的负责人。自分配保持静默。

## 查询与展示

任务列表支持 `time=all|starting_today|due_today|overdue`。日期筛选只返回 `todo` 任务，并继续与 `scope`、状态、优先级和清单筛选按 AND 组合。

序列化结果包含只读 `time_state`：

- `starting_today`
- `due_today`
- `overdue`
- 不符合上述条件时为 `null`

## 当前边界

- 不支持用户自定义提醒时刻或提前天数。
- 不支持每日重复催办、稍后提醒或关闭单条提醒。
- 不为普通标题或说明变更发送即时通知。
- 浏览器 E2E 不验证外部 IM 最终送达；账本、幂等、失效和重试由后端测试覆盖。
