# 任务优先级当前功能说明

个人任务和会议行动项生成的任务共用 `Task.priority`。

## 取值与权限

当前创建和修改接口接受：

- `low`
- `medium`
- `high`
- `urgent`

默认值为 `medium`。模型和筛选仍识别 `none`，用于兼容历史任务；新建和编辑接口不再允许把任务设置为 `none`。

创建人、任一当前负责人，以及所属清单的编辑者或所有者可以修改优先级。只读清单成员、仅关注人和仅通过会话查看的用户不能修改。

实际变化会写入 `priority_changed` 操作历史；提交相同值不会生成新活动或通知。

## 列表、筛选与排序

列表支持 `priority=all|none|low|medium|high|urgent`，并与范围、状态、日期和清单筛选按 AND 组合。

未指定 `ordering` 时使用稳定默认排序：

1. 状态：`todo`、`completed`。
2. 优先级：紧急、高、中、低、历史无优先级。
3. 截止日期升序，未设置日期排末尾。
4. 更新时间倒序。
5. 主键保证分页稳定。

显式传入 `ordering=priority` 或 `ordering=-priority` 时，只按优先级及主键排序。列表、看板、创建表单和详情面板使用一致的优先级标签与选择控件。

## 通知

优先级变化后，任务助手向除操作者之外的全部当前负责人创建可靠投递记录。连续修改会使旧的待投递记录失效；负责人变化后，不再向已移除负责人投递。

同一请求同时变更负责人和优先级时，以分派/转交通知为准，避免新增负责人连续收到两张卡片。分派、日期提醒和优先级变化卡片都会展示当前有效优先级。
