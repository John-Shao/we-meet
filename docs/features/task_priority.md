# 任务优先级

## 范围

个人任务、会议行动项生成的任务和一级子任务共用 `Task.priority`，可选值为 `none`、`low`、`medium`、`high` 和 `urgent`。字段默认 `none`，历史任务通过迁移 `0118` 保持无优先级；子任务不继承父任务，会议行动项创建任务时也不推断优先级。

只有任务创建人可以设置或修改优先级。负责人仍只能按照状态机推进任务。优先级实际变化会写入独立的 `priority_changed` 操作历史；提交相同值不会产生历史或通知。

## 列表与展示

任务列表支持 `priority=all|none|low|medium|high|urgent`，并与 `scope` 和时间筛选按 AND 组合。默认排序固定为：

1. 状态：进行中、待处理、已完成、已取消。
2. 同状态内优先级：紧急、高、中、低、无。
3. 截止日期升序，未设置截止日期排末尾。
4. 更新时间倒序，最后按主键保证分页稳定。

非空优先级使用语义色标签：紧急为危险色、高为警示色、中为主色、低为中性色；无优先级不显示标签。创建、编辑和子任务表单使用公共选择组件，列表提供单选优先级筛选，并覆盖中、英、法、德、荷五种语言。

## 通知

创建人修改协作任务的优先级后，任务助手向当前负责人可靠投递“任务优先级已调整”卡片，包含原档位、新档位和修改人。连续修改只保留最新待投递快照；转交后旧负责人的待投递记录失效；创建人与负责人相同时保持静默。

同一次修改同时变更负责人和优先级时，只发送分派或转交通知，并在该卡片展示当前非空优先级。分派、转交和时间提醒卡片也展示当前非空优先级。

## 发布与验收

本能力不增加环境变量或 Helm 配置。发布 backend 和 frontend 时使用相同 Git 短哈希镜像标签，并确认迁移 `0118` 执行成功。生产验收覆盖创建和筛选、默认排序、改级通知与历史、负责人越权拒绝、会议任务默认无优先级，以及浅色、深色和窄屏展示。
