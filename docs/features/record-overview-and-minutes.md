# 实录概要与智能纪要

依据 2026-09-22 的产品反馈，将实录（对应妙记）中的内容概要与独立智能纪要文档分开。

| 页面 | 内容与操作 |
| --- | --- |
| 会议实录 → 概要 | 快速理解录音：概述、主要观点、原音定位。与文字记录、章节、发言人共同组成实录阅读页。 |
| 智能纪要 | 独立文档：标题、总结、决策、行动项、待确认问题；保留生成、人工修订、问答、分享、通知、导出和历史版本。 |

概要提供“打开智能纪要”；文档提供“查看实录与概要”。文档不嵌入实录标签或播放器，实录概要不承载文档编辑和分发工具。Web 与 Android 使用相同的区分。

概要单独生成：直接读取已完成录音的文字记录或已发布的上传转写，冻结原文快照，使用概要专用提示词生成 `synopsis` 与带标题、原文引用的 `topics`。生成任务使用 `kind=overview`，输出保存到独立的 `MeetingOverviewVersion`。不读取智能纪要内容、人工修订稿或纪要分块缓存，不回填旧纪要结果，也不触发纪要通知、文档导出或任务创建。

`GET /meeting-records/{id}/overview/` 返回概要、生成状态与可用操作；`POST /meeting-records/{id}/overview-requests/` 接受生成、重新生成和失败重试。请求沿用通用的幂等提交、原文快照、队列和用量统计设施；概要请求与智能纪要请求按任务类型隔离。Web 与 Android 分别保存概要的待确认请求，页面加载和轮询不会自动提交生成。

长原文按顺序分块生成概要后合并，不截断头尾。引用必须匹配冻结原文；生成前、分块间、保存前均检查原文和权限。原文变化后旧概要标记为过时；重新生成失败仍保留旧结果。权限撤销时页面停止显示私有内容。阅读沿用记录的 `read_summary` 授权，生成要求当前原文管理权限。

Web 的 `?tab=overview` 打开实录概要；现有 `?tab=summary`、`?summary=<id>`、`?human=<id>` 与审核入口打开独立文档。固定版本链接继续读取指定版本，权限检查继续生效。旧版在线会议纪要保留在文档页。

发布需先应用数据库迁移 `0189_independent_record_overviews`，更新 backend（包含 Celery worker/beat），再更新 Web/Android。`MEETING_OVERVIEW_ENABLED` 默认开启，但不会自动生成；`MEETING_OVERVIEW_MODEL` 默认 `qwen3.8-flash`。沿用当前模型供应商连接和凭据，智能纪要的生成开关不控制概要。

验证：100 项后端相关测试、56 项 Web 测试、11 项 Android 接口测试通过；TypeScript、JSON、语言键检查、安卓 Kotlin 编译和 `checkDesignTokens` 通过。`scripts/check-record-overview-ui.mjs` 使用本地模拟数据验证桌面/窄屏显式生成、概要独立接口、纪要导航及权限撤销。模型调用在测试中被模拟，尚未验证线上模型生成质量或安卓真机画面。本次未部署。
