# 任务与会议行动项状态联动

## T3.1–T3.2 目标

会议行动项负责确认会议结论，任务负责跟进执行。T3.1 建立从任务到来源行动项的可解释状态联动；T3.2 增加行动项完成与重新打开对关联任务的反向联动。两个方向都保留人工决策优先、来源审计和循环抑制。

## 任务到行动项规则

仅带有 `source_action_item` 的会议任务参与联动：

| 任务变化 | 来源行动项当前状态 | 结果 |
| --- | --- | --- |
| 待处理/进行中 → 已完成 | 已确认 | 自动改为已完成，并记录本次任务动态为同步来源 |
| 待处理/进行中 → 已完成 | 已完成 | 保持不变，记录已经一致；人工完成不会被标记为任务驱动 |
| 待处理/进行中 → 已完成 | 待确认/已驳回 | 保持人工状态，记录同步冲突 |
| 已完成 → 待处理/进行中 | 上次由任务自动完成 | 自动恢复为已确认，并清除同步来源 |
| 已完成 → 待处理/进行中 | 人工完成 | 保持已完成，记录人工覆盖 |
| 已完成 → 待处理/进行中 | 已确认 | 保持不变，记录已经一致 |
| 已完成 → 待处理/进行中 | 待确认/已驳回 | 保持人工状态，记录同步冲突 |

任务状态流转不允许从已完成直接进入已取消，因此不需要额外定义“已完成 → 已取消”的行动项行为。个人任务和没有来源行动项的任务不执行任何同步。

## 行动项到任务规则

只有行动项的人工状态操作触发反向联动；任务自动修改行动项时不会再次触发：

| 行动项变化 | 关联任务当前状态 | 结果 |
| --- | --- | --- |
| 已确认 → 已完成 | 待处理/进行中 | 自动改为已完成，并向未操作的任务协作者发送状态通知 |
| 已确认 → 已完成 | 已完成 | 保持不变，记录已经一致 |
| 已确认 → 已完成 | 已取消 | 保持已取消，记录同步冲突 |
| 已完成 → 已确认 | 已完成 | 自动恢复为待处理，并发送状态通知 |
| 已完成 → 已确认 | 待处理/进行中 | 保持当前开放状态，记录已经一致 |
| 已完成 → 已确认 | 已取消 | 保持已取消，记录同步冲突 |

行动项的待确认和已忽略状态不映射任务状态，也不会自动取消任务。任务取消及恢复仍只允许任务创建人操作。

## 人工优先与来源标记

`ActionItem.task_status_sync_activity` 仅保存最近一次真正改变行动项状态的任务动态。它不是通用的“最后修改人”字段，而是判断任务重新打开时是否有权恢复行动项的内部来源标记。

会议管理员或行动项负责人手工修改行动项状态时，服务端会清除该标记。此后即使任务重新打开，也不会覆盖人工完成、待确认或驳回状态。部署前已经处于已完成状态的历史行动项没有来源标记，按人工完成处理，不会因任务重新打开而自动恢复。

## 审计

任务状态变化动态的 `changes.source_action_item_sync` 记录行动项 ID、同步前后状态、结果和可选原因。结果包括：

- `updated`：联动实际修改了行动项。
- `already_aligned`：双方状态已经一致。
- `skipped_manual_override`：人工完成优先，未执行回退。
- `skipped_conflict`：行动项处于待确认或已驳回等冲突状态，未覆盖。

来源行动项发生人工状态变化时，关联任务新增 `source_action_item_changed` 动态，记录原状态、新状态、是否覆盖任务同步结果，以及 `changes.linked_task_sync` 中的反向同步结果。反向同步实际改变任务时，另写一条带 `changes.source_action_item_origin` 的任务状态动态，并复用任务状态通知的可靠投递机制。任务页面会把完整来源和结果展示在操作历史中。

反向产生的任务状态动态带有明确来源，任务到行动项的同步器会忽略该动态；两个更新入口统一先锁定行动项、再锁定任务，降低并发双向操作时的死锁风险。

## 本阶段边界

T3.2 不包含：

- 标题、说明、负责人或日期的双向同步。
- 待确认/忽略与任务取消状态之间的自动映射。
- 自动修复历史任务与行动项的状态差异。

后续如扩大映射范围，需要先解决行动项管理员与任务创建人的权限差异，不能绕过任务取消权限。

## 部署与验收

首次部署 T3.1/T3.2 前执行迁移 `0117_action_item_task_status_sync`；T3.2 本身没有新增迁移，但需要同时发布后端和前端。建议至少验收：

1. 已确认行动项的任务完成后，行动项自动完成，任务历史显示同步成功。
2. 同一任务重新打开后，行动项自动恢复为已确认。
3. 人工完成行动项后再完成并重新打开任务，行动项仍保持已完成，历史显示人工优先。
4. 待确认或已驳回行动项对应的任务完成时，行动项不变，历史显示同步冲突。
5. 任务自动完成行动项后，再人工修改行动项状态，任务历史显示来源行动项的人工变化；随后重新打开任务不会覆盖该状态。
6. 普通个人任务的状态流转保持原有行为。
7. 人工完成行动项后，开放任务自动完成，另一位任务协作者收到通知。
8. 人工重新打开行动项后，已完成任务恢复为待处理，负责人看到状态更新和通知。
9. 已取消任务不被行动项完成或重新打开覆盖，操作历史显示冲突。
10. 行动项待确认或忽略不修改关联任务。
