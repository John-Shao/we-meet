# 最小任务模块规划

## 目标

任务模块从会议模块中独立出来，提供一个可持续跟进工作的最小闭环：用户可以创建个人任务或把任务分派给组织内同事、查看自己负责或创建的任务、推进任务状态，并在任务来自会议时回到来源会议。

会议行动项仍负责“会议结论的确认”，任务负责“会后的持续执行”。只有已确认且已分配负责人的行动项才能转换为任务，同一行动项只生成一个任务。

## 本阶段范围

- 独立的“任务”导航和任务中心页面。
- 创建任务；负责人默认是当前用户，也可从通讯录选择组织内在职同事。
- “我负责的”“我创建的”“全部相关”三个视图。
- 待处理、进行中、已完成、已取消四种状态及受控流转。
- 创建人可修改标题、描述、开始日期、截止日期、负责人和状态。
- 负责人可修改状态，不能修改任务内容。
- 任务来自会议行动项时展示来源会议，并可跳回会议详情。
- 任务仅对创建人和负责人可见。

## 暂不纳入

- 批量分派、跨组织分派和外部联系人分派。
- 新建、转交任务后的 IM 通知。
- 评论、附件、子任务、标签、优先级。
- 提醒、重复任务、日历同步。
- 看板、项目、任务统计与自动化规则。
- 行动项和任务状态的双向自动同步。

这些能力在最小闭环稳定后单独规划，避免任务模块被会议场景反向绑死。

## 数据模型

`Task` 是独立聚合根，包含：

- 标题、描述、创建人、负责人。
- 状态、开始日期、截止日期、完成时间。
- 可选的来源行动项；通过来源行动项关联会议。

个人任务没有来源行动项。会议任务保留 `source_action_item`，行动项同时保存 `task_id` 作为面向会议详情的轻量引用。

## 权限

| 操作 | 创建人 | 负责人 | 其他用户 |
| --- | --- | --- | --- |
| 查看 | 是 | 是 | 否 |
| 修改标题/描述/开始日期/截止日期 | 是 | 否 | 否 |
| 转交负责人 | 是 | 否 | 否 |
| 修改状态 | 是 | 是 | 否 |
| 删除 | 本阶段不提供 | 本阶段不提供 | 否 |

任务默认由创建人自己负责。创建人可以从自己的组织通讯录选择在职成员作为负责人，并可在后续编辑时转交；原负责人转交后不再拥有该任务的查看权限。会议任务的创建人是执行转换的会议管理员，负责人继承行动项负责人。

## 状态机

- `todo` → `in_progress` / `completed` / `canceled`
- `in_progress` → `todo` / `completed` / `canceled`
- `completed` → `todo`
- `canceled` → `todo`

进入 `completed` 时记录 `completed_at`；离开 `completed` 时清空。取消采用状态而不是删除，以保留来源与审计线索。

## API

- `GET /api/v1.0/tasks/?scope=assigned|created|all`
- `POST /api/v1.0/tasks/`
- `GET /api/v1.0/tasks/{id}/`
- `PATCH /api/v1.0/tasks/{id}/`
- `POST /api/v1.0/rooms/{room_id}/action-items/{id}/task/`（已实现的会议转换入口）

列表只返回当前用户相关任务。创建接口可选传 `assignee_id`，不传时统一设为当前用户；修改接口仅允许创建人变更 `assignee_id`。负责人必须是创建人本人或与创建人同组织、在通讯录中有效的成员。

## 后续阶段候选

1. 协作分派通知：新建、转交任务后的负责人通知与失败重试。
2. 执行协作：评论、附件、子任务和操作历史。
3. 时间能力：提醒、重复、日历同步和逾期视图。
4. 组织能力：项目、看板、标签、优先级和统计。
5. 会议联动：行动项与任务状态的可解释双向同步。
