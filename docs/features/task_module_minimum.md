# 最小任务模块规划

时间提醒与逾期管理的后续实现见 [task_time_reminders.md](./task_time_reminders.md)。

## 目标

任务模块从会议模块中独立出来，提供一个可持续跟进工作的最小闭环：用户可以创建个人任务或把任务分派给组织内同事、查看自己负责或创建的任务、推进任务状态，并在任务来自会议时回到来源会议。

会议行动项仍负责“会议结论的确认”，任务负责“会后的持续执行”。只有已确认且已分配负责人的行动项才能转换为任务，同一行动项只生成一个任务。

## 本阶段范围

- 独立的“任务”导航和任务中心页面。
- 创建任务；负责人默认是当前用户，也可从通讯录选择组织内在职同事。
- “我负责的”“我创建的”“全部相关”三个视图。
- 待处理、进行中、已完成、已取消四种状态及受控流转。
- 创建人可修改标题、描述、开始日期、截止日期、负责人和状态。
- 负责人可修改状态，不能修改任务内容。
- 任务来自会议行动项时展示来源会议，并可跳回会议详情。
- 任务仅对创建人和负责人可见。
- 新建任务或转交负责人后，由独立的“任务助手”私聊通知新的负责人。
- 创建人调整开始日期或截止日期后，由任务助手向不同人的当前负责人发送包含原值和新值的改期通知。
- 任务状态实际变化后，由任务助手向未执行本次操作的当前协作者发送包含原状态、新状态和操作人的进度通知。
- 开放任务支持按负责人时区计算的今天开始、今天截止和已逾期状态、筛选与一次性提醒。
- 通知采用持久化投递记录、幂等消费和退避重试；IM 故障不回滚任务操作。
- 记录任务创建、内容修改、日期调整、负责人转交、状态变化和附件移除，并向相关用户展示操作时间线。
- 创建人和当前负责人可围绕任务发表评论，评论按时间顺序展示且只追加、不编辑删除；新评论由“任务助手”通知另一位当前协作者。
- 创建人和当前负责人可查看任务附件；两者均可上传附件，单个文件最大 20 MB。
- 顶层任务支持一级子任务：可展开查看、创建、分派和推进状态，并显示“已完成/总数”；子任务不在三个顶层任务列表中重复展示。

## 暂不纳入

- 批量分派、跨组织分派和外部联系人分派。
- 多级子任务、子任务排序和自动进度汇总。
- 标签、优先级。
- 自定义提醒时间、每日重复催办、重复任务和日历同步。
- 看板、项目、任务统计与自动化规则。
- 行动项和任务状态的双向自动同步。

这些能力在最小闭环稳定后单独规划，避免任务模块被会议场景反向绑死。

## 数据模型

`Task` 是独立聚合根，包含：

- 标题、描述、创建人、负责人。
- 状态、开始日期、截止日期、完成时间。
- 可选的父任务；接口只允许创建一级子任务。
- 可选的来源行动项；通过来源行动项关联会议。

个人任务没有来源行动项。会议任务保留 `source_action_item`，行动项同时保存 `task_id` 作为面向会议详情的轻量引用。

`TaskActivity` 是只追加的任务操作历史，记录操作者、事件类型、必要的结构化差异和发生时间。一次 PATCH 如果同时改变不同关注点，可以产生多条动态，例如内容修改、日期调整和状态变化各自独立；没有实际变化时不写记录。历史记录不保存整份任务或长描述快照，也不提供修改、删除接口。部署前已经存在的任务不回填“创建”记录，后续操作会正常进入时间线。

`TaskComment` 是只追加的协作评论，记录任务、作者、正文和创建时间。评论不混入操作历史，避免系统事件与讨论内容互相干扰；当前创建人和负责人可以读取同一条完整讨论，新负责人接手后可看到此前上下文，原负责人则随任务查看权限一起失去访问权。发表评论后只通知创建人和当前负责人中的另一方；创建人与负责人是同一人时保持静默。

`TaskAttachment` 只保存任务、通用文件记录和上传人之间的关联。任务附件对象存入私有 `we-task-attachment` 桶，`File.storage_bucket` 持久化实际桶名；历史空值回退主桶，确保旧附件继续可下载。附件列表只暴露受保护的任务下载端点，由后端按当前任务协作者权限签发短期对象存储 URL。创建人和当前负责人均可移除附件：关联立即消失，文件进入软删/硬删队列后从其记录的桶异步清理，并写入操作历史。转交负责人后，新负责人立即获得查看与移除权，原负责人立即失去访问权。最小阶段不提供重命名、版本管理和附件通知。

子任务继续复用 `Task` 的负责人、状态机、通知、评论、附件和操作历史，不建立第二套任务实体。父任务只保存与直接子任务的关系和完成数量汇总；子任务状态不会自动改变父任务状态。

## 权限

| 操作 | 创建人 | 负责人 | 其他用户 |
| --- | --- | --- | --- |
| 查看 | 是 | 是 | 否 |
| 修改标题/描述/开始日期/截止日期 | 是 | 否 | 否 |
| 转交负责人 | 是 | 否 | 否 |
| 修改状态 | 是 | 是 | 否 |
| 查看/发表评论 | 是 | 是 | 否 |
| 查看/上传/移除附件 | 是 | 是 | 否 |
| 删除任务 | 本阶段不提供 | 本阶段不提供 | 否 |

任务默认由创建人自己负责。创建人可以从自己的组织通讯录选择在职成员作为负责人，并可在后续编辑时转交；原负责人转交后不再拥有该任务的查看权限。会议任务的创建人是执行转换的会议管理员，负责人继承行动项负责人。

顶层任务的创建人和当前负责人均可创建、查看并推进其直接子任务；他们也继承对子任务评论和附件的协作访问权。子任务自身的创建人和负责人仍按上表获得权限，只有子任务创建人可以修改内容或转交负责人。接口拒绝在子任务下继续创建子任务。

本人给自己新建或转交任务时不发送通知。协作分派由“任务助手”通知新的负责人，不占用“会议助手”的会议纪要与文档通知职责，也不通知原负责人；评论同样由“任务助手”通知另一位当前协作者，不通知评论作者本人。状态变化通知发给未执行本次操作的当前创建人或负责人；通过父任务继承权限推进子任务时，子任务双方都可收到通知。如果任务在通知成功前再次转交，旧负责人的待投递记录会标记为已作废；连续改期或流转状态时也只保留最新的待投递快照。每次有效分派、评论、改期或状态变化通知对应一条 `TaskImDelivery`，其中活动类通知通过 `activity + recipient` 唯一约束防止重复，成功后重复消费不会再次发消息。临时网络、配置或 IM 身份尚未就绪时最多尝试五次，生产环境现有的每分钟维护任务会重新入队因 Broker 或 Worker 中断而遗留的待投递记录。

## 状态机

- `todo` → `in_progress` / `completed` / `canceled`
- `in_progress` → `todo` / `completed` / `canceled`
- `completed` → `todo`
- `canceled` → `todo`

进入 `completed` 时记录 `completed_at`；离开 `completed` 时清空。取消采用状态而不是删除，以保留来源与审计线索。

## API

- `GET /api/v1.0/tasks/?scope=assigned|created|all`
- `POST /api/v1.0/tasks/`
- `GET /api/v1.0/tasks/{id}/`
- `PATCH /api/v1.0/tasks/{id}/`
- `GET /api/v1.0/tasks/{id}/activities/`
- `GET /api/v1.0/tasks/{id}/subtasks/`
- `POST /api/v1.0/tasks/{id}/subtasks/`
- `GET /api/v1.0/tasks/{id}/comments/`
- `POST /api/v1.0/tasks/{id}/comments/`
- `GET /api/v1.0/tasks/{id}/attachments/`
- `POST /api/v1.0/tasks/{id}/attachments/`
- `GET /api/v1.0/tasks/{id}/attachments/{attachment_id}/download/`
- `DELETE /api/v1.0/tasks/{id}/attachments/{attachment_id}/`
- `POST /api/v1.0/rooms/{room_id}/action-items/{id}/task/`（已实现的会议转换入口）

列表只返回当前用户相关的顶层任务。创建接口可选传 `assignee_id`，不传时统一设为当前用户；修改接口仅允许创建人变更 `assignee_id`。负责人必须是创建人本人或与创建人同组织、在通讯录中有效的成员。子任务接口复用相同的创建字段和负责人校验。

## 后续阶段候选

1. 执行协作：一级子任务最小闭环已完成；后续再规划排序和自动进度汇总。
2. 时间能力：提醒、重复、日历同步和逾期视图。
3. 组织能力：项目、看板、标签、优先级和统计。
4. 会议联动：行动项与任务状态的可解释双向同步。
