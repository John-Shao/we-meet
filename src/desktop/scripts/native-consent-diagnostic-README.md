# B 端原生授权诊断

此工具用于定位 delivery.8 点击“允许本次控制”后的异常退出，不是新客户端安装包，也不是远控验收通过凭据。

1. 停止共享，完全退出 We-Meet（包括托盘中的退出）。无需退出另一款远程桌面软件，继续使用当前操作方式，以保留复现条件。
2. 将本目录完整复制到 B。两个 EXE 必须留在同一目录。普通双击 `WeMeet-Consent-Diagnostic.exe`，不要以管理员身份运行。
3. 在出现的原生窗口中核对名称 `We-Meet native consent test（不发送键鼠输入）`，点击一次“允许本次控制”。这是诊断窗口，不是 POC验证 的真实会议申请。
4. 等待窗口自行关闭。程序提示“诊断已结束”后，将同目录新生成的 `native-consent-日期时间.jsonl` 文件中的文字回复给维护者，然后按回车关闭控制台。不要反复点击或运行多份诊断。
5. 若窗口未出现或立即关闭，同样提供日志文字；无需重新安装客户端。暂时不重新入会申请远控。

## 范围

- 不联网、不读取账号凭据，不申请会议授权。
- 仅发送原生协议 Hello、ParentAlive、Consent、Close；代码中的允许列表禁止 Arm、Input、Lease。不会发送键盘、鼠标或文本输入。
- 会创建原生授权窗口及其守护进程；用户允许后观察两秒，再关闭并等候清理结果。最长等待授权 60 秒。
- 使用 delivery.8 原生程序，启动前校验其固定 SHA-256，文件变化时拒绝执行。原生程序保留桌面状态、停止入口及清理保护。
- 报告仅包含时间、事件名称、原因码、进程编号、显示器尺寸/DPI、哈希和清理结果，不保存屏幕截图、桌面内容、机器名、账号、签名私钥或会议令牌。
- 选择原点为 `(0,0)` 的唯一主显示器；若不存在唯一匹配则终止诊断。
- 两个 EXE 为内部测试文件，未签名。若系统阻止启动，请保留提示并反馈，不要关闭安全防护。

## 已完成的本机验证

独立启动诊断进程并仅针对其带测试标签的窗口执行测试：允许、拒绝两条路径都收到 guardian cleanup=1、workerExitCode=0，输入指令数为 0。允许路径退出码 0；拒绝路径退出码 1 表示未授权，属于预期结果。这不能替代 B 的实际操作验证。
